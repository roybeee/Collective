# 성장2 발행 이후 관측 연결

G2-08/09/19/28의 실행·관측 연결 증분이다. 성장 미션에서 기존 발행·실험 안·저장된 플랫폼 측정·게시별 귀속 주문을 정확히 따라가며, 새 실적 장부나 자동 수집을 만들지 않는다.

## 조회 계약

- 같은 owner·브랜드·캠페인의 성장 발행 연결에서 출발한다. publication의 실험·안과 source의 publicationId·target·channel·experiment·arm이 모두 일치해야 한다. Buffer 게시 ID와 Instagram 미디어 ID는 서로 대체하지 않는다.
- 초안은 명시된 arm의 target·정의·기간·수집 시각·자격증명 범위를 확인한다. 미확인 legacy fallback이나 다른 브랜드·지점 자료를 대신 붙이지 않는다. 인증정보와 공급자 오류 원문은 응답에 넣지 않는다.
- Instagram의 저장 reach/shares는 해당 share_rate 관측으로만 표시한다. 안전한 수치와 실제 0을 보존하며 다른 지표·분모로 전용하지 않는다. 수집 실패·재인증·pending·불일치·손상 자료는 보류와 null로 표시한다.
- 정상 종료된 수집의 과거 성공값은 historical로 표시하고 원래 수집 시각·기간을 유지한다. 오래된 관측을 현재 실적이나 성공적인 새 수집으로 표시하지 않는다.
- 선택한 기간의 기존 campaignAttribution을 요청당 한 번 조회하고 정확한 byPublication만 연결한다. 캠페인 전체 실적을 미션에 복사하지 않는다. 환불과 원가 미확인을 보존하고, 연결된 귀속 행이 없으면 장부 근거 없음으로 표시한다.
- 플랫폼 측정과 주문 장부의 기간·정의·분모를 나란히 표시한다. 전환율·ROAS·증분 효과를 새로 계산하지 않는다. 게시·플랫폼 반응·귀속 주문·인과 효과는 별개다.
- 자료 상한을 넘으면 오류를 반환하며 일부 자료를 전체 합계처럼 제공하지 않는다. 조회는 새 기록 저장·외부 API 호출·자동 재수집·규칙 승격을 수행하지 않는다.

## 기존 수집기 연결 보존

기존 collectForExperiment의 성공 저장은 measurement_source를 새 객체로 만들면서 publicationId를 잃었다. 이번 증분은 기존 연결의 실험·안·채널·target·publication 범위가 정확히 일치할 때만 publicationId를 보존한다. 다른 대상으로 재수집할 때는 옛 게시 연결을 승계하지 않는다. 실제 공급자 요청은 기존 수집기 경로에만 있으며 개발 검사는 모의 응답을 쓴다.

## 검증과 잔여

TDD로 성공·실제0·null·실패·만료/종료·권한·타범위·자료 한도·원장 불변과 수집기 성공 시 연결 보존을 검사한다. 브라우저는 기간/조회 실패·모바일·제작발행/성과 화면 이동을 확인한다. 실제 계정 수집과 주문 대사는 not_run이며, 일반 방문자 무작위 배정·비구매 분모·성숙 증분 분석(G2-09/10)은 완료되지 않는다.
