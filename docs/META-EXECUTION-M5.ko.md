# M5 별도 실행 승인과 중단

`meta_ads_execution` 기본 OFF. 이 기능을 켜도 자동 활성화하지 않는다. 대표 사용자가 현재 검증된 패키지와 원본 PNG 업로드 영수증, 예약, 계정/토큰 판, 최대 집행액, 일일 목표, 손실 한도, 안전 여유, 일정, 승인 만료, 비상 중단 위임을 승인하고 별도로 활성화해야 한다.

## 통화 계약

공식 Meta Python SDK의 [User.currency](https://github.com/facebook/facebook-python-business-sdk/blob/main/facebook_business/adobjects/user.py)와 [Currency.currency_offset/user_currency](https://github.com/facebook/facebook-python-business-sdk/blob/main/facebook_business/adobjects/currency.py)를 사용한다. `/me?fields=currency`의 실제 `user_currency=KRW` 및 양의 정수 `currency_offset`을 조회하고 `Graph 원문 예산 = 원화 일일 목표 × offset`을 확인한다. 광고 계정 자체도 KRW/Asia/Seoul이어야 한다. KRW의 고정 배율을 추정하거나 수동 텍스트를 증거로 쓰지 않는다. 이 필드가 제공되지 않는 토큰/시스템 사용자에서는 신규 활성화를 차단한다. 중단에는 currency 조회를 요구하지 않는다. 공식 통화 문서는 이번 조사에서 429로 확인하지 못했으며 실제 운영 권한/응답 검증은 수행하지 않았다.

## 상태와 복구

- `approved` 이후 명시적 요청만 광고 → 광고세트 → 캠페인 순으로 ACTIVE 변경한다. 매 전송 전에 CAS 저널을 저장하고 전체 외부 구성과 현재 근거를 대조한다. 부모의 다른 광고세트나 광고세트의 다른 광고가 있으면 활성화하지 않는다.
- 응답 유실·시간 초과·성공 저장 실패는 `unknown` 또는 기존 `activating/pending`으로 남긴다. ACTIVE 자동 재전송은 없다.
- 중단은 기능 OFF·만료·토큰 교체 후에도 동일 브랜드/계정의 현재 토큰으로 수행한다. 저장된 캠페인 ID를 먼저 PAUSED로 전송하고, 자식 하나가 실패해도 나머지 고정 ID 중단을 시도한다. 전체 중단 조회가 안 되면 unknown으로 예약을 유지한다.
- 감시 워커는 한 tick에 한 기록만 처리한다. 승인된 기록을 자동 활성화하지 않는다. 지출/일일/손실 한도, 기간/승인 만료, 근거/토큰/설정 변경, 3분 넘는 감시 공백, 미확정 활성화는 중단한다. 실패 기록도 갱신하여 다른 기록의 감시를 막지 않는다.
- 손실은 검증된 기여매출이 없는 상태에서 지출 전액을 손실로 보수적으로 취급한다.
- `stopped`만으로 예약을 해제할 수 없다. 대표가 지연된 최종 청구 내역을 대조하고 현재 외부 지출 이상 금액을 확인한 `settled`, 여야 한다. 승인 철회도 외부 관리 도구의 상태 변경 가능성 때문에 고정 ID 중단·대조를 거친다.

## 한계와 검증

이는 Meta의 강제 청구 상한이 아니다. 공급자 지출 집계 지연·일일 예산 초과 게재·워커 중단·권한 상실 동안 추가 광고비가 발생할 수 있다. 최종 청구 대조는 대표의 명시적 확인이며 Insights만으로 청구 최종성을 증명하지 않는다. 원본 PNG 전송 검증은 제공자의 변환된 표시 이미지와 바이트 동일성을 뜻하지 않는다.

실제 토큰 사용/광고 집행 없이 모의 Graph 응답과 메모리 SQLite에서 승인, 활성화, 중복 차단, CSRF/소유자 격리, 시간 초과, 만료, 기능 OFF 중단, 토큰 교체 복구, 자식 조회 장애, 실패 큐 회전, 예약 해제 보류를 검사한다. 전체빌드/브라우저 게이트는 통합 작업자가 수행한다.
