# 브랜드 사실 → 제작 → 발행 → 주문

캠페인 상세의 **제작·발행** 탭에서 사용할 수 있다. Instagram 첫 어댑터는 Buffer이며, 실제 계정과 공개 미디어 호스트를 연결하기 전에는 외부 발행을 수행하지 않는다.

## 사용 흐름

1. 사실에 출처·확인일·유효기한을 입력하고 사람이 확인한다. 후보·거절·만료 사실은 제작에서 제외된다. 지점 사실은 해당 지점에서만 사용한다.
2. 사실 1~4개로 1080×1080 PNG를 만든다. 브랜드명·색과 사실만 렌더링하며 긴 문장은 자르는 대신 제작을 거부한다. PNG 원본, 해시, 브리프/사실 버전을 저장한다.
3. 원본을 다운로드해 Cloudinary 또는 공개 R2 `*.r2.dev`에 `<sha256>.png` 파일명으로 올린다. URL은 HTTPS·리디렉션 없음·512KB 이하 PNG여야 한다. 비공개 앱 파일 URL은 Buffer에 전달하지 않는다.
4. 관리자 계정으로 Buffer API 키·조직 ID·Instagram 채널 ID를 연결한다. 앱은 실제 채널을 조회하고 키를 암호화 보관한다.
5. 캠페인의 최대 발행 시도와 누적 예정 비용 한도를 설정한다. 실제 모델/API/광고 청구액의 하드캡이 아니다. 실패·미확인 시도도 차감하며 자동 환급하지 않는다.
6. 소재·공개 URL·예약 시각·예정 비용을 지정한다. PNG·문구·계정·사용권·파일 유지 조건을 확인한 뒤 승인하고 별도 접수 버튼을 누른다. 브리프·사실·계정·한도 변경은 기존 승인을 무효화한다.
7. 공급자 게시 번호로 상태를 조회한다. `scheduled/sending`은 예약 접수, `sent`만 게시 확인이다. `draft/needs_approval` 또는 알 수 없는 응답은 확인 필요로 표시한다.
8. 점포 주문·매출 입력에서 캠페인과 소재를 선택하고 귀속 근거를 기록한다. CSV도 선택적 campaignId/creativeId 열을 받으며 기존 CSV는 호환된다. 귀속 매출과 증분 매출은 다르다.

## 보존·오류 정책

- 공급자 호출 전에 시도를 영구 기록한다. 응답 유실은 `uncertain`, 처리 중 중단은 `submitting`에 남아 자동 재전송하지 않는다. Buffer에서 직접 확인해야 하며, 이 단계에는 공급자 게시 번호 수동 연결 기능이 없다.
- 공급자 응답은 owner 잠금 재획득에 의존하지 않는 버전 조건부 UPDATE로 저장한다. 저장소 자체 장애나 호출 중 프로세스 종료까지 exactly-once를 보장하지 않는다.
- 접수된 예약의 취소는 Buffer에서 처리한다. 앱의 ‘새 발행 접수 중지’는 이미 접수된 예약을 취소하지 않는다.
- 실행 기록 또는 귀속 주문이 있는 캠페인은 삭제를 차단한다. 파일/감사 기록의 보관·정리 UI는 후속 범위다.
- 공개 파일은 승인과 실행 직전에 원본 해시와 비교한다. 외부 호스트의 향후 덮어쓰기를 기술적으로 막지는 못하므로 게시 완료까지 파일을 유지해야 한다.
- 사실/실행 POST는 각각 워크스페이스당 분당 60회로 제한한다. 소재 200개/소유자, 발행 기록 200개/캠페인, 사실 200개/브랜드를 보관한다. 사실 수정 200회 이후에도 확정 사실의 사용 거절은 허용한다.
- 이메일 로그인 모드에서 채널·한도·승인·실행·취소는 관리자만 가능하며 승인자의 실제 계정 ID를 기록한다. 데이터 범위는 기존 공유 워크스페이스 권한을 따른다.

## 검증 범위

SQLite 통합 테스트는 Buffer·미디어 HTTP·R2를 모의 응답으로 검증한다. Playwright는 실제 Chromium Canvas·로컬 D1/R2를 사용하되 기본 인증 헤더를 주입한다. 별도 이메일 로그인 테스트는 로컬 쿠키 세션을 사용한다. 실제 Buffer/Instagram 계정 호출·공개 미디어 업로드·외부 게시는 연결 정보 미제공으로 not_run이다. 생성형 이미지/영상 대량 제작, GEO 모니터링, 자동 CRM 발송, 실제 광고 집행은 이 첫 실행 흐름의 범위 밖이다.
