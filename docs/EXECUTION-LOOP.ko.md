# 브랜드 사실 → 제작 → 발행 → 주문

캠페인 상세의 **제작·발행** 탭에서 사용할 수 있다. 탭 위의 단계 체크리스트(사실 확정 → PNG → 채널 → 한도 → 초안 → 승인 → 접수)가 현재 단계를 강조한다. Instagram 첫 어댑터는 Buffer이며, 실제 계정을 연결하기 전에는 외부 발행을 수행하지 않는다.

## 사용 흐름

1. 사실에 출처·확인일·유효기한을 입력하고 사람이 확인한다. 후보·거절·만료 사실은 제작에서 제외된다. 지점 사실은 해당 지점에서만 사용한다. 캡션과 PNG에는 내부 항목 key 대신 표준 항목 라벨(`factLabel`, 예: `address` → 주소)을 쓴다.
2. 사실 1~4개로 1080×1080 PNG를 만든다. 브랜드명·색과 사실만 렌더링하며 긴 문장은 자르는 대신 제작을 거부한다. PNG 원본, 해시, 사실 버전, 소재 입력 지문(브랜드 이름·색 + 사실 `{id,version}` + 캡션)을 저장한다. 브리프 버전만 바뀌면 소재를 그대로 쓰고, 브랜드 이름·색이나 사용한 사실이 바뀌면 새 소재가 필요하다. 지문 이전에 만든 소재는 기존대로 브리프 버전으로 판정한다. 선택으로 **소재 제목**(앞뒤 공백을 뺀 1~60자, 예: '오픈 주소 안내 v1')을 붙인다. 제목은 PNG·캡션·해시(소재 입력 지문·PNG 해시)에 들어가지 않아 제목 때문에 재승인이 필요하지 않다. 비우면 저장하지 않고(기존 소재와 같은 모양), 화면은 '소재 · 9월 23일 00:05 생성 · 첫 사실 줄'(한국 시각)로 보인다. 소재 목록·발행 준비의 소재 선택·준비된 발행에 제목이 보인다. 같은 PNG·입력으로 다시 만들면 기존 소재를 그대로 돌려준다. 이때 기존 소재에 제목이 없으면 입력한 제목만 붙이고(버전은 그대로라 발행의 소재 버전 비교가 바뀌지 않는다), 다른 제목이 이미 있으면 409('같은 소재가 이미 … 제목으로 있어 제목을 바꾸지 않았습니다')로 알리고 입력란을 비우지 않는다. 이 PR 전에 만든 제목 없는 소재도 같은 사실로 다시 만들면 제목을 붙일 수 있다.
3. 관리자가 Buffer API 키를 입력하면 조직과 Instagram 채널 목록을 불러온다. 조직·채널을 골라 연결하면 앱이 채널을 다시 확인하고 키를 암호화 보관한다. 다시 연결할 때는 화면에 표시된 연결 버전이 현재와 같아야 한다. **Buffer 연결 해제**는 저장된 키를 지우고, 이 브랜드의 승인된 발행을 모두 초안으로 되돌리며, 감사 이벤트를 남긴다.
4. 캠페인의 최대 발행 시도와 누적 예정 비용 한도를 정한다. 한도가 없으면 승인할 수 없다. 이때 화면은 승인 버튼 옆에 차단 사유를 보여 주고 **기본 한도(발행 1회·0원) 저장** 버튼을 제공한다. 비용 상한은 확정 예산(0원 무예산 포함) 안에서만 정한다. 예산이 미확정이면(null, 확정 표시가 없는 이전 0원 기록 포함) 0원 상한만 저장할 수 있다. 한도를 저장한 뒤 예산을 낮추거나 미확정으로 되돌리면 승인·접수 때 '예산 초과'·'예산 미확정' 사유로 막는다. 이 한도는 실제 모델·API·광고 청구액의 하드캡이 아니다. 실패·미확인 시도도 차감하며 자동으로 되돌리지 않는다. 되돌리려면 아래 '접수 확인'에서 관리자가 명시적으로 고른다.
5. 소재·예약 시각·예정 비용으로 발행 초안을 만든다. 승인된 콘텐츠 작업물(현재 브리프 버전)의 '게시 카피'는 캡션 후보로 불러올 수 있다. **단, 이 기능은 `AI_COPY_CAPTIONS=enabled`일 때만 켜진다. AI 생성물 표시 줄과 승인 게이트의 표시 확인(결정 17)은 구현됐지만, 표시 문구가 대표·법률 검토 전 초안이라 꺼 둔다. 켜기 전 체크리스트는 [AI 생성물 표시](AI-DISCLOSURE.ko.md)에 있다.** 후보는 PR 2 근거 컨텍스트로 검사한다. 거절 사실의 값, 확정 사실에 근거가 없는 광고 표현(인기·할인·무료 등), 미확인 후보 사실의 값, 남은 `[확인 필요]`·`자료 필요` 표시 중 하나라도 있으면 사유를 보여 주고 선택할 수 없다. 캡션은 고른 카피, 빈 줄, 사실 라벨 문구 순서로 붙는다. AI 작업물(출처 `ai`·`ai_edited`) 카피면 그 뒤에 빈 줄과 AI 생성물 표시 줄을 붙인다(아래 'AI 생성물 표시' 절). 관리자는 **게시 코드**(쿠폰·POS 태그)를 골라 캡션 끝에 코드 줄을 붙일 수 있다(아래 '게시 코드' 절). 이미지 주소를 비워 두면 승인할 때 앱 공개 주소가 채워진다. 외부 호스트는 '고급: 외부 호스트'에서만 입력한다.
6. 관리자가 PNG·문구·계정·예약 시각·비용·사용 권리를 확인하고 승인한다. 승인에는 다음이 모두 필요하다. 불충족이면 서버가 409와 구체 사유를 돌려주고, 화면은 같은 사유를 승인 버튼 옆에 보여 준다.
   - 캠페인 기획 승인(`status==='approved'`)
   - 시작일·종료일 확정
   - 예약일(한국 날짜)이 캠페인 기간 안
   - 발행 횟수 한도, 채널 연결, 유효한 사실, 사용 권리 확인
   - 예산 조건: 예산이 미확정이면 예정 비용 0원만, 확정이면 비용 상한이 예산 이하
   - AI 카피 발행이면 'AI 생성물 표시 확인' 체크(`aiDisclosureConfirmed:true`, 아래 'AI 생성물 표시' 절)
7. 승인 후 별도 버튼으로 Buffer에 접수한다. 접수 직전에도 기획 승인·기간·한도·채널·사실을 다시 확인한다(예: 새 작업물로 캠페인이 '검토 대기'가 되면 기획을 다시 승인해야 접수할 수 있다). 승인 뒤 바뀐 항목(발행 계정, 낮아진 발행 횟수 한도·예정 비용 상한, 사용한 사실, 소재 입력, 카피 작업물, AI 카피의 표시 확인 기록 누락)이 있으면 409 응답에 그 항목을 적는다. 이때 **재확인**을 누르면 발행이 새 버전의 초안으로 돌아가고, 다시 승인할 수 있다. 단, 사용한 사실이나 소재 입력이 바뀐 경우에는 사실 버전이 달라져 같은 소재로 다시 승인할 수 없다. 화면은 재확인 대신 **이 발행 취소**를 안내하고, 새 PNG로 새 초안을 만든다. 한도를 올리는 변경은 기존 승인을 유지한다.
8. 공급자 게시 번호로 상태를 조회한다. `scheduled/sending`은 예약 접수, `sent`만 게시 확인이다. `draft/needs_approval` 또는 알 수 없는 응답은 확인 필요로 표시한다. 예약 1시간 전부터 2일 뒤까지의 접수 건은 화면에 들어올 때 자동으로 한 번 다시 조회한다(최대 3건). 수동 조회 버튼은 그대로 있다. 외부 호스트 발행은 조회 결과가 예약 접수·공급자 확인 필요이면 공개 파일 해시를 다시 확인한다. 달라졌거나 읽을 수 없으면 '외부 이미지가 승인한 원본과 다릅니다' 재검토 표시를 남긴다. Buffer에서 예약을 취소해야 한다.
9. 점포 주문·매출 입력에서 캠페인과 소재를 선택하고 귀속 근거를 기록한다. CSV도 선택적 campaignId/creativeId 열을 받으며 기존 CSV는 호환된다. 귀속 매출과 증분 매출은 다르다.

## 게시 코드 (A4-2)

같은 소재를 여러 번 게시해도 어느 게시가 주문을 만들었는지 가르도록, 발행마다 짧은 추적 코드를 캡션에 넣는다(`exec-loop-4` 권고 (2)).

- **발급**: 발행 준비의 '게시 코드 (선택)'에서 유형(쿠폰 코드·POS 태그)을 고르면, 서버가 발행 id를 먼저 정하고 `lib/publication-codes.ts`의 `issuePublicationCode`로 이 발행에만 쓰는 추적 코드를 발급한다. 발행 기록에 `trackingCode{id,code,type,storeId}`를 저장한다. 코드 발급을 포함한 발행 준비는 추적 코드 만들기(A4-1)처럼 관리자만 할 수 있다. 코드 없는 준비는 기존대로다.
- **지점**: 지점 캠페인은 그 지점이 기본이며 다른 지점은 409로 거절한다. 브랜드 공통 캠페인은 같은 브랜드의 운영 지점을 화면에서 골라야 한다(미선택 400, 다른 브랜드·없는 지점·보관 지점 409).
- **캡션**: 고른 카피, 빈 줄, 사실 라벨 문구, 빈 줄, 코드 줄 순서다. AI 카피면 사실 라벨 문구와 코드 줄 사이에 빈 줄과 AI 생성물 표시 줄이 들어간다. 쿠폰은 '주문할 때 쿠폰 코드 CABCD2345를 알려 주세요.', POS 태그는 '주문할 때 코드 PABCD2345를 말씀해 주세요.'이다. 목적격 조사(을/를)는 코드 끝 글자를 읽는 소리로 고른다. 코드 줄은 결정론 문구라 AI 생성물 표시 대상이 아니고 결정 17 스위치(`AI_COPY_CAPTIONS`)와 무관하며, 그 스위치는 그대로다. 코드를 고르지 않으면 캡션·해시·승인 흐름은 이전과 바이트 단위로 같다.
- **검사**: 승인·접수의 소재 일치 검사는 코드 줄을 포함한 캡션으로 비교한다. 재확인·연결 해제로 초안이 돼도 같은 코드와 캡션을 유지하며, 다시 승인할 수 있다. Buffer에 보내는 문구도 코드 줄을 포함한다.
- **한도**: Instagram 2,200자 한도는 코드 줄을 포함해 검사한다. 발급 전에 가장 긴 코드(12자)로 재고, 넘으면 코드를 발급하지 않고 400을 돌려준다. 그래서 발급 뒤에는 발행 저장만 남는다.
- **고아 코드 방지**: 코드 발급 뒤 발행 저장이 실패하면 발행 없는 코드가 남을 수 있다. 같은 캠페인·소재·지점·유형으로 다시 준비하면 그 코드의 발행 id를 그대로 써서 멱등 발급이 같은 코드를 돌려준다. 재시도해도 코드가 늘지 않는다. 다른 유형·지점으로 준비하면 새 코드를 발급하며, 남은 코드는 발행이 없어 주문 귀속 때 거절된다(점포 쪽 게시 상태 검증).
- **화면**: 준비된 발행에 코드·유형·지점과 **코드 복사** 버튼이 보인다. 매장 직원에게 이 코드를 알려 주문 장부의 쿠폰·POS 태그 열에 남기게 한다. 브랜드 공통 캠페인에서 지점 목록을 불러오는 중이면 그 사실을, 불러오지 못하면 오류와 **다시 시도** 버튼을 보이고, 운영 지점이 정말 0개일 때만 '운영 중인 지점이 없습니다'를 보인다. 어느 경우든 고를 지점이 없으면 초안 저장을 막는다.
- **귀속**: 주문 장부는 이 코드로 게시별 귀속 주문·매출을 집계한다([점포 실측](STORE-MEASUREMENT.ko.md)). 게시가 예약 접수·게시 확인이고 주문일이 예약일(한국 날짜) 이후인 주문만 세며, 게시가 나중에 취소·발행 실패되면 귀속 보고에서 빠진다(게시 관문). 귀속 매출은 증분 매출이 아니다.
- **PNG에는 넣지 않는다(A4-4 또는 소재 템플릿 작업)**: PNG는 소재를 만들 때 브라우저 Canvas로 렌더링하고, 그 바이트의 해시(`pngHash`)가 소재 입력 지문·승인·앱 공개 주소(`/media/<sha256>.png`)·외부 호스트 검증에 고정된다. 게시마다 다른 코드를 PNG에 넣으면 발행마다 새 PNG·새 해시·새 소재가 필요해 소재 재사용과 승인 흐름이 바뀐다. 그래서 이번에는 캡션에만 넣고, PNG에 코드를 렌더링하는 일은 A4-4 또는 소재 템플릿 작업(공개 미디어 경로 변경 필요)으로 넘긴다. A4-3(주문 기록의 추적 코드 입력)은 PNG를 바꾸지 않았다([점포 실측](STORE-MEASUREMENT.ko.md)의 범위 밖).

## AI 생성물 표시 (결정 17)

표시 대상·문구 초안·위치·법률 검토 주체·스위치를 켜기 전 체크리스트는 [AI 생성물 표시](AI-DISCLOSURE.ko.md)에 있다. 발행 흐름에서 달라지는 점은 다음과 같다.

- **판정**: 작업물에 새 저장 필드를 두지 않는다. `lib/ai-disclosure.ts`의 `isAiGenerated`가 B1 출처(`origin`)에서 파생한다. `ai`·`ai_edited`는 AI 생성물이고, 직접 작성(`manual`)은 아니다. 출처가 없거나 알 수 없는 작업물(출처 불명)의 카피는 AI 생성물인지 판정할 수 없어 캡션 후보에서 막고, 준비·승인·접수도 409다. 발행을 준비할 때 결과를 카피 기록 `copy.aiGenerated`에 남긴다. 사실 카드 PNG·사실 라벨 문구·게시 코드 줄은 결정론 결과라 대상이 아니다.
- **표시 줄**: AI 카피면 캡션의 사실 라벨 문구 뒤, 코드 줄 앞에 빈 줄과 표시 줄 한 줄을 넣는다. 문구는 대표·법률 검토 전 초안이며 코드 상수 `AI_DISCLOSURE_LINE` 한 곳에만 있다. AI 카피가 없는 발행(카피 없음·사람 카피·코드 줄만)의 캡션은 이전과 바이트 단위로 같다.
- **검사**: Instagram 2,200자 한도, 승인·접수의 소재 일치 검사, Buffer에 보내는 문구가 모두 표시 줄을 포함한 캡션을 쓴다. 기록된 판정이 작업물 출처와 다르면(이 필드 이전의 카피 기록 포함) 409로 다시 준비하게 한다. 스위치를 켠 뒤 문구를 바꾸면 이전 표시 줄이 저장된 AI 카피 초안·승인은 409('AI 생성물 표시 문구가 준비 뒤 바뀌었습니다 …')다. 재확인으로 풀리지 않으므로 취소하고 다시 준비한다(게시 코드가 있던 발행은 새 코드를 받는다).
- **승인 게이트**: AI 카피 발행은 승인 요청에 `aiDisclosureConfirmed:true`가 없으면 409('… AI 생성물 표시를 확인하세요')다. 승인 기록에 확인자 `aiDisclosureConfirmedBy`와 시각 `aiDisclosureConfirmedAt`을 남긴다(`approvedBy`와 같은 방식). 재확인·연결 해제로 초안이 되면 이 기록을 지워 다시 체크해야 한다. 기록 없는 AI 카피 승인은 '승인 뒤 바뀐 항목: AI 생성물 표시 확인'으로 접수하지 않는다(409). 화면도 접수 버튼을 막고 재확인을 안내한다.
- **화면**: 캡션 후보에 'AI 생성물 · ' 표시와 표시 줄 미리보기, 준비된 발행 카드에 **AI 생성물** 배지와 표시 줄 미리보기, 승인 영역에 필수 확인란 **AI 생성물 표시 확인**이 있다. 체크 전에는 승인 버튼 옆에 차단 사유가 보인다.
- **스위치**: `AI_COPY_CAPTIONS`는 그대로 꺼 둔다. 꺼져 있으면 AI 카피 준비와 승인된 카피 발행의 접수가 409다. 대표가 문구 초안을 확정하고 법률 검토를 마친 뒤 켠다.

## 앱 공개 주소

- 주소는 `<origin>/media/<sha256>.png`이다. origin은 `AUTH_ORIGIN`을 우선하고, 없으면 요청 주소의 origin을 쓴다. 파일명이 내용 해시라 추측할 수 없고 내용이 바뀌지 않는다.
- 승인된 발행이 참조하는 PNG만 인증 없이 제공한다. 참조가 없는 해시는 404이다. 제공 여부는 참조 목록이 아니라 참조한 발행의 현재 상태(승인·접수 중·접수 여부 미확인·예약 접수·공급자 확인 필요·게시 확인)로 판정한다. 참조 해제가 실패해도 취소·실패·초안 발행의 PNG는 404이다.
- 응답은 5분만 캐시한다(`public, max-age=300, must-revalidate`, ETag=내용 해시). 공개를 멈춘 뒤에도 공유 캐시가 최대 5분 더 제공할 수 있다.
- 인증 없는 판정 조회는 해시별 참조 행(owner가 빈 값인 `public_media_ref`)으로 `(owner,parent_id)` 인덱스를 탄다. 판정 결과 캐시와 IP별 요청 제한은 아직 없다.
- 승인 직후 화면이 로그인 정보 없이(쿠키 없이) 공개 주소를 HEAD로 확인한다. 접근할 수 없으면 사이트 공개 설정이나 '고급: 외부 호스트'를 쓰라고 경고한다.
- Buffer는 이 주소에서 이미지를 가져간다. **앱 사이트(Sites)가 public일 때만 Buffer가 가져올 수 있다.** 사이트가 로그인 뒤에 있으면 Buffer 게시가 실패한다. 이 경우 '고급: 외부 호스트'에 Cloudinary 또는 공개 R2 `*.r2.dev` 주소를 `<sha256>.png` 파일명으로 입력한다. 외부 주소는 HTTPS·리디렉션 없음·512KB 이하 PNG여야 한다.
- 승인과 접수 직전에 공개 파일이 원본 해시와 같은지 확인한다. 앱 주소는 자기 자신을 fetch하지 않고 R2 공개 사본을 검사한다. 외부 주소는 HTTP로 받아 검사한다.

## 보존·삭제 정책

- **공개 시작**: 발행을 승인할 때 R2 공개 사본(`public/<sha256>.png`)을 만들고 그 발행의 참조를 기록한다. 비공개 원본(`execution/…`)은 그대로 둔다.
- **공개 중지(참조 해제)**: 승인된 발행을 취소할 때, 재확인·연결 해제로 초안이 될 때, 발행이 실패로 끝날 때(공급자 `error` 또는 관리자의 '없음 확인'). 같은 PNG를 참조하는 다른 발행이 없으면 공개 사본을 지운다.
- **유지**: 접수 확인 중·접수 여부 미확인·예약 접수·공급자 확인 필요·게시 확인 상태에서는 공개를 유지한다. Buffer가 예약 시각에 이미지를 가져가고, 게시 뒤에는 근거로 남는다. 게시 확인 뒤 자동 삭제와 공개 사본 정리 UI는 후속 범위다.
- 참조 해제가 실패해도 상태 변경은 유지하고 서버 로그만 남긴다. 접수 직후 공급자가 `error`를 돌려준 경우에는 잠금을 다시 얻었을 때만 즉시 해제한다. 어느 경우든 제공은 발행 상태로 판정하므로 바로 멈춘다. 남은 참조는 같은 PNG의 다음 해제 때 함께 정리되고, 그때 공개 사본도 지운다.

## 보존·오류 정책

- 공급자 호출 전에 시도를 영구 기록한다. 응답이 유실되면 `uncertain`, 처리 중 중단되면 `submitting`에 남고, 어느 쪽도 자동 재전송하지 않는다.
- **접수 확인**(관리자): Buffer에서 찾은 게시 ID를 입력하면 원래 Instagram 채널의 게시인지 확인한 뒤 상태를 확정한다. '없음 확인'은 실패로 닫으며, 이때 발행 시도 차감을 복원할지 유지할지 명시적으로 고른다. 접수 중(`submitting`) 발행은 Buffer 응답(최대 15초)을 기다리는 중일 수 있어 접수 시도 2분 뒤부터 확정할 수 있다. 그 전에는 서버가 409를 돌려주고 화면은 확정 버튼을 숨긴다. 확정한 관리자와 시각을 기록하고 이벤트를 남긴다.
- 공급자 응답은 owner 잠금 재획득에 의존하지 않는 버전 조건부 UPDATE로 저장한다. 반영되지 않으면(`changes=0` 또는 저장 오류) Buffer 게시 번호를 별도 감사 기록(`execution_provider_audit`)과 응답에 남긴다. 그 번호로 '접수 확인'을 할 수 있다. 저장소 자체 장애나 호출 중 프로세스 종료까지 exactly-once를 보장하지는 않는다.
- 사실 값을 바꾸거나, 철회하거나, 유효 기한을 줄이면 그 사실을 쓴 승인·접수 중·접수 여부 미확인·예약 접수·공급자 확인 필요 발행에 `needsReview`(사유·시각)가 표시되고 화면 위에 배너가 뜬다. 유효 기한 연장은 대상이 아니다. 승인 건은 사실 버전이 바뀌어 같은 소재로 다시 승인할 수 없으므로 취소하고 새 PNG로 새 초안을 만든다. 이미 접수된 예약은 **Buffer에서 취소해야 한다**. 앱은 Buffer 예약을 취소하지 않는다.
- ‘새 발행 접수 중지’는 이미 접수된 예약을 취소하지 않는다. 중지 중에는 이미 접수된 예약 목록을 함께 보여 준다.
- 실행 기록 또는 귀속 주문이 있는 캠페인은 삭제를 차단한다. 파일/감사 기록의 보관·정리 UI는 후속 범위다.
- 제작·발행 기록이 있는 캠페인은 지점에 연결할 수 없다. 기존 소재는 지점 정보 없이 만들어져 연결 뒤 발행할 수 없기 때문이다. 지점 캠페인을 새로 만들어 제작한다.
- 사실/실행 POST는 각각 워크스페이스당 분당 60회로 제한한다. 소재 200개/소유자, 발행 기록 200개/캠페인, 사실 200개/브랜드를 보관한다. 사실 수정 200회 이후에도 확정 사실의 사용 거절은 허용한다.
- 이메일 로그인 모드에서 채널 목록 조회·연결·연결 해제·한도·승인·접수·취소·재확인·접수 확인은 관리자만 할 수 있다. 승인자·재확인자·접수 확인자의 실제 계정 ID를 기록하고, 연결 해제·재확인·접수 확인 이벤트에 행위자를 남긴다. 데이터 범위는 기존 공유 워크스페이스 권한을 따른다.

## 후속 범위

- PNG에 게시 코드 넣기(A4-4 또는 소재 템플릿 작업, 공개 미디어 경로 변경 필요): 위 '게시 코드' 절의 이유로 이번에는 캡션에만 넣는다.
- 이미 붙은 소재 제목을 바꾸는 편집. 지금은 만들 때(또는 제목 없는 소재를 같은 사실로 다시 만들 때)만 정한다.
- 캠페인 성과 탭의 게시별 귀속 주문·매출 자동 집계(PR 4b 잔여). 지금은 점포 귀속 보고서 안에서만 게시별로 본다.
- 실사진 템플릿: 사용자가 올린 사진(JPEG 허용, 용량 상향) 위에 확인 사실을 얹는 템플릿(exec-loop-7 (2)). 지금은 사실 텍스트 카드만 만든다.
- Buffer 게시 목록 조회로 같은 채널·예약 시각·이미지의 게시를 연결 후보로 제시하기, 관리자 확인 후 Buffer 예약 취소 호출.
- 게시 확인 뒤 공개 사본과 감사 기록의 보관·정리 UI.
- 소재 보관 한도 단위: 지금은 워크스페이스(owner) 전체 200개다. 캠페인·브랜드 단위로 바꾸고, 발행 시도가 없는 소재만 있는 캠페인은 소재 레코드와 R2 원본을 함께 지워 삭제할 수 있게 한다(exec-loop-12 (1) 뒷부분·(2)).
- 공개 미디어 판정 결과의 짧은 캐시(`caches.default`)와 IP별 요청 제한(SEC-2 나머지).
- 이메일 로그인 모드로 stores·meetings·workflow 스위트 실행: `testRuntime`에 인증 모드 옵션을 두고 쿠키 세션으로 한 번 더 돈다(eng-hygiene-5 ③). 지금은 헤더 인증(legacy) 고정이다.

## 검증 범위

SQLite 통합 테스트는 Buffer(조직·채널 목록, 게시 접수, 게시 조회)·미디어 HTTP·R2를 모의 응답으로 검증한다. Playwright는 실제 Chromium Canvas·로컬 D1/R2를 사용하되 기본 인증 헤더를 주입한다. 별도 이메일 로그인 테스트는 로컬 쿠키 세션을 사용한다. 실제 Buffer/Instagram 계정 호출, Buffer 조직 목록 쿼리(`account.organizations{id name}`)의 실제 응답, 공개 사이트에서 Buffer가 앱 공개 주소를 가져가는지는 연결 정보가 없어 not_run이다. 생성형 이미지/영상 대량 제작, GEO 모니터링, 자동 CRM 발송, 실제 광고 집행은 이 첫 실행 흐름의 범위 밖이다.

운영 배포 검증 체크리스트(공개 미디어): 발행 하나를 승인한 뒤 로그인하지 않은 환경(쿠키 없음)에서 `curl -I <origin>/media/<hash>.png`가 `200`·`content-type: image/png`인지, 취소 뒤 같은 요청이 `404`인지 확인한다. 로그인 페이지로 리디렉션되면 Buffer도 이미지를 가져가지 못한다.

공급자 계약: [Buffer 조직](https://developers.buffer.com/examples/get-organizations.html), [Buffer 채널](https://developers.buffer.com/examples/get-channels.html), [이미지 게시](https://developers.buffer.com/examples/create-image-post.html), [미디어 호스팅](https://developers.buffer.com/guides/hosting-media.html), [게시 상태](https://developers.buffer.com/types/PostStatus.html).
