# AI 생성물 표시 (결정 17)

AI 작업물의 카피를 게시 캡션에 쓰면 캡션 끝에 AI 생성물 표시 줄을 붙이고, 그 발행은 관리자가 **AI 생성물 표시 확인**을 체크해야 승인된다. 표시 판정과 표시 줄, 승인 게이트는 구현돼 있다. 다만 표시 문구는 **대표·법률 검토로 확정하기 전의 초안**이다. 그래서 AI 카피 캡션 스위치(`AI_COPY_CAPTIONS`)는 꺼 둔다. 대표가 문구를 확정하고 아래 체크리스트를 마친 뒤에 켠다.

- 결정 출처: [GROWTH-PLAN 결정 17](GROWTH-PLAN.ko.md)(표시 대상·문구·위치·법률 검토 주체, 작업물 aiGenerated, 발행 승인 게이트의 표시 확인 체크)
- 감사 근거: `exec-loop-7` 권고 (1)(승인된 콘텐츠 작업물 카피를 캡션 후보로 쓴다)
- 코드: `lib/ai-disclosure.ts`(판정·문구·표시 줄), `lib/execution.ts`(`composeCaption`·`approvalBlockers`), `lib/execution-server.ts`(준비·승인·접수), `app/execution-panel.tsx`(화면)

## 1. 표시 대상

| 구분 | 표시 여부 | 이유 |
|---|---|---|
| 승인된 콘텐츠 작업물 카피를 쓴 캡션, 작업물 출처 `ai`(AI 작성) | 표시 | AI가 쓴 문구다. |
| 같은 카피, 작업물 출처 `ai_edited`(AI 초안을 사람이 고침) | 표시 | 사람이 고쳐도 AI 초안에서 왔다. B1 이전에 사람이 고친 판(`origin ai`·v2 이상·`meetingId` 없음)도 출처가 `ai`라 표시한다. |
| 같은 카피, 작업물 출처 `manual`(직접 작성) | 표시 안 함 | 사람이 쓴 문구다. |
| 같은 카피, 출처가 없거나 알 수 없는 작업물(출처 불명) | 캡션에 쓰지 않음 | AI 생성물인지 판정할 수 없다. 표시 줄 없이 AI 카피가 게시되지 않게 막는다(아래 판정 방법). |
| 사실 카드 PNG | 표시 안 함 | 브랜드명·색·확인 사실만 그리는 결정론 렌더링이다. 생성형 이미지가 아니다. |
| 사실 기반 캡션(확인 사실 라벨 문구) | 표시 안 함 | 사람이 확인한 사실을 정해진 형식(`라벨: 값`)으로 옮긴 결정론 문구다. |
| A4-2 게시 코드 줄 | 표시 안 함 | '주문할 때 …' 결정론 문구다. |

**판정 방법**: 작업물에 새 저장 필드를 두지 않는다. `isAiGenerated(artifact)`가 B1 출처(`origin`)에서 파생한다(`ai`·`ai_edited`면 AI 생성물). 발행을 준비할 때 이 값을 발행의 카피 기록(`copy.aiGenerated`)에 남긴다. 사람 카피도 `aiGenerated:false`로 남겨, 어떤 판정으로 준비했는지 기록에서 볼 수 있다. 카피를 쓰지 않은 발행에는 카피 기록 자체가 없다.

**출처 불명**: 출처가 없거나 `ai`·`ai_edited`·`manual`이 아닌 작업물은 `hasKnownOrigin`이 거짓이다. 이런 작업물의 카피는 표시 여부를 정할 수 없으므로, 캡션 후보에 '작업물 출처 불명' 사유로 보이고 고를 수 없다. 발행 준비·승인·접수도 409다. 지금은 모든 작성 경로가 출처를 남기므로(AI 실행 `ai`, 직접 등록 `manual`, 사람 수정 `ai_edited`·`manual`) 해당 작업물이 없다. 이 규칙은 앞으로 출처를 빠뜨린 작성 경로가 생겨도 표시 없이 게시되지 않게 하는 안전장치다.

## 2. 표시 문구 (초안)

> 이 게시물의 문구는 AI의 도움을 받아 작성하고 담당자가 확인했습니다.

- **초안이다.** 대표와 법률 검토 주체가 확정하기 전에는 이 문구로 게시하지 않는다(스위치가 꺼져 있어 게시되지 않는다).
- 코드 안에서는 `lib/ai-disclosure.ts`의 상수 `AI_DISCLOSURE_LINE` 한 곳에만 있다. 캡션 조합·2,200자 한도·일치 검사·화면 미리보기가 모두 이 상수를 쓴다.
- **문구를 바꾸는 PR**: 한 PR에서 세 곳을 함께 바꾼다. (1) `lib/ai-disclosure.ts`의 `AI_DISCLOSURE_LINE` 상수, (2) 이 문서 2절 인용문, (3) `tests/ai-disclosure.test.mjs`의 기대값 `LINE`. 테스트가 이 문서 2절 인용문에 문구가 그대로 있는지도 검사하므로, 하나라도 빠지면 테스트가 실패한다.
- **스위치를 켠 뒤 문구를 바꾸면**: 이미 만든 AI 카피 발행의 캡션에는 이전 표시 줄이 저장돼 있다. 그런 초안·승인은 승인·접수 때 409('AI 생성물 표시 문구가 준비 뒤 바뀌었습니다. 이 발행을 취소하고 다시 준비하세요.')다. 재확인은 캡션을 바꾸지 않아 이 상태를 풀지 못한다. 관리자가 해당 발행을 취소하고 다시 준비한다. 게시 코드가 있던 발행은 다시 준비할 때 새 코드를 받는다(이전 코드는 취소된 발행에 남는다). 이미 Buffer에 접수된 예약은 Buffer에서 처리한다. 스위치를 켜기 전의 첫 문구 확정은 AI 카피 발행이 없어 영향이 없다.

## 3. 위치

캡션 끝, 확인 사실 문구 뒤, 게시 코드 줄 앞에 빈 줄을 두고 한 줄로 붙인다.

```
<고른 카피>

<확인 사실 라벨 문구>

<AI 생성물 표시 줄>        ← AI 카피일 때만

<게시 코드 줄>             ← 게시 코드를 골랐을 때만
```

- PNG에는 넣지 않는다. 사실 카드는 AI 생성물이 아니고, PNG 해시가 소재 입력 지문·승인·공개 주소에 고정돼 있다.
- AI 카피가 없는 발행(카피 없음·사람 카피)의 캡션은 이전과 바이트 단위로 같다. 코드 줄만 있는 발행도 같다.

## 4. 캡션 검사와 승인 게이트

- **한도**: Instagram 2,200자 한도는 표시 줄을 포함해 검사한다. 게시 코드도 고르면 두 줄을 모두 포함하고, 코드 발급 전에 재서 넘으면 코드를 발급하지 않는다(400, '… AI 생성물 표시 줄을 포함한 캡션이 …').
- **일치 검사**: 승인과 접수 직전의 소재 일치 검사는 표시 줄을 포함한 캡션으로 비교한다. 저장된 캡션에 현재 표시 줄이 없으면(빠졌거나 문구가 바뀜) 409('AI 생성물 표시 문구가 준비 뒤 바뀌었습니다. 이 발행을 취소하고 다시 준비하세요.')다. 기록된 판정(`copy.aiGenerated`)이 작업물 출처에서 다시 계산한 값과 다르면 409로 다시 준비하게 한다. 이 필드가 생기기 전의 카피 기록도 여기에 해당한다.
- **승인**: AI 카피 발행은 승인 요청에 `aiDisclosureConfirmed:true`가 있어야 한다. 없으면 409('… AI 생성물 표시를 확인하세요')이고 초안은 바뀌지 않는다. 승인 기록에는 승인자(`approvedBy`)와 같은 방식으로 확인자 `aiDisclosureConfirmedBy`(계정 ID)와 시각 `aiDisclosureConfirmedAt`을 남긴다. 사람 카피·카피 없는 발행은 이 체크 없이 기존대로 승인한다.
- **재준비**: 재확인·Buffer 연결 해제로 승인이 초안이 되면 표시 확인 기록도 지운다. 캡션(표시 줄 포함)은 그대로이며, 다시 승인할 때 다시 체크해야 한다.
- **제출**: Buffer에 보내는 문구는 표시 줄을 포함한다. 표시 확인 기록이 없는 AI 카피 승인(승인 경로 밖에서 기록이 바뀐 경우)은 '승인 뒤 바뀐 항목: AI 생성물 표시 확인'으로 접수하지 않는다(409). 화면도 같은 항목을 보이며 접수 버튼을 막고 **재확인**을 안내한다. 재확인 뒤 다시 체크해 승인하면 접수할 수 있다.
- **출처 불명**: 출처가 없거나 알 수 없는 작업물의 카피는 준비·승인·접수가 모두 409다(1절).
- **스위치**: `AI_COPY_CAPTIONS`가 `enabled`가 아니면 캡션 후보를 내주지 않고, 카피를 붙인 발행 준비와 이미 승인된 카피 발행의 접수를 409로 막는다(#29 이후 기존 동작 그대로).

## 5. 화면

- 발행 준비의 캡션 카피 목록에서 AI 작업물 카피 앞에 'AI 생성물 · '을 붙인다. 고를 수 있는 AI 카피가 있으면 표시 줄 미리보기와 위치 안내를 보인다.
- 준비된 발행 카드에 **AI 생성물** 배지와 표시 줄 미리보기('캡션 끝, 게시 코드 줄 앞')를 보인다. 승인 뒤에는 표시 확인 시각도 보인다.
- 승인 영역에 필수 확인란 **AI 생성물 표시 확인**을 둔다. 체크하기 전에는 승인 버튼 옆에 차단 사유('AI 생성물 표시 확인 필요 · …')가 보이고 버튼이 비활성이다. 서버도 같은 조건을 409로 막는다.

| 개발 | 문구 변경 PR(상수·2절 인용문·테스트 기대값, 2절), 표시 규칙 테스트 유지 |

## 7. `AI_COPY_CAPTIONS`를 켜기 전 체크리스트

1. [ ] **대표 문구 확정**: 대표가 2절 초안을 그대로 쓸지 고칠지 정한다. 고치면 2절 '문구를 바꾸는 PR'대로 `AI_DISCLOSURE_LINE` 상수·이 문서 2절 인용문·테스트 기대값(`LINE`)을 같은 PR에서 바꿔 병합한다.
2. [ ] **법률 검토**: 법률 검토 주체(대표 본인, 결정 12와 동일 — 외부 고객 전 전문가 재검토)가 표시 대상(1절)·문구(2절)·위치(3절)를 검토하고, 검토자·검토일·결론을 기록한다.
3. [ ] **스위치 변경 게시**: 운영 런타임 환경 변수 `AI_COPY_CAPTIONS=enabled`를 설정하고 [게시 절차](PUBLISH.ko.md)대로 게시한다. 스위치 변경 사실과 시각을 `docs/STATUS.md`에 기록한다.
4. [ ] **켠 뒤 확인**: 제작·발행 탭에서 AI 카피 후보에 'AI 생성물' 표시와 미리보기가 보이는지, 초안 캡션 끝(코드 줄 앞)에 표시 줄이 붙는지, 확인란 없이 승인하면 막히는지 본다.

끄려면 스위치를 `enabled`가 아닌 값으로 바꾸거나 지운다. 새 AI 카피 준비와 승인된 AI 카피 발행의 접수가 막힌다. 이미 Buffer에 접수된 예약은 Buffer에서 처리한다. 켠 뒤 문구를 바꾸면 남은 AI 카피 초안·승인은 2절대로 취소하고 다시 준비한다.

## 8. 범위 밖

- 생성형 이미지·영상의 표시: 지금은 사실 카드 PNG만 만든다.
- 플랫폼이 제공하는 AI 표시 기능 연동, 규제·플랫폼 표시 위반을 찾는 결정론 채점기(GROWTH-PLAN A2).
- 작업물 승인 경로(`app/api/action`)의 표시 확인: 작업물 승인은 광고 집행·외부 게시로 이어지지 않아 이번 범위 밖이다. 게시 직전 게이트(발행 승인)에서 확인한다.

## 검증

`tests/ai-disclosure.test.mjs`: 판정 규칙(`ai`·`ai_edited`·`manual`·기타), 표시 줄 위치(사실 뒤·코드 앞), 한도 계산, AI 카피 없는 발행의 바이트 불변, 승인 체크 없으면 409·있으면 승인과 확인자·시각 기록, 스위치 꺼짐이면 AI 카피 거절, 출처 불명 작업물 카피 거절, 일치 검사(문구가 바뀐 캡션 포함)·재준비(재확인·연결 해제)·제출 경로, 표시 확인 기록 누락의 드리프트, 화면 승인 본문(`approvalRequest`). 실제 SQLite, Buffer·R2는 모의 응답이다(mocked).
