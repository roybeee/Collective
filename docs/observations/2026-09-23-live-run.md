## 2. 관측하기로 한 다섯 가지

### ① 실제 토큰·시간·원화

토큰과 시각은 위 표. **원화는 측정 불가.** `db/schema.ts`의 `jobs`에 `tokens` 정수만 있고
단가·금액·통화 컬럼이 없다. 캠페인이 남는 장사였는지 판단할 수 없다는 구조적 결손이
실측으로 확인됐다.

### ② quality의 `reportedVerdict` vs 최종 `verdict`

**비교할 데이터가 없다. D1을 조회해도 마찬가지다.** (후속 관측, 5절)
`reportedVerdict`·`checks`·`gateIssues`를 남기는 `enforceQuality`는 커밋 `d67adeb`
(2026-09-17 14:14 UTC)에서 들어왔다. quality 실행 3건은 모두 그보다 먼저 실행됐다 —
8역할 quality run 08:29 UTC, 회의 quality 단계 08:30 UTC, 회의 품질 재검토 산출물
14:00:03 UTC. `/api/meetings`는 단계 output을 그대로 돌려주는데(`raw`·`providerId`만 제거),
회의 quality 단계 output에 `reportedVerdict`가 없고 `checks`·`taskChecks`가 0건이다.
산출물 record에도 `qualityReview` 키가 없다. 게이트 이전 코드가 만든 데이터라서 판정
하향이 일어났는지 관측할 수 없다. 이 질문에 답하려면 게이트가 배포된 뒤 새로 실행해야 한다.

관측된 것은 최종 산출물의 결론뿐이다. quality 역할은 "사용자 검토용 완성안이 아니라
자료 확보와 추가 수정이 필요한 상태"로 판정하고 발견 위치를 세 곳 지목했다 —
insight의 후보 선정표, strategy의 MAPDAL 선택 이유, 그리고 `candidateArtifacts`에 남은
구버전 CMO 브리프가 수정 전략과 충돌한다는 점. 형식 검사만 통과시키는 것이 아니라
상류·하류 산출물의 모순을 실제로 짚었다.

### ③ `lib/practice.ts`가 금지한 실패 모드의 실제 발생 여부

**위반을 찾지 못했다.**

- 산출물 8건 전체에서 URL이 **0건**이다. "접근하지 않은 URL을 확인했다고 쓰지 말 것"이
  지켜졌다.
- `insight`는 머리말에 `외부 검색: 미실시`를 명시하고, 출처 표에 캠페인 입력 4건만 올린 뒤
  "확인되지 않은 사항" 열을 따로 뒀다.
- `creative`는 미확인 값을 `[아티스트·앨범명]`, `[가격]`, `[배송 가능 지역]` 자리표시자로
  남기고 "미확정 특전은 노출하지 않습니다"라고 제작 지시에 적었다. 상품명을 지어내지 않았다.
- `cmo`는 `[사실]` 2, `[제안]` 2, `[미확정]` 2, `[자료 필요]` 1로 증거 구분을 가장 조밀하게 썼다.
  `insight`·`quality`는 마커 대신 출처 표와 "근거 — 자료 필요" 절 형식을 택했다.

### ④ `content.slice(0,40000)` 무음 절단

**발생하지 않았다.** 최장 산출물이 `data` 9,896자로 한도의 25%다. 절단 경로는 여전히
고지 없이 잘리지만, 현재 산출물 길이 분포에서는 도달하지 않는다.

### ⑤ HERMES 경로에서 insight가 쓴 근거

**웹 검색 없이 캠페인 입력만 썼다.** 출처 표의 4개 행이 전부 "캠페인 브리프/운영 입력/
상품 입력/측정 입력, 2026-09-17"이고 외부 출처가 없다. 이는 `app/api/run/route.ts`에서
`tools:[{type:'web_search'}]`가 OpenAI 분기에만 있고 HERMES 분기에는 도구 지정이 없다는
코드 판독과 일치한다. 모델은 검색하지 못했고, 검색한 척하지도 않았다.

## 3. 이 관측이 바꾸는 판단

- **"유료 실행 1회"는 더 이상 미해결 과제가 아니다.** 이미 실행됐고, 필요했던 것은
  실행이 아니라 관측이었다.
- **산출물 품질이 미검증이라는 전제가 틀렸다.** 증거 규율은 실호출에서 지켜졌고,
  독립 품질 검수는 상류 산출물의 실제 모순을 짚었다.
- **`data` 역할은 계획 수준에서 실험 위생을 지킨다.** 세션 단위 무작위 배정,
  `cross_exposure` 표시, 기준 전환율 없이는 표본 산정 거부를 명세했다. 다만 코드에는
  배정 프리미티브가 없으므로 그 계획은 사람이 수동 이행해야 한다. 계획과 실행의
  간극은 그대로다.
- **원가 계측 부재는 실측으로 확인된 결손이다.** 3,126,481 토큰을 쓰고도 금액을 모른다.

## 4. 이 기록이 확인하지 못한 것

- 실행 1건당 소요 시간 (`jobs`에 `createdAt`/`updatedAt`은 있으나 이번 관측에서 측정하지 않음)
- 팬사인회·점포 등 다른 기능 경로의 실행 여부
- 게이트 도입 뒤의 `reportedVerdict` vs `verdict` 차이 (게이트 이후 실행이 없어 관측 대상 없음)

빈 결과를 앱이 `failed`로 기록했다. 원문 응답은 231자이고 `jobOutputs`에 남아 있다.
viral_discovery는 도구 없이는 성공할 수 없는 작업이다. 도구 연결이 이 기능이 동작하기 위한 전제다.

### `reportedVerdict` vs `verdict` — 비교 대상 없음

2절 ②에 정리했다. 데이터가 게이트 이전에 만들어져서 필드 자체가 없다.
