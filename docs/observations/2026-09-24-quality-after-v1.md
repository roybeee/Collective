# 품질 재평가 — 품질 수정 v1 뒤 (2026-09-24)

이 문서는 [품질 기준선 v1](2026-09-24-quality-baseline-v1.md)과 같은 평가 케이스를 품질 수정 v1(#80) 게시 뒤 다시 잰 실측이다.
운영 코드 `443fff4`(Sites 버전 28)의 역할 지시로 같은 동결 요청을 평가 전용 HERMES 프로필에 제출하고 서버가 채점했다.
근거: real(평가 전용 HERMES 실호출, 서버 채점). 운영 HERMES 프로필과 운영 사용량 장부는 쓰지 않았다.

비유: 같은 체중계에 다시 올라서니 숫자가 크게 줄었다. 남은 눈금을 하나씩 확인해 보니 몸무게가 아니라 체중계 바늘이 떨린 것이었다.
그래서 바늘(측정 도구)을 고치고, 전과 후 기록을 고친 체중계로 다시 읽는다.

## 0. 결론 먼저

- **모델 원문 단계에서 내부 경로·제목 깊이 결함이 사라졌다.** 11개 산출물 모두 정규화 건수(스키마 경로·제목)가 0이고
  예방 판정(`prevention`) 실패가 0이다. 기준선은 `internal_id_exposure` 11/11, `heading_nesting` 5/11이었다.
- **결함 0개 산출물은 기준선 0/11에서 7/11이 됐다**(MAPDAL cmo·quality·data·growth, ODA cmo·strategy·insight).
  적용 채점기 통과율은 기준선 58/81 = 71.6%에서 77/82 = 93.9%다(3절).
- **남은 채점기 실패와 규제 block은 모두 측정 도구 오탐이었다.** 원문을 읽어 재현하니 모델이 금지 규칙을 적은 문장·표,
  정의가 아닌 문장, 부정·중단 조건 문장, 매체 광고비 집행 문장을 위반으로 잡았다(4절, 5절). 모델 원문의 실제 결함은 아니다.
- **측정 도구를 고치면 전후 비교가 흔들린다.** 그래서 이 PR(측정 도구 v2)은 오탐을 고치면서 같은 저울 재채점(`regrade_run`)을 함께 만든다.
  기준선 run과 이 재평가 run을 새 채점기·사전으로 다시 채점해 비교한다. 재채점 결과는 게시 뒤 `regrade_run`으로 갱신한다(8절 다음 조치, 게시 전이라 not_run).
- 공유 케이스 11개는 30쌍 미만이라 통계적 `개선`은 주장하지 않는다([비교 통계 규칙](../EVAL.ko.md#비교-통계-규칙)). 아래 전후 숫자는 기술 통계다.

## 1. 목적

대표 지시(2026-09-24, 품질 우선 결정): **'우리가 산출해낸 결과는 최고의 품질이어야만 한다.'**
기준선 기록 9절의 다음 조치대로, 품질 수정 v1을 게시한 뒤 같은 케이스로 다시 재서 수정이 결함을 예방했는지 본다.

## 7. 해석 주의

- 전후 숫자는 채점 버전이 다르다(기준선 `failure-types-v1`, 재평가 `failure-types-v1+normalized`). 두 결함의 예방 효과는 `prevention`으로 읽고,
  이번에는 정규화 건수가 0이라 사람이 보는 본문 판정과 같다.
- 공유 케이스는 11개로 30쌍 미만이다. 비교 통계 규칙상 결론은 `비회귀` 또는 `비교 불충분`만 쓴다. `GET /api/eval?compare=`의 n·b·c·p는 이 기록에 없다(게시 뒤 두 run을 재채점하고 `&regrade=1`로 비교해 8절에 갱신한다).
- 남은 실패가 오탐이라는 판독은 원문 재현에 근거한다. 측정 도구가 이제 모델보다 더 큰 오차원이므로, 도구를 고친 뒤에는 전후 run을 모두 같은 도구로 다시 채점해야 비교가 성립한다.
- 결정론 채점기는 설득력·창의성·전략 타당성을 판정하지 않는다(기준선 기록 7절). 통과는 품질의 필요조건일 뿐이다.
