# 사전 `.16` 마케팅 묶음 로컬 측정 (2026-11-16, P2 로컬 부분)

> 비유: 새 저울을 가게에 들이기 전에, 이미 무게를 아는 추(기존 테스트 문장·합성 케이스)를 올려 보는 일이다. 묶음을 끈 저울이 예전 저울과 같은 값을 내는지, 켠 저울이 새로 가리키는 눈금이 맞는지를 본다. 실제 손님 장부(운영 run)는 이 단계에서 열지 않았다.

- **결론:** 묶음을 끄면 3,442개 문장 전부에서 이슈가 `.15`와 같다. 묶음을 켜면 새 규칙 적중 28건 중 TP 26건·FP 2건(정밀도 93%)이다. 첫 측정에서 나온 오탐 7건은 규칙을 고쳐 없애고 정상 묶음에 고정했다(3절 아래 표). 과차단 정상 묶음 30문장은 오탐 0이다.
- **운영 재채점:** `not_run`. 이 작업에는 운영 접근이 없고 원격 API를 부르지 않았다. 아래 "소유자가 할 일"을 실행해야 운영 기준 run의 같은 저울 비교가 된다.
- 근거 종류: real(로컬 코드로 실제 채점), 모델·네트워크 호출 0회. 법률 자문이 아니다.

- 결과: 3,442/3,442 문장에서 기본 호출, 가맹 옵트인(`franchise:{scope:'recruitment'}`), `packs:[]`, `packs:null` 네 경로 모두 같다(`tests/compliance-mkt.test.mjs` ①).

## 4. 켤 후보 판단(계획 P2 기준: 정상 묶음 오탐 0 + 실제 적중 정밀도 90% 이상)

- 정상 묶음 오탐 0은 모든 규칙이 충족한다.
- 정밀도 90% 이상이고 적중이 있는 규칙: `kr.ad.scarcity_unverified`(12/12), `kr.ad.authority_claim`(4/4), `kr.food.body_change`(2/2), `kr.rights.official_claim`(1/1). 다만 표본이 합성 문장이고 작아 운영 재채점 전에는 후보로만 둔다.
- 미달: `kr.msg.sender_missing`(7/8 = 87.5%), `kr.ec.extra_cost_missing`(0/1, 추출 잡음).
- 판단 불가(적중 0): 나머지 8개 규칙과 두 확장. 운영 run 재채점에서 표본을 모아야 한다.
- block 승격 판단은 하지 않았다. 계획대로 대표가 정한다.

## 5. 소유자가 할 일(운영, not_run)

1. 이 PR을 운영에 게시한 뒤(레인 A), 비교에 쓰는 기준 run(품질 기준선 v1 두 run, 11-09·11-15 글로벌 평가 run)마다 `regrade_run`을 실행한다. 스위치 `compliance_mkt_rules`는 끈 채로 둔다. 기대: 각 run의 `issuesByRule`가 `.15` 재채점과 같다(버전 문자열만 `.16`).
2. 소유자 워크스페이스에서만 `compliance_mkt_rules`를 켜고 같은 run을 다시 `regrade_run`한다. 새로 잡힌 mkt 규칙 적중에 TP/FP 라벨을 붙여 이 문서 3절 표 형식으로 기록한다.
3. 규칙별로 정상 묶음 오탐 0 + 정밀도 90% 이상인지 보고, 켤 규칙과 block 승격 여부를 정한다. 그 전까지 스위치는 기본 꺼짐이다.
4. 재채점 비교는 두 run의 사전 버전이 같아야 한다(`.16`끼리). `.15` 재채점 결과와 `.16` 결과를 직접 비교하지 않는다(EVAL 6절 같은 저울 원칙).

## 6. 재현 방법

- 회귀 오라클·쌍·정상 묶음: `node --experimental-vm-modules tests/compliance-mkt.test.mjs`
- 규칙별 적중 집계는 `tests/helpers/compliance-corpus.mjs`의 `corpus()`를 `checkCompliance(text)`와 `checkCompliance(text,{packs:['mkt']})`로 각각 채점해 규칙 id별로 세는 방식이다(이번 측정 스크립트는 로컬 작업 공간에만 두었다. 로컬 산출물 경로를 읽기 때문이다).
