# GEO 자동 추적 (G5)

AI 검색 답변(ChatGPT·Perplexity·Gemini·Google AI 개요·네이버)에 브랜드가 나오는지, 공식 페이지가 인용되는지를 HERMES 브라우저 실행으로 관찰해 기록한다. 스위치 `geo_tracking`(기본 꺼짐). 화면: 캠페인 → 성장 탭 → 근거 → 조건부 확장(GEO·해외·MMM) → "AI 검색 노출 자동 추적". 손으로 적는 기존 "AI 답변 인용 관측"은 그대로 쓴다.

모든 숫자에는 **관찰 기록 · 노출 보장 아님** 표시가 붙는다.

## 구성

| 파일 | 역할 |
|---|---|
| `lib/geo-questions.ts` | 질문 입력 검사, 확정 사실로 만드는 시작 질문 10개(결정론 템플릿), 측정 쌍(질문×엔진) |
| `lib/geo-observation.ts` | HERMES 지시, 응답 JSON 검사, 공식 URL 일치·첫 언급 순서 계산 |
| `lib/geo-report.ts` | 엔진별 점유율·인용률·주간 변화·인용 도메인, 개선 백로그, llms.txt 템플릿 |
| `lib/geo-run-server.ts` | 조회·저장·측정 시작·진행·중지, 예약 측정 |
| `app/api/geo/route.ts` | GET 조회, POST `save_question`·`add_starters`·`save_site`·`start_run`·`advance`·`cancel_run` |
| `app/geo-panel.tsx` | 화면(lazy) |
| `lib/scheduled-runs.ts` | 예약 종류 `geo_weekly` + 행동 `run_geo_tracking`(짝으로만, 주 1회) |

기록(record kind, 모두 브랜드 부모, 캠페인과 무관): `geo_question`, `geo_run`, `geo_observation`, `geo_settings`. 제출 원문은 `hermes_submission` `geo-<작업 id>`(부모 없음).

## 방법

1. **질문**: 브랜드마다 최대 30개. 질문마다 언어(ko·en·ja)·유형(브랜드·카테고리·지역)·엔진·추적 켜기를 정한다.
   시작 질문은 확정 사실(유효기한 안의 `confirmed` 사실)과 브랜드 이름·업종에서만 만든다. 예: `{지역} {업종} 추천`(지역은 확정 주소의 동·구), `{브랜드} 영업시간`, `{대표 메뉴} 맛집`. 사실이 없으면 그 템플릿은 건너뛴다. 저장 요청의 문장이 서버가 다시 만든 추천 목록에 없으면 409다.
2. **계획**: 켜 둔 질문 × 고른 엔진 수, 측정당 추정 토큰(제출 본문 추정+출력 여유, 최근 GEO 실행 실제 평균, 하한 15,000 중 큰 값)과 합계를 먼저 보인다. 한 번에 최대 50쌍.
3. **실행**: 쌍마다 HERMES 실행 1회. 지시는 엔진의 공개 답변 화면 한 장을 열어 답변 앞 1,500자를 그대로 옮기고 인용 링크(최대 20개)와 브랜드·경쟁 브랜드 언급을 JSON 하나로 답하게 한다. 입력은 질문·엔진·브랜드 이름·경쟁 브랜드 이름뿐이다.
   - 진행 중 실행은 최대 3개, 한 번 진행에 제출 2개·조회 3개. 화면이 15초마다, 예약 실행 큐가 tick마다 진행을 부른다.
   - `brandCited`는 HERMES가 아니라 서버가 인용 URL을 공식 URL(브랜드 웹사이트·SNS 링크·확정 사실 값 안의 주소)과 비교해 계산한다. 경로가 있는 공식 URL(플레이스·계정)은 같은 호스트+경로 접두어로만 맞춘다.
   - 첫 언급 순서는 발췌 안에서 브랜드보다 먼저 나온 경쟁 브랜드 수+1이다. 발췌 밖 언급은 null.
4. **응답 검사**: 모르는 키·빠진 키·schema/엔진/질문 불일치·발췌 1,500자 초과·실행 시간 밖 `observedAt`·목록에 없는 경쟁 브랜드·발췌에 브랜드가 있는데 `brandMentioned:false`는 오류다. 오류면 그 작업은 실패이고 관찰을 만들지 않는다(부분 합성 없음).
5. **보고서**: 주는 KST 월요일 시작. 같은 주 (질문, 엔진)의 마지막 관찰만 센다. 점유율=언급/관찰 질문, 인용률=공식 인용/관찰 질문. `login_required`·`unavailable`은 분모에서 빼고 따로 센다. 주간 변화는 직전 달력 주와의 비율 차(%p), 없으면 비교 불가.
6. **개선 백로그**(결정론): 경쟁 브랜드만 나온 질문 → `공식 페이지에 '{질문}' 답변 섹션 추가`, 언급되지만 인용 없음 → 확정 사실 명시, 아무도 안 나온 질문 → FAQ 항목, 로그인 필요 엔진 → 수동 관측, JSON-LD 미확인·없음 → 위의 GEO 상품 구조화 데이터 생성기, llms.txt 미확인·없음 → 확정 사실·공식 URL로 만든 템플릿. JSON-LD·llms.txt 유무는 사람이 "사이트 점검"에 표시한다(서버가 사이트를 읽지 않는다).

## 비용·안전 게이트

- 토큰: 시작 때 계획 합계를 `assertTokenBudget`(워크스페이스·캠페인 월 상한)로 확인하고, 제출마다 측정당 추정을 다시 확인한 뒤 `submitHermes`가 예약한다. 넘으면 409로 보내지 않고, 남은 대기 작업도 실패로 닫는다. 사용량 원장 종류는 `role`, 역할 `geo_observation`이다(원장 종류에 GEO 전용 값이 없다. 브랜드 조사 평균을 끌어내리지 않게 조사 종류로 쓰지 않는다).
- 자율성: 직접 측정은 `research_run`이 금지면 403. 예약 측정은 `research_run`이 **자동**일 때만 돈다(확인 후·금지·자율성 규칙 꺼짐이면 건너뛴 사유만 남긴다).
- 전역 중단: 시작은 409. 진행 중이면 남은 대기 작업을 취소하고 이미 보낸 실행 결과만 읽는다.
- 권한: 대표·관리자만 조회·저장·측정(직원 403). 스위치가 꺼지면 모두 409.
- 예약: `geo_weekly`는 주 1회(요일 하나)만. 같은 (예약, 날짜)는 같은 측정 번호라 두 번 만들지 않는다.

## 한계

- 엔진 답변은 사용자·위치·시각·로그인 상태·실험군마다 바뀐다. 한 번의 관찰은 그 시각 그 화면의 기록일 뿐이며, 발췌·인용과 관찰 시각을 함께 저장한다.
- ChatGPT·Gemini는 로그인을 요구하는 경우가 많다. 자동 로그인은 하지 않고 `login_required`로 남긴다. 그 엔진은 수동 관측으로 채운다.
- Google AI 개요·네이버 AI 브리핑은 질문에 따라 나오지 않는다(`unavailable`).
- 발췌는 앞 1,500자라 그 뒤의 언급은 HERMES의 `brandMentioned`만 근거이고 순서는 모른다.
- HERMES가 화면을 잘못 옮겨도 형식이 맞으면 저장된다. 자기모순 검사로 일부만 거른다. 실제 브라우저 실행은 이 PR에서 검증하지 않았다(테스트는 mocked).

## 접근 원칙(robots·이용약관)

- 공개 화면만 읽는다. 로그인·캡차·본인확인을 넘지 않는다.
- 질문마다 엔진별로 주 1회, 공개 화면 한 장만 연다. 추가 검색·다른 화면 이동·새로고침 반복·크롤링을 하지 않는다.
- 결과는 내부 관찰 기록으로만 쓰고 원문을 외부에 다시 게시하지 않는다.
- 엔진의 이용약관이 자동화된 조회를 금지하면 그 엔진은 질문에서 빼고 수동 관측을 쓴다. 판단은 운영자가 한다(법률 자문 아님).
