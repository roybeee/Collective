# ODA 실사용 오류 보완

2026-09-23 ODA PIZZERIA 휘경 C107 캠페인의 실제 실행에서 재질문 2건이 정상 작업물로 저장됐고, 회의는 Content의 선행 발언 참조 오류로 중단됐다. 다음 변경은 이 실패를 재현한 테스트를 기준으로 한다.

## 역할 실행과 재작성

- 새 요청은 현재 역할·과업·필수 산출물과 `role-output-v1` 계약을 요청/저장에 포함한다. 필수 항목 누락·역할 불일치·알려진 재질문은 작업물로 저장하지 않는다.
- 사용량은 `invalid_output`으로 남기며 실패 원문은 소유자 범위 내부 기록에 보존한다. 일반 workspace/API에 실패 원문을 노출하지 않는다. 캠페인 삭제 시 관련 계약·실패 기록도 삭제한다.
- 기존 진행 중 요청은 원래 텍스트 계약과 요청 키를 유지하되 명백한 재질문은 거부한다.
- 수정 요청·브리프 버전 불일치·재질문 작업물에서 다음 역할을 호출하지 않는다. AI 팀 화면의 첫 보완 대상에 `다시 작성`을 제공한다.
- 재작성은 작업물 ID/버전을 검사한다. 성공하면 해당 역할의 이전 결과와 모든 후속 작업물을 이력으로 보존하고 이전 버전으로 전환한다. 실패하면 기존 작업물을 유지한다.
- 일반 역할에는 선행 역할별 최대 6,000자, Quality에는 24,000자를 전달한다. 출처 ID/버전/원문 길이/발췌 여부를 표시하며 Quality가 발췌를 받았으면 원문 검토 필요를 표시한다.

필수 항목 검증은 과업 형식과 알려진 무응답을 검사한다. 전략의 실질적 품질·모든 사실의 진실성을 자동으로 증명하지 않는다. 사용자 검토와 독립 검수는 계속 필요하다.

## 회의 실패 단계 재작성

- `실패 단계 다시 작성`은 같은 회의의 완료 발언을 그대로 두고 응답 검증에 실패한 단계만 재작성한다. 사용자 요청이 필요하며 단계당 추가 2회로 제한한다.
- 재작성은 새 제출 키, 접수 불명확 복구는 해당 시도의 기존 키를 사용한다. 중복 클릭/응답 유실로 같은 시도가 두 번 과금되는 것을 막는다.
- 브리프·작업물 변경, 다른 활성 작업/초안, 취소/완료 상태, 재시도 상한에서는 재작성을 거부한다.
- 실패 원문·공급자 ID·사용량은 내부 시도 이력에 남긴다. 공개 진단과 회의록에는 단계·필드별 오류·시도별 상태·토큰을 남기되 원문과 공급자 ID를 포함하지 않는다.
- `respondsTo`의 누락·빈 배열·허용되지 않은 발언 ID를 구분한다. 재작성 입력에 허용되는 앞선 발언 ID를 명시한다.
- `후속 회의 새로 시작`은 별도의 새 회의다. 이전 완료 토론과 실패 내용도 전달한다. 실패 단계 재작성과 혼동하지 않는다.
- 기본 회의 최대 13호출과 재작성 추가 호출은 별도다. 무제한 자동 재시도는 없다.

## 서버 진행과 브라우저 조회

회의는 등록된 서버 작업자가 진행한다. 브라우저는 4초 간격 GET으로 조회하며 `advance`를 자동 제출하지 않는다. 시작·중지·접수 복구·실패 단계 재작성은 명시적인 사용자 동작이다. 시작/재작성에는 작업자 등록이 필요하고 오프라인이면 연결 대기를 표시한다. 일시적인 조회 오류 이후에도 다음 조회를 계속한다.

## 브리프와 사용량

- 공통 물품보관함 지시를 제거하고 목표/제품이 해당 서비스일 때만 제공한다.
- 브랜드 소개를 검증된 상품 사실로 승격하지 않는 규칙과 고객별 첫 구매일 기준 30일 성숙 코호트 정의를 공통 지시에 적용한다. 이것은 생성 지침이며 별도 사실 검증 DB를 신설한 것은 아니다.
- `hermes-agent`는 연결 별칭으로 표시하며 기반 모델을 추정하지 않는다. 별칭에 모델 단가를 등록·적용하지 않는다. 이전 별칭 가격 기록은 원본을 보존하되 API/UI에서 유효한 비용으로 제시하지 않는다.
- 전체 사용량과 결과 요건 미충족 사용량을 분리하고, 토큰 미확인은 합계에서 빠진 건수를 표시한다. 저장 완료와 내용 승인·성과 달성을 구분한다.

## 검증 범위

- 실제 ODA 재질문, 필수 항목 누락, legacy 복구, 선행 작업 차단, 재작성 뒤 후속 무효화, 원문 소유자 격리/삭제를 회귀 검증한다.
- 완료 발언 4건 뒤 5번째 실패·그 단계만 재작성·응답 유실·재시도 상한·stale snapshot·개별 참조 오류·공개 원문 제외를 검증한다.
- 공급자 호출은 mocked, SQLite 저장·핸들러는 real이다. Playwright는 실제 Chromium/로컬 D1이고 인증 및 회의 공급자 응답은 mocked이다.
- 전체 테스트, 타입 검사, lint 기준선, 빌드, 모바일/데스크톱 E2E를 실행한다. 커버리지 비율은 측정하지 않았다.
- 이 변경만으로 실제 HERMES 모델의 새 응답 성공을 주장하지 않는다. 게시와 운영 실호출 결과는 별도 기록한다.
