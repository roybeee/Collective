# 성장2 M2 — 외부 주문·환불 가져오기 첫 증분

Meta 보고 구매 금액과 실제 주문 장부는 같은 지표가 아니다. 자사몰 스택이 정해지기 전에도 주문과 환불을 기존 `store_order` 장부에 반영할 수 있도록 공통 CSV 계약을 제공한다.

## 계약

- 캠페인에 연결된 지점의 기존 주문 장부를 사용한다. 화면 합계는 해당 지점 전체 채널·선택 기간의 장부이며 Meta 귀속 또는 증분 효과가 아니다. 누락이 있을 수 있음을 표시한다.
- `sourceKey`는 같은 몰에서 유지하는 식별자다. 행은 `order_id,revision,order_date,status,paid_amount,refund_amount,mode`만 받는다. 이름·전화번호·주소·이메일과 추가 열을 받지 않는다.
- 원화 정수, 서울 주문일, 100개 주문·150KB 상한. `revision`은 외부 상태 변경 순서를 나타내는 양의 정수이며 파일을 업로드한 횟수가 아니다. 원본에서 제공하지 않는 경우 운영자가 최신 상태 순서를 확인해 부여해야 한다.
- `refund_amount`는 누적 환불액이다. 결제액을 넘을 수 없고 전액 환불/취소는 결제액과 같다. 부분 환불은 paid 상태다. 환불이 먼저 도착해도 최신 상태를 보존하며 뒤늦은 낮은 개정은 건너뛴다.
- 같은 개정·같은 내용은 중복 처리, 같은 개정·다른 내용은 충돌이다. 파일 전체 미리보기 해시는 입력·지점 판·기존 장부 판에 묶인다. 확정 전 변경되면 재확인한다.
- 최초 주문일·주문번호는 유지한다. 기존 수동 장부와 충돌하면 새 구매로 만들지 않는다. 연결 후 사람이 장부를 수정한 경우 외부 수집이 덮어쓰지 않는다. 원본과 장부 대조 후 별도 조정이 필요하다.
- `storefront_order_link`는 외부 ID·개정·기존 주문 ID 연결만, `storefront_order_revision`은 반영 이력만 보존한다. 매출은 `store_order`에서만 집계한다. 기록·연결·반영 이력은 한 트랜잭션으로 반영한다.
- 원가 미입력은 미확인이다. 주문 가져오기로 캠페인 귀속·순이익·신규 고객 여부를 추정하지 않는다. 기존 주문의 귀속과 비용은 환불 갱신 시 유지한다.

## 검증과 후속

- 전용 모의 검사 32 assertions: 신규·반복·부분/전액 환불·취소·역순·동일 개정 충돌·날짜 변경·수동 수정·파일 오류·미리보기 이후 변경·소유자/역할/CSRF·원자성.
- 실몰 어댑터/웹훅·Pixel/CAPI는 이번 증분에 없다. 외부 고객 전환 전송은 항상 0회다. 첫 몰 스택·접근 권한 확정 후 해당 공급자의 서명·개정/수정 시각 계약과 테스트 주문으로 연결한다.
- 비용·환불 보정 이력과 실제 주문을 대조할 기반이며 M2 전체 종료를 선언하지 않는다. 후속: 읽기 계정 목록/수집 상태, 서명된 몰 이벤트, 이벤트 중복 제거·동의·전송 권한, 소재/실험/PAUSED 초안/예산 승인.
