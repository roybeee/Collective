# 성장2 상세페이지 수정안 ↔ 실제 적용 영수증

대상 카드: G2-26(판매면)·G2-29(구매 병목 수정 실행)·G2-12a(실행 영수증). [다음 증분 권고 2](GROWTH-2-NEXT-GAPS.ko.md#2-상세페이지-수정안--검토-가능한-산출물실제-적용-영수증-분리).

## 무엇을 하는가

- 오퍼(id·판)·상품 판·확정 브랜드 사실 판·(선택) 구매 병목 판에 고정한 상세페이지 수정안을 만든다. 구역은 제목·구매 이유·가격 표시·배송·반품·신뢰·옵션·FAQ·구매 버튼 중 최대 12개이며 현재 문구와 변경 문구를 함께 보존한다(되돌림 기준).
- 상태: `draft → approved → applied → rolled_back`, `draft/approved → withdrawn`. 승인은 페이지 변경이 아니다(`pageChanged: not_confirmed`). 운영자가 실제 판매처 페이지를 바꾼 뒤 확인 시각·내부 증빙 ID·확인 URL로 `record_applied`(`manual_attested`)를 남길 때만 `operator_attested`가 된다. 되돌림도 같은 영수증 형식이며 사유가 필요하다.
- 판매처 자동 수정 adapter는 없다(`adapter:null`, `mayApply:false`). 실제 adapter가 생기면 같은 승인 digest·낙관적 잠금·재조회·되돌림 영수증에 연결한다.

## 차단 규칙

- 상세페이지 URL은 오퍼에 등록한 URL과 같아야 한다(쿼리·인증정보 없는 공개 HTTPS).
- 가격 표시 구역은 승인된 오퍼 가격만 쓸 수 있다. 다른 구역도 승인가와 다른 금액 표기는 막는다. 재고·한정 수량 문구는 쓸 수 없다. 신뢰·배송·반품 구역에는 현재 확정 사실 근거가 필요하다. 상품 권리 확인이 없으면 승인하지 않는다.
- 저장 뒤 오퍼·상품·사실·병목 판이 바뀌면 `held`이고 승인·적용 기록이 409다. 새 초안으로 다시 검토한다. 승인 뒤 내용 digest가 다르면 적용 기록을 막는다.
- 적용 시각은 승인 이후·현재 이전, 되돌림 시각은 적용 이후. 확인 URL이 수정안 URL과 달라도 막는다.
- 전역 중단 중에는 승인만 막는다. 이미 한 페이지 변경의 적용·되돌림 기록과 보관 캠페인의 되돌림 기록은 복구 경로로 허용한다.

## 구매 병목과의 관계

구매 병목의 `appliedAt`은 운영자가 직접 입력한 값이다. 이 화면은 병목마다 `operator_receipt`(적용 영수증 있음)·`raw_applied_at_only`(영수증 아님)·`none`을 구분해 보여준다. 전후 비교를 효과 확정 근거로 쓰기 전에 영수증 유무를 확인한다. 인과 효과는 `not_measured`다.

## 저장
