# 다SKU 번들 미션과 내부 이행 원장

번들 탭의 판매 미션·이행 원장에서 구성 재고와 공유 위임 예산을 한 트랜잭션으로 준비한다. 기존 독립 예약은 같은 수량·SKU·단위와 미배정 전량이 확인될 때 미션에 연결할 수 있다.

- 서버가 현재 캠페인·번들·카탈로그·재고·위임 판과 지점·브랜드를 검증한다. 모든 구성 재고, 예산, 미션, 이력, 요청 영수증을 하나의 batch로 저장한다.
- 주문은 canonical store_order에 연결하고 SKU별 결제·환불 배분을 명시한다. 단일 상품 품목과 번들 품목 합계가 canonical 결제·환불 금액을 넘을 수 없다. 외부 품목 ID 중복과 예약 수량 초과를 거부한다.
- 출고·해제·환불 수량·부분 반품은 기존 공유 재고 projector를 사용한다. 반품 검수 및 재판매 가능 확인이 있을 때만 해당 SKU를 재입고한다. 반품 원인 기록에도 번들 주문 연결을 유지한다.
- 최종 예산 대사는 미출고 배정이 있으면 거부한다. 미배정 예약 잔량은 명시적 확인과 최신 재고 판을 제출해야 같은 batch에서 해제한다. 무집행 전체 해제는 주문 배정 이력이 없는 미션만 허용한다.
- 새 예약·새 주문 배정·출고는 전역 중단 중 거부한다. 환불·반품·안전 해제·대사는 계속 가능하다. owner lease와 UUID 요청 영수증이 동시 실행과 내용 변경 재시도를 막는다.

## 범위와 남은 연결

출고·반품은 운영자가 실제 증빙을 확인해 기록하는 **내부 원장**이다. 외부 주문 생성, 결제, 발주, 택배 API 호출은 없다. 기존 단일 상품 판매 미션·발행·실험 화면에 번들 미션이 자동 연결되지는 않는다. 번들 전체 기능의 운영 완료를 의미하지 않는다.

검증: 신규 `tests/growth-bundle-fulfillment.test.mjs`는 실제 메모리 SQLite와 mocked 인증을 사용하며 외부 호출을 거부한다. 예산/재고/미션 준비, 주문 배정, 무집행 해제 실패의 전체 rollback, 공유 cap, 전역 중단, 부분 반품, 원인 연결, 최종 미처리 재고 차단과 잔량 해제를 확인한다. 실제 공급자 연동과 브라우저 E2E는 이 스위트로 입증되지 않는다.
