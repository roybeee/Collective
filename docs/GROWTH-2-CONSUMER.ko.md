# 성장2 소비자 동의·재구매 후보

G2-14의 첫 소비자 운영 증분이다. 운영자가 확인한 가명 고객·주문 연결과 목적별 동의를 바탕으로 구매 후 안내 및 재구매 **계획 후보**를 판단한다. 고객 동일성을 자동 검증하거나 메시지를 발송하지 않는다.

## 저장과 동의 경계

- 서버가 브랜드별 무작위 가명 키를 만든다. 이름·전화번호·이메일·주소·외부 고객 ID·연락처 해시를 입력받지 않는다. 가명 키도 보호 데이터이며 관리자 이상만 조회·변경할 수 있다.
- 목적은 `identity_link`(고객·주문 연결), `post_purchase`(구매 후 안내), `marketing_reorder`(재구매 마케팅)로 분리한다. 다른 목적이나 기존 Meta 전환 측정 동의를 재사용하지 않는다.
- 부여에는 확인 시각·만료·고지 버전·내부 근거가 필요하다. 철회는 이전 근거를 다시 요구하지 않고 즉시 반영한다. 과거 부여 사건을 뒤늦게 접수해 철회를 되돌리지 못하며 명시적 새 동의는 새 판으로 기록한다.
- 사건과 현재 판은 원자 저장한다. 같은 요청 ID·같은 내용은 멱등 처리하고 다른 내용은 거부한다. 캠페인 보관 뒤 신규 고객/부여/연결은 중단해도 철회·연결 삭제는 유지한다.
- 원 주문은 기존 `store_order`다. 현재 지점·브랜드 주문을 선택하고 운영자 연결 근거를 남긴다. 한 주문을 두 고객에게 연결할 수 없다. 주문 변경 시 기존 판을 확인해 같은 고객의 연결을 다시 검토한다.

## 적격성

조회 시 현재 동의와 원 주문을 다시 읽는다. 연결 동의가 없거나 철회/만료되면 연결 주문을 후보 계산에 쓰지 않는다. 구매 후 안내와 재구매는 각각 해당 목적 동의로 판단한다.

현재 지점의 유료·미환불 주문을 기준으로 하며 취소·환불·미래 날짜·오래된 연결 판은 보류한다. 재구매 대기 일수(0~365일, 기본30일)는 화면의 계획 기준이며 법정 주기나 자동 발송 일정이 아니다. 마지막 유효 구매 이후 경과를 확인하며 타지점의 모든 구매까지 확인했다고 표시하지 않는다.

`maySend=false`, `mayExecute=false`다. 후보는 실제 판매·발송·성숙 재구매율이 아니다. 이탈 사건 수집이 준비되지 않아 이탈 회수는 이번 판정에 포함하지 않는다.

## 삭제와 전송

고객 연결 삭제는 동의 사건·주문 연결·연결 이력과 요청의 연결 정보를 제거/최소화한다. 재활성화를 막는 최소 삭제 표시를 남기고 원 주문 장부는 보존한다. 캠페인 삭제만으로 브랜드 공통 철회를 초기화하지 않는다. 법적 정보주체 요청의 전체 처리 완료를 뜻하지 않는다.

가명 고객·동의·주문 연결은 모델 입력·로그·공개 보고서·가맹 리드에 전달하지 않는다. 정적 의존 경계와 합성 보호 표식을 넣은 모의 모델 실행으로 검사한다. 근거 입력에서 식별정보·인증정보를 차단하지만 모든 난독화 형태를 식별하는 것은 아니다.

## 검증과 잔여

전용 검사: 목적 분리·만료/철회·역순 부여·소유자/브랜드/지점 격리·중복 연결·동시 변경·원자 rollback·연결 삭제·외부 호출0. 브라우저: 생성→동의→주문 연결→후보→철회→재조회 제외. 실행 수치는 `STATUS.md`와 PR에 기록한다.

실제 동의 수집/검증 adapter, 승인된 초안·발송·수신 거부 동기화, 구매 후 이행 안내, 이탈 사건/회수, 성숙 코호트·재구매 효과 검증은 잔여다. G2-14 전체 완료로 표시하지 않는다.
