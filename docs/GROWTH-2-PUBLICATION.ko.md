# 성장2 자연 유입 미션과 Buffer 발행 연결

원안 G2-12a/28의 첫 공급자 실행 연결이다. 이미 승인된 Buffer Instagram 발행과 예산·재고 예약이 준비된 organic 미션을 관리자가 연결한다. 연결만으로 발행하지 않으며 기존 발행 화면의 명시 실행 경로를 사용한다.

## 범위와 계약

- 미션 실행 준비와 승인된 미전송 발행을 같은 owner·브랜드·캠페인·지점 범위에서 1:1로 연결한다. 내용과 오퍼의 일치는 관리자가 확인한다. 채널은 위임 accountId와 승인 publication.channelId가 정확히 일치해야 한다.
- 승인 소재·판·PNG·캡션·사실·예약 시각·비용·계정을 고정하고, 상태 조회로 증가하는 판과 콘텐츠 변경을 구분한다. 연결 교체·해제로 실행 게이트를 우회하지 않는다.
- 기존 발행 실행 진입점은 클라이언트가 성장 ID를 생략해도 서버 연결을 조회한다. 현재 위임·기간·손실/예산 한도와 정확한 예산·재고 예약을 검사한다. 같은 예약을 다시 차감하거나 별도 예산 원장을 만들지 않는다.
- publication submitting과 성장 실행 unknown·추가 전용 영수증을 같은 DB batch로 저장한다. 중간 실패는 전체를 되돌리며 외부 요청 전 결과불명 기록을 남긴다.
- 발행 상태 동기화는 최신 서버 publication을 읽는다. 요청자가 공급자 ID·결과를 지정할 수 없다. 접수/예약은 발행 성공이 아니며, 발행 성공도 고객 반응·주문·인과 효과를 뜻하지 않는다.
- 결과불명·공급자 실패·운영자 notFound만으로 재전송하거나 재고/예산을 해제하지 않는다. 연결된 실행의 수동 결과 덮어쓰기와 직접 재고 해제 우회를 막는다. 실제 비용 대사·조회·복구는 전역 중단 뒤에도 유지한다.
- 이번 증분에서 외부 요청 직전 실패의 자동 해제는 제공하지 않는다. 취소된 미시도 발행의 서버 확인만 무집행 취소 근거로 사용할 수 있다. 실제 공급자 요청이 시도된 기록은 보수적으로 예약을 유지한다.
- 새 연결/실행은 관리자·CSRF·owner 잠금·CAS 검사를 적용한다. 연결과 영수증은 캠페인 삭제 후에도 보존하며 비밀 자격증명을 응답에 포함하지 않는다.

## 검증과 잔여

도메인/API 테스트는 모의 Buffer와 실제 메모리 SQLite를 사용하고, UI는 Chromium/local D1에서 연결·재조회·충돌 입력 보존을 확인한다. 실행 결과는 STATUS에 별도 기록한다. 실제 계정 발행·도달·주문·공급자 비용 검증은 이 개발 검사에 포함하지 않는다. 다른 채널·광고·파트너·고객 발송과 원안 전체는 후속이다.
