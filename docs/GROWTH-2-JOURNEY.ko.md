# 성장2 구매 병목 — G2-29

전체 원안 연속 개발 승인에 따라 `bdda24e`(#268 병합)의 `codex/growth2-journey`에서 구현한다. 유입 → 클릭 → 상품 → 장바구니 → 결제 → 배송 중 한 단계의 병목 가설, 대체 설명, 전후 관측, 수정 행동·담당·기한과 현재 판매 오퍼/미션을 연결하는 증분이다.

## 관측과 수정 계약

채널·기기·세그먼트와 분모의 정의/단위를 하나의 기록에 고정한다. 전후 각각 관측 시작/끝, 자료 확인일, 집계 지연 시간, 추적 상태, 공개 출처와 근거, 분모·다음 단계 도달 수·유료 주문·환불 주문·공헌이익을 저장한다. 날짜는 KST의 날짜이며 관측 마지막 날을 포함한다. 고객 개인 식별자료 대신 집계와 역할 담당자만 입력한다.

빈 숫자는 미확인(null)이며 명시한 0과 구분한다. 공헌이익은 음수를 허용한다. 전환율은 다음 단계 도달 수/정의한 분모, 환불률은 환불 주문/유료 주문이다. 분모 0은 0%가 아니라 계산 불가다. 이 기록은 운영자가 제공한 집계이며 주문 장부의 매출·이익·현금 합계를 덮어쓰지 않는다.

수정 행동·역할 담당자·기한·적용일을 기록한다. 구매 상담/옵션 추천을 준비할 때 사실 근거와 사람에게 전달할 이유를 남긴다. 입력된 자유문구는 상품 사실 자동 검증이나 고객에게 보낸 응답이 아니다.

## 비교와 증거 경계

전후 관측창의 길이, 비중첩, 수정 적용 시점, 자료 출처·근거, 신뢰할 수 있는 추적 상태와 집계 지연을 확인한다. 미래 관측이나 성숙하지 않은 관측, 누락·추적 장애·변경된 연결은 판정을 보류한다. 같은 길이/분모 정의도 동일 모집단이나 인과 효과를 입증하지 않는다. 전환 차이는 퍼센트포인트, 환불 차이는 주문 기반 퍼센트포인트, 이익 차이는 원 단위로 표시한다. 미확인 지표는 계산하지 않는다.

`mayExecute:false`, `causalStatus:not_measured`를 유지한다. 수치가 좋아져도 자동으로 해결·성공·확대 판정하지 않는다. 계획 저장이 판매면 변경, 고객 발송, 예산 집행을 수행하지 않는다.

## 저장·권한

`GET/POST /api/growth/journey`, `save_blocker`. 관리자 쓰기·CSRF·소유자 잠금·캠페인/병목 버전 검사, 동일 요청 멱등, 같은 소유자/브랜드/캠페인의 정확한 오퍼/미션 판을 사용한다. 미션에 연결된 오퍼와 병목의 오퍼가 일치해야 한다. 상위 근거 또는 미션 상태 변경은 조회 때 다시 평가한다. 보관 캠페인과 일반 멤버는 조회만 허용한다.

`growth_journey` 현재 기록과 `growth_journey_history` 추가 전용 이력은 같은 D1 batch에 저장한다. 새 병목은 캠페인별 500개까지 쓰기 전에 제한한다. 두 kind는 실행 원장이 아닌 로컬 계획/수동 관측이므로 캠페인과 함께 삭제한다. 실주문·집행 원장의 별도 삭제 보호를 바꾸지 않는다.

새로고침·저장 실패는 작성 중 입력을 보존한다. 충돌 시 최신 서버 내용을 검토하고 명시적으로 최신 판을 채택하거나 서버 기록으로 교체한다. URL은 공개 HTTPS만 허용하며 서버에서 URL을 가져오지 않는다.

## 검증과 잔여

필수 검사: null/0, 음수 이익, 잘못된 정수·수치 범위, 분모/환불 주문 대조, 날짜/지연 경계, 추적 불량/상위 변경, 개인정보/인증정보, 권한·범위·CSRF·CAS·멱등·이력·한도. 브라우저는 저장/재조회·입력 보존·모바일 너비를 확인한다. 명령과 실제 결과는 STATUS에 기록한다.

G2-29의 수동 병목 관측·수정계획·전후 관측평가 부분 구현이다. 실제 퍼널 자동수집, 사실 기반 상담/옵션 추천 실행, 판매면 수정 영수증, 실전환·이익·환불 개선 검증과 동의 기반 이탈 회수(G2-14)는 남아 있다. 다음 본선은 G2-11/31/32 일일 결정·운영 교훈과 G2-28/12a 일반 판매 실행 연결이다.
