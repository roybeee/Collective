# 바이럴 실험 판정 통계

바이럴 학습의 콘텐츠 실험(A 대조안 · B 실험안)에 Beta-Binomial 사후확률, 상대 lift 신용구간, 중간 확인(peeking) 경고를 더했다. 기존 판정(관찰상 개선 · 개선 가설 미지지 · 차이 불명확 · 근거 부족)은 그대로 두고, 그 옆에 통계 권고를 붙인다. 판정의 확정은 여전히 사람이 한다.

- 코드: `lib/viral-stats.ts`(순수 함수, import 없음), 연결은 `lib/learning-server.ts`, 화면은 `app/learning-panel.tsx`
- 테스트: `tests/viral-stats.test.mjs`(수치·경고·권고), `tests/learning.test.mjs`(저장·표시·확정 기록·모델 입력 검증)
- 난수를 쓰지 않는다. 같은 입력이면 항상 같은 값이 나온다. LLM 호출과 스키마 migration은 없다.
- 결과 한 번을 저장할 때 로컬 측정(warm 평균)으로 약 20~80 ms가 든다. 분모 100만·반응률 50% 부근이 가장 느리다(500,000/1,000,000 대 500,500/1,000,000에서 약 79 ms). Workers CPU 한도를 고려해 격자 크기를 정했다. 운영 한도에서는 측정하지 않았다.

## 방법

### 사전분포와 사후분포

각 안의 반응률 p에 사전분포 Beta(1, 1)(0~1 균등)를 둔다. 분모 n 중 반응 s를 관찰하면 사후분포는 Beta(1 + s, 1 + n − s)다.

### B가 A보다 나을 확률

P(p_B > p_A) = ∫ F_A(x) dF_B(x)를 수치 적분으로 계산한다. F는 사후분포의 누적분포함수(CDF)다. 정규 근사는 쓰지 않는다.

1. 각 사후분포의 평균 ± 12 표준편차 구간을 1,000칸으로 나누고, 칸 경계마다 정확한 CDF(정규화 불완전 베타 함수, 연분수 전개)를 계산해 표를 만든다.
2. 두 표의 격자를 합친다. 한쪽 분포가 매우 좁아도 그 구간의 해상도가 유지된다.
3. 합친 격자에서 Stieltjes 사다리꼴 합을 구한다. 같은 격자에서 P(B > A) + P(A > B) = 1이 정확히 성립하므로 두 안을 바꾸면 확률도 정확히 뒤집힌다. 같은 데이터는 정확히 0.5다.
4. 결과는 소수 4자리로 반올림한다.

정확도는 정수 모수에서 성립하는 닫힌 식(유한합)과 대조했다. 10/100 대 20/100, 크기가 크게 다른 두 안, 백만 표본 등 9가지 조합에서 차이는 0.0001 이하다. 분모가 10억을 넘으면 로그 감마 함수의 부동소수 오차 때문에 4자리 정밀도를 보장할 수 없어 계산하지 않는다(422 성격 오류, 화면에는 통계 판정 불가로 표시).

### 상대 lift 신용구간

상대 lift는 p_B / p_A − 1이다. 비율 R = p_B / p_A의 CDF P(R ≤ r) = ∫ F_B(r·y) dF_A(y)를 같은 방식으로 적분하고, 로그 척도에서 Illinois 수정 가위치법으로 5%와 95% 분위수를 찾는다(90% 등꼬리 구간). 기준값은 따로 계산했다. 정수 모수 Beta CDF를 이항 유한합으로 구하고 40만 칸 Simpson 적분을 대조안 쪽과 실험안 쪽 두 방향으로 계산해 서로 일치를 확인했다. 이 기준값과의 차이는 상대 0.1% 이내다. 대조안 반응이 0에 가까워 꼬리가 긴 경우(0/100 대 3/100)에도 같다. 0에 가까운 값은 상대 오차 대신 절대 오차로 본다(10/100 대 20/100의 95% 구간 하한 +0.10%, 기준값 +0.0979%). 테스트는 이 기준으로 고정한다. 값은 기존 판정의 lift와 같은 백분율 단위(소수 2자리)다. 분위수가 비율 10⁶배를 넘으면 null이다. 상한이 null이면 화면에 "상한 없음"으로, 하한까지 null이면(예: 대조안 0/10억 대 실험안 10억/10억) "+99,999,900% 초과"로 표시한다.

### 계산 대상

두 안 모두 분모가 0보다 크고 반응 수가 분모 이하일 때만 계산한다. 값이 비었거나, 공유·클릭처럼 반응 수가 분모를 넘을 수 있는 이벤트 집계는 이항 모형에 맞지 않는다. 이때 화면에는 "비율 지표 없음 — 통계 판정 불가"를 표시하고 기존 판정만 쓴다. 입력 검증(음수, 반응 수 > 분모, 정수가 아닌 값, 0 이하의 사전분포 모수)을 어기면 순수 함수는 status 422인 `ViralStatsError`를 던진다.

## 권고

| 조건 | 권고 |
|---|---|
| P(B > A) ≥ 0.95, 중간 확인 경고 없음, 기존 판정이 관찰상 개선 | 채택 권고 (`adopt`) |
| P(B > A) ≤ 0.05 | 중단 권고 (`stop`) |
| 그 외 | 판단 보류 권고 (`inconclusive`) |

기존 판정이 관찰상 개선이 아니면 확률이 높아도 채택을 권고하지 않는다. 목표 개선율 미달(예: 각 안 100만 표본에서 +2%, 목표 10%), 대조안 반응 0, 근거 부족이 여기에 든다. 채택 권고가 학습 반영 조건과 어긋나지 않게 하려는 것이다. 이때 화면에는 "기존 판정이 ○○이라 채택을 권고하지 않습니다"를 함께 표시한다.

중단 권고는 경고가 있어도 유지하고 기존 판정도 보지 않는다. 계획 전에 멈추는 쪽은 잘못된 채택보다 비용이 작다고 본다.

## 중간 확인(peeking) 경고

결과를 저장할 때마다 경고를 계산한다. 사유 코드는 네 가지다.

| 코드 | 조건 |
|---|---|
| `sample_below_plan` | 두 안 중 하나라도 분모가 계획한 최소 표본 미만이다. 분모를 모르면 미달로 본다. |
| `duration_below_plan` | 시작부터 측정 종료 시점까지가 계획한 최소 관찰 시간 미만이다. 화면을 연 시점이 아니라 측정 종료 시점으로 잰다. |
| `not_comparable` | 결과 입력에서 두 안의 대상·기간·배포 조건을 비교할 수 있다고 확인하지 않았다. 두 안의 측정 기간이 다르면 이 확인을 끈다. 자동 수집 초안은 설계상 항상 이 상태다(`lib/measurement-collection.ts`). |
| `repeated_looks` | 판정할 수 있는 결과(계획한 최소 표본·기간을 채우고 비교 가능)를 이미 1회 이상 본 뒤, 다른 수치로 다시 결과를 입력했다. |

계획을 채우기 전에 결과를 여러 번 봤더라도, 계획을 채운 시점에 처음 판정하면 경고하지 않는다. 오류율이 커지는 것은 결과를 볼 때마다 멈출지 정하는 경우다. 계획 전에 판정하려 하면 앞의 두 코드로, 비교 가능성을 확인하기 전에 판정하려 하면 `not_comparable`로 잡힌다. 계획을 채운 뒤 결과를 보며 측정을 늘리거나 수치를 고치는 경우는 `repeated_looks`로 잡는다. 이를 위해 실험 레코드에 판정할 수 있는 확인 횟수(`completedLooks`)를 남긴다.

- 계획 미달이거나 비교 가능성을 확인하지 않은 결과는 확인 횟수에 넣지 않는다.
- 두 안의 분모·반응 수가 직전 저장과 같은 재저장은 새 확인이 아니다. 메모, 비교 가능성 확인, 측정 종료 시점만 고친 경우다. 이때는 직전 확인을 대신하고 횟수를 늘리지 않는다. 예를 들어 비교 가능성 확인을 빠뜨리고 저장한 뒤 같은 수치로 확인만 켜서 다시 저장하면, 그 저장이 첫 확인이 되고 경고가 붙지 않는다.

## 사람의 확정

바이럴 실험의 확정은 "학습에 반영"(`adopt_rule`)이다. 관찰상 개선이면 채택(시험 적용 규칙), 개선 가설 미지지면 중단(주의사항 규칙)으로 확정한다. 통계 권고는 참고이며 확정을 막지 않는다. 확정이 권고와 어긋나면 그 사실을 규칙에 기록하고, 화면은 사유 입력칸(선택)을 보여 준다.

| `decisionConflict` | 경우 |
|---|---|
| `interim` | 중간 확인 경고가 있는데 채택한다. |
| `mismatch` | 확정이 통계 권고와 다르다. 예: 목표 lift는 넘었지만 P(B > A)가 0.95 미만이라 판단 보류 권고인데 채택한다. |

B4 1부의 범위는 사후확률과 중간 확인 경고를 더하는 것이다. 그래서 확정에 새 차단 조건(사유 필수, 400)을 두지 않았다. 이 기능 이전에 사유 없이 채택되던 실험도 그대로 채택된다. 사유를 필수로 할지는 따로 결정할 사항이다.

통계를 계산할 수 없는 실험(비율 지표 없음)은 어긋남도 기록하지 않는다. 학습 규칙 승격 조건은 바꾸지 않았다. 기존 판정이 관찰상 개선이나 개선 가설 미지지여야 하고, `evidenceLevel`은 `observational`이다. 규칙의 `sourceAssessment`에 사후확률 요약(`stats`), 확정(`decision`), 어긋남(`decisionConflict`, 없으면 생략), 사유(`decisionReason`, 입력했을 때만)를 함께 기록한다.

### 모델 입력

규칙의 `stats`·`decision`·`decisionConflict`·`decisionReason`은 역할 실행·브리프 초안·회의의 모델 입력과 학습 스냅샷에 넣지 않는다(`learningContext`가 뺀 사본을 넘긴다). 모델 입력은 이 기능 이전과 같다. 역할 지시문에 이 필드의 뜻이 정의돼 있지 않고, 성장 계획 원칙 1(기준선 없이 프롬프트를 바꾸지 않음)을 지키기 위해서다. 넣으려면 지시문과 기준선 비교를 함께 바꾼다.

## 저장과 하위 호환

- 실험 레코드(`viral_experiment`)에 `stats`(요약)와 `completedLooks`를 더했다. 기존 EAV 레코드에 필드만 추가하므로 migration이 필요 없다.
- 요약 필드: `probBetter`, `liftLow`, `liftHigh`, `level`(0.9), `controlRate`, `treatmentRate`(관측 비율), `n`(안별 분모), `prior`, `warning`(`codes`, `message`), `recommendation`, `looks`.
- 이 기능 이전에 저장된 실험은 조회할 때 요약을 계산해 보여 주고 저장하지 않는다. 이전 확인 이력은 알 수 없으므로 0회로 본다. 이런 실험을 채택할 때도 같은 방식으로 계산해 규칙에 기록하지만, 권고와 어긋나도 이전처럼 채택된다.
- 이전 형식 실험의 결과를 다시 저장하면, 저장돼 있던 결과가 판정할 수 있는 결과(계획 충족·비교 가능)였을 때 확인 1회로 센다.
- 재검증 실험은 `stats: null`, `completedLooks: 0`으로 시작한다.

## 한계

- **독립성 가정.** 이항 모형은 분모의 각 단위가 독립적으로 한 번 반응한다고 가정한다. 같은 사람에게 여러 번 노출되거나, 한 사람이 여러 번 공유하거나, 공유가 다시 도달을 만드는 연쇄는 이 가정을 깬다. 이때 신용구간은 실제보다 좁다.
- **채널 알고리즘 노출 편향.** 두 안은 무작위로 배정된 같은 모집단에 노출되지 않는다. 플랫폼 알고리즘은 초기 반응이 좋은 게시물에 노출을 몰아준다. 분모(도달·노출) 자체가 결과의 일부라서 비율 비교가 치우칠 수 있다. 게시 시점, 계정 상태, 광고 집행 차이도 모형 밖에 있다.
- **귀속 ≠ 증분.** 비율 차이는 두 게시물에서 관찰된 반응의 차이다. 콘텐츠 요소 하나가 만든 증분 효과가 아니다. 확률은 모형 안의 확률이며 인과를 확정하지 않는다.
- **사전분포.** 표본이 작으면 Beta(1, 1)의 영향이 크다. 예를 들어 0/0 대 0/0에서도 lift 구간은 −90% ~ +900%로 나온다.
- **다중 비교.** 여러 실험이나 지표를 동시에 보면 우연히 0.95를 넘는 실험이 생긴다. 권고는 실험 하나의 주지표 하나에 대한 것이다.
- **표본 계획.** 최소 표본 기본값은 검정력 계산이 아니다. 작은 효과는 계획한 표본으로 판정이 안 날 수 있다.
- **arm별 측정 기간.** 두 안의 측정 기간이 다르면 비율 비교가 치우친다. 결과 레코드는 측정 종료 시점 하나만 보존하고 arm별 기간은 저장하지 않는다. 지금은 사람이 비교 가능성 확인을 끄면 `not_comparable` 경고로 채택 권고를 막는 데까지다(`loop-9`, arm별 기간 보존은 이월).

## finding 대응

성장 계획의 B4는 `loop-2`·`loop-3`·`loop-6`·`loop-9`를 확장한다. 1부는 그중 판정 부분만 다룬다.

| finding | 1부에서 반영한 판정 부분 | 이월 |
|---|---|---|
| `loop-2` 발행물이 실험 arm과 연결되지 않음 | 없음. 판정 입력은 사람이 입력한 두 안의 수치다. | 발행물과 실험 arm 연결, 게시물 ID 확보(B4 2부와 `loop-2` 본 작업) |
| `loop-3` 귀속 주문이 성과·학습으로 이어지지 않음 | 한계 "귀속 ≠ 증분"과 화면 문구로 확률이 인과를 확정하지 않음을 밝혔다. | 캠페인·소재별 귀속 집계, 추적 코드 |
| `loop-6` 사례 채널과 실행·측정 채널 불일치 | 한계 "채널 알고리즘 노출 편향"과 화면 문구로 반영했다. | 검증 채널을 사례 채널과 따로 고르는 기능 |
| `loop-9` 수집 초안에서 arm별 기간이 사라짐 | 비교 가능성을 확인하지 않은 결과에 `not_comparable` 경고를 붙여 채택 권고를 막는다. 두 안의 기간이 다르면 사람이 확인을 끈다. | arm별 기간(window) 보존과 자동 비교. 수집 초안을 결과로 옮기는 경로가 아직 없고(`loop-1`), 초안의 기간을 arm별로 나누는 일은 수집 쪽 변경이라 1부 범위 밖이다. |
