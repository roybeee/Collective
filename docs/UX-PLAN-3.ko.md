# 화면·UX 3차 개발 계획: 3.3 → 4.5 이상

작성: 2026-10-01, Claude 세션. 대표 지시는 "지금도 3.3점대인데 최고 수준이라고 부르기엔 한참 부족하다. 더 끌어올릴 개발 계획이 필요하다. 목표를 달성해야 한다"였다.

기준은 운영 Sites 83 = main `9b60796`(tree `23d50a4`)이다. 앞선 경과는 [UX 2차 계획과 1차 구현 결과](UX-PLAN.ko.md)에 있다. 구현 소유는 [레인 표](LANES.ko.md)의 A다. 2026-10-01 대표가 9절 결정 6건을 모두 승인했고, 성능·사람 개입 최소화·쉬운 사용을 최우선으로 지시했다. 그에 따른 조정은 [10절](#10-대표-결정과-조정2026-10-01)에 있고, 이 세션이 구현과 단계별 게시를 맡는다.

## 0. 한 장 요약

- **왜 3.3에서 멈췄나.** 2차는 위생(대비·터치·형식)과 뼈대(6섹션·안건·주소)를 고쳤다. 화면을 이루는 부품은 그대로다. 원시 버튼 273개, 원시 입력 370개, 임의 색 488종, 인라인 스타일 96개, 브레이크포인트 49종이 남아 있다.
  - 데이터 표현과 피드백도 바뀌지 않았다. 성장 패널 31개에는 표가 0개이고 " · " 연결은 488회다. 골격 로딩은 0개, 기본 확인창은 48개, 필드 오류 연결(`aria-invalid`)은 앱 화면에 0개다.
  - 최고 수준 제품과의 차이는 이제 "고장"이 아니라 "완성도와 일관성"에 있다.
- **3.3은 내가 매긴 판단 점수다.** 최고 수준이라고 부르려면 측정 가능한 통과 조건과 실제 사용자 검증이 있어야 한다. 3차는 점수를 조건표(1절)로 바꾸고, 사용성 테스트 2회를 목표에 넣는다.
- **목표:** 12개 차원 모두 4.5 이상(평균 4.5 이상). 사용성 척도 SUS 80 이상, 핵심 8과제 성공률 90% 이상. 모든 자동 조건은 CI 게이트로 고정해 다시 떨어지지 않게 한다.
- **방법:** Q0~Q8 9단계, PR 약 30개. 코드 작업은 2차처럼 빠를 수 있다. 임계 경로는 사람이 참여하는 사용성 테스트 2회(Q0 기준선, Q8 검증)다.
- **대표 결정 6가지:** [9절](#9-대표-결정-필요-사항). 핵심은 목표 정의, 캠페인 상세의 전체 페이지 전환, 사용성 테스트 참가자다.

## 1. 점수 기준을 조건표로 바꾼다

## 3. 단계별 개발 계획

각 단계는 끝날 때 조건표의 해당 칸을 CI 게이트로 고정한다. 게이트는 기준선 이하로만 내려가게 하는 방식(래칫)으로 걸어서 다른 레인 작업을 막지 않는다.

### Q0 측정 게이트와 기준선 (PR 3개)
- `scripts/ux-audit.mjs`를 CI 잡으로 올리고 예산 파일 `ux-budget.json`을 둔다. 대상은 axe, 44px, 가로 넘침, 탭 요청 수, 청크 크기, 위 2절 grep 계수다.
- 과업 하네스 `e2e/ux-tasks.spec.ts`를 만든다. 핵심 8과제의 클릭 수, 화면 전환 수, 소요 시간을 기록한다.
  - 8과제: 오늘 안건 처리, 상품·오퍼·미션 만들기, 고객 문의 기한 처리, 확대 제안 승인, Meta 준비 점검, 발행 승인, 주간 성과 확인, 전역 중단과 재개.
- 사용성 테스트 1회차(기준선)를 한다. 대표와 직원 3~4명이 회당 40분 동안 같은 8과제를 하고, SUS와 성공률, 지적 사항을 기록한다. 진행 대본과 기록 양식은 이 단계에서 문서로 만든다.

### Q1 디자인 체계 통일 (PR 5개)
- 토큰을 정한다. 색(의미 이름 24종 안팎), 간격 8단계, 글자 6단계, 반경 3단계, 그림자 2단계를 `app/globals.css` `:root`에 둔다. 임의 색은 토큰으로 바꾼다.
- 원시 버튼과 입력을 공용 `Button`·`FormField`·`DateTimeField`·`MoneyField`로 바꾼다. 패널 묶음 단위(성장 31, Meta 16, 나머지)로 PR을 나눈다.
- 인라인 스타일을 없애고 브레이크포인트를 4개로 줄인다.
- 핵심 12화면 × 3너비 시각 회귀 스냅샷을 CI에 둔다.
- 린트 규칙으로 원시 버튼·임의 색·인라인 스타일 재유입을 막는다.

### Q2 데이터·피드백 계층 (PR 5개)
- `useResource`(캐시·중복 제거·중단·재검증)와 `useMutation`(요청 ID 멱등·CAS 결과)을 만든다. 성장·Meta 패널부터 옮긴다. 직접 `fetch`·`AbortController` 중복을 줄인다.
- `PanelShell`이 골격 로딩, 오류와 다시 시도, 빈 상태와 다음 행동을 한 곳에서 처리한다.
- `ConfirmDialog`로 기본 확인창 48곳을 바꾼다. 대화상자는 무엇이, 어디까지, 되돌릴 수 있는지를 한 문장씩 말한다.
- 보관·중단·상태 변경처럼 되돌릴 수 있는 작업에는 실행 취소 알림을 둔다.
- 서버 400 응답에 필드 이름을 싣고 화면은 필드 아래에 오류를 보인다. 서버 의미와 권한 판정은 바꾸지 않는다.

### Q3 정보구조 완성 (PR 5개)
- 캠페인 상세를 전체 페이지로 바꾼다. 주소는 `?view=campaigns&campaign=<id>&ctab=<탭>&section=<섹션>&panel=<패널>`이고, 기존 링크는 그대로 열린다.
- 데스크톱은 왼쪽 섹션 내비, 모바일은 상단 선택기와 하단 고정 주 동작을 쓴다. 상단에는 위치 표시(브레드크럼)를 둔다.
- Meta 하위 탭 15개는 4단계 흐름(목표 → 준비 점검 → 소재·예산 → 실행·보고)과 '더보기'로 묶는다.
- 설정은 하위 메뉴 4개(연결·수집과 비용·운영 안전·기능표)로 나눈다.
- 판매 기본 기록(근거 → 고객·기회 → 상품 → 오퍼 → 미션)을 단계형 흐름으로 바꾸고 진행 표시를 단다. 저장하면 다음 단계를 제시한다.
- 전역 검색을 둔다. 명령 팔레트가 캠페인·브랜드·기록을 찾고, 최근 항목을 보여준다.

### Q4 데이터 표현 (PR 4개)
- 공용 `DataTable`(정렬·필터·고정 머리줄·모바일 카드)을 만들고 목록형 기록(문의·주문 품목·실험·확대·교훈 등)에 적용한다. " · " 연결은 표나 항목 목록으로 바꾼다.
- 숫자 표기 규칙(단위·분모·미확인과 0 구분)을 린트로 고정한다.
- 일일 운영·손익·성과에 작은 추세 차트를 둔다. 색과 축은 하나의 차트 규칙을 따른다.
- 공용 CSV 내보내기를 둔다.

### Q5 문장 (PR 3개)
- 패널 첫 문단을 60자 이하 한 문장으로 다시 쓴다. 금지·경계 설명 138곳은 섹션마다 하나인 '안전 범위' 안내로 모은다.
- 버튼·상태어·오류 문구를 모두 `lib/ui-copy.ts` 사전으로 옮긴다. 저장 동사는 '저장'과 '기록' 2종이다.
- 오류 문구는 3형식(불러오기 실패, 저장 실패와 입력 보존, 충돌)으로 통일한다.
- 길이·동사·금지어 규칙을 문구 린트에 더한다.

### Q6 온보딩·생산성 (PR 3개)
- 첫 사용 안내를 만든다. 견본 캠페인으로 안건 → 성장 섹션 → 미션 저장까지 따라간다. 견본은 표시만 하고 외부 실행은 없다.
- 핵심 용어 30개에 도움말을 단다(위임, 확대 게이트, 대사, 사전등록 등).
- 단축키를 둔다. `g h` 홈, `g c` 캠페인, `/` 검색, `?` 단축키 안내다.
- 모든 빈 상태에 다음 행동 버튼을 둔다.

### Q7 성능 (PR 2개)
- 첫 화면 JS를 180KB gz 이하로 줄인다. 공통 청크 분리, 아이콘 개별 가져오기, 대화상자 지연 로딩을 쓴다.
- 성장 탭 요청을 3건 이하로 줄인다. 전역 중단 상태를 요약 API에 합친다. 재방문은 캐시로 0건이다.
- E2E에서 상호작용 지연(INP)과 4G 조건 LCP를 잰다. 링크에 마우스를 올리면 미리 읽는다.

### Q8 검증과 재채점 (PR 1개 + 테스트)
- 사용성 테스트 2회차를 1회차와 같은 대본과 사람으로 한다. SUS 80 이상, 성공률 90% 이상이 목표다.

- **E2E 로케이터 대량 변경.** 공용 부품 전환은 61개 spec의 버튼·입력 이름에 닿는다. 접근 가능한 이름(라벨)은 유지하고 구조만 바꾸는 것을 원칙으로 하고, 이름을 바꾸는 PR은 따로 낸다.

- **이 계획이 하지 않는 것:** 외부 실행·발행·지출·고객 발송 추가, 서버 의미·권한 변경, 상태 어휘 변경, 다크모드 설계.

### 10.2 사람 개입 최소화: 개발 과정
- **사용성 테스트는 임계 경로에서 뺀다.** 사람 테스트 2회 대신 자동 과업 하네스(8과제의 성공·클릭 수·시간)와 독립 평가(이 계획을 모르는 별도 세션이 조건표와 화면 캡처로 채점)를 게이트로 쓴다. 사람 SUS는 원하면 언제든 하는 참고 지표다.
- **대표 확인 단계를 없앤다.** 캠페인 페이지 전환은 기능 스위치 뒤에서 대표 확인을 기다리지 않는다. E2E·과업 하네스가 통과하면 기본으로 켜서 게시한다.
- **화면 사용 집계의 사내 안내**는 회의 대신 설정 화면 한 줄 안내로 한다.
- **게시는 이 세션이 단계마다 자동으로 한다.** 대표 승인은 이 지시로 갈음한다.

### 10.3 사람 개입 최소화: 제품 안에서
운영자가 병목이 되지 않게, 사람이 해야 하는 일 자체를 줄인다. 외부 실행·지출·발송의 승인 게이트(`mayExecute:false`, 소유자 승인)는 그대로 두되, 승인을 1클릭으로 만든다.
- **안건에서 바로 처리:** 확대 승인, 상세페이지 승인, 협업 승인, 신호 확인, 문의 처리 완료를 안건 행에서 바로 한다. 캠페인을 열 필요가 없다.
- **일괄 처리:** 같은 종류의 안건은 한 번에 확인·처리한다.
- **기본값 자동 채움:** 직전 기록·브랜드 사실·캠페인 목표에서 값을 채운다. 사람은 확인만 한다.
- **초안 자동 보관:** 긴 입력은 자동으로 보관되고 다시 열면 이어진다.
- **다음 단계 자동 이동:** 저장하면 다음 할 일로 바로 간다.

### 11.3 Q2 확인 대화상자 + Q6 단축키 (2026-10-01)

- **확인 대화상자:** 브라우저 기본 확인창 21곳을 공용 확인 대화상자(`components/app/confirm-dialog.tsx` `askConfirm`)로 바꿨다. 대화상자는 무엇을 하는지, 영향, 되돌리기를 한 줄씩 보이고 버튼 이름을 동작으로 붙인다(예: '원본 삭제', '광고 활성화', '연결 해제'). 위험 동작은 확인 버튼을 경고색으로 둔다. 대화상자 부품은 처음 물을 때 내려받는다.
- 앱 화면의 `confirm(` 호출은 26곳에서 5곳으로 줄었다. 남은 5곳은 페이지 이탈 경고(`beforeunload`·링크 이동)와 인터뷰 화면의 저장 안 한 입력 보호처럼 동기 확인이 필요한 곳이다. 예산 래칫을 5로 낮췄다.
- **단축키:** `/` 또는 Ctrl·⌘+K는 바로 가기, `?`는 단축키 안내, `g` 다음 `h`·`c`·`b`·`m`·`l`·`s`는 홈·캠페인·브랜드·점포·학습·설정이다. 입력란과 대화상자 안에서는 단축키로 보지 않는다. 바로 가기 목록의 화면 이름 옆에 단축키가 보인다.
- 검증: 확인 대화상자를 쓰는 E2E 3개(원본 삭제·광고 활성화 취소/승인·서명 수신 켜기)를 대화상자 버튼으로 고쳤다. `e2e/ux-shell.spec.ts`가 단축키를 확인한다.
