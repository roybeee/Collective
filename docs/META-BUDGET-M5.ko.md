# M5 예산 범위 검토 — 첫 증분

Meta 작업의 **예산 검토**에서 현재 준비 계획·소재·읽기 연결을 대조하고 소유자가 검토 또는 철회를 기록한다. 이는 **로컬 계획 검토**이며 지출 승인·예산 예약·외부 한도 설정이 아니다. 모든 응답/기록은 `purpose: plan_scope_only`, `maySpend: false`다. 전체 M5 종료가 아니다.

## 범위

- 상품/랜딩, 계정, 시작·종료(KST), 총 예산·일별 운영 목표·손실 한도·안전 여유, 중단 기준, 소재 ID/파일 해시를 고정한다.
- 금액은 원 단위 계획값이다. 총 예산 − 안전 여유가 0보다 커야 하며 일별 목표/손실 한도가 그 금액을 넘으면 차단한다. 첫 제한 실험의 검토 기간은 제품 규칙으로 최대31일, 시작 시각은 미래여야 한다. Meta의 정책 한도라고 주장하지 않는다.
- 기존 M0 필수값과 M3 현재 소재/근거/실험 검토, 브랜드 읽기 연결을 재확인한다. 저장된 서버 근거만 사용하며 브라우저가 전달한 금액/계정으로 덮어쓰지 않는다.
- 소유자만 변경, 관리자/직원은 조회. CSRF·워크스페이스 범위·mutation lock·현재 version/digest로 이전 화면과 동시 변경을 거절한다. 계정 연결의 version뿐 아니라 updatedAt도 비교해 재연결 판 초기화 후 이전 검토를 재사용하지 않는다.
- 검토 기록은 같은 근거에서 멱등이다. 계획·캠페인·검토·파일·실험·근거·연결 변경 또는 시각 경과는 현재 상태를 무효화한다. 과거 기록은 변경하지 않는다.
- 철회는 별도 새 기록으로 이전 검토 범위와 행위자/시각/메모를 남긴다. 계획 변경·캠페인 보관 후에도 철회할 수 있다. 실제 광고 정지 요청이 아니다.
- 원문 토큰/고객 정보 없음. `meta_ads_budget_review`는 지출 이력이 아니므로 캠페인 삭제 시 같이 삭제하며 기존 삭제 영향 안내에 포함한다. 예산 집행·예약 장부는 후속 별도 보존 정책을 필요로 한다.

## 화면

총 예산·안전 여유·남은 금액·손실 한도, 기간과 범위, 누락/변경 조건, 검토 메모와 명시 확인, 최근20개 불변 이력을 제공한다. 오류/다시 조회 시 입력 메모를 보존한다. 실행 준비의 값을 복제 편집하는 폼은 만들지 않는다. 모바일 탭은 줄바꿈한다.

## 검사와 경계

전용35 assertions passed·mocked: 익명/타 소유자/관리자/직원 권한·CSRF, 최신 근거/판 CAS, 검토 확인/메모, 동일 검토 중복, 불변 금액/소재 해시, 계획/연결 변경 무효화, 변경/보관 후 철회, 기간/금액 한계. 외부 fetch가 발생하면 실패하도록 검사한다. 타입·lint70/39·프롬프트22·빌드 passed. 전체 회귀·데스크톱/모바일 E2E는 통합 CI에서 확인한다.

실제 광고 자산·계정·지출 검증은 not_run. 이 로컬 검토를 나중에 ACTIVE 권한으로 해석하면 안 된다. 후속 M5 집행 승인은 검증된 외부 캠페인/광고세트/광고·픽셀·계정 통화 단위·공급자 한도/종료 시각·전체 승인 범위를 새로 고정하고, 예산 예약·결과 불명·외부 변경 대조·중단 확인까지 구현한 뒤 별도로 받아야 한다.
