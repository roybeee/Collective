# 성장2 단일 SKU 소싱 비교

G2-26의 공급 후보 비교·발주 검토 부분 구현이다. 등록된 상품 카탈로그를 근거로 후보의 원가·최소주문수량(MOQ)·납기와 예상 구매비를 비교한다. 실제 공급자 연락·발주·결제·입고·가격 승인 권한은 부여하지 않는다.

## 후보와 비교 기준

카탈로그 ID와 판, 비식별 공급 후보 코드, 단위원가, 최소주문수량, 납기 일수, 고정 배송비·부대비, KRW 세금 기준, 견적 유효기한과 내부 증빙을 기록한다. 미확인은 null이며 확인된 무료 조건만 0으로 입력한다. 수량과 단가의 단위는 개(piece) 또는 팩(pack)으로 구분하고 단위를 자동 환산하지 않는다.

동일 상품·수량·단위·세금 기준으로 비교한다. 후보별 구매 검토 수량은 요청 수량과 MOQ 중 큰 값이다. MOQ는 최소수량이며 포장 배수로 해석하지 않는다. 포장 배수·구간별 가격은 별도 미지원 조건이다. 단위원가×검토수량에 배송·부대비를 더한 예상 구매비를 계산하며 안전한 정수 범위를 넘으면 보류한다. 견적 만료, 미확인 비용, 단위·세금 불일치, 참조 판 변경은 보류 사유로 표시한다. 세액이나 환율을 임의로 보정하지 않는다.

## 재고와 현금의 의미

재고는 카탈로그의 수동 stock 값이 아니라 기존 지점·SKU 공유 재고와 사건 원장을 읽는다. 다른 캠페인의 예약도 포함한다. 가상 입고 후 가용수량은 `max(0, onHand + 검토수량 − reserved)`이며 기존 부족분도 함께 본다. 현재 onHand가 미확인이거나 수량 단위가 다르면 예상 재고를 확정하지 않는다.

예상 구매비는 이 주문 검토안에 필요한 금액이며 실제 지급 또는 사용 가능한 현금 잔고가 아니다. 판매단계의 기존 변동비와 구매단계의 배송·부대비를 중복 합산하지 않는다. 입금 증빙을 은행 잔고로 간주하지 않는다. 비교안 저장은 기존 예산 예약·재고·오퍼 가격·원가·정산 기록을 변경하지 않는다.

## 저장과 수용 범위

후보 개정과 비교안은 owner·브랜드·캠페인 경계를 확인하고 잠금·판 비교·UUID 재시도를 적용한다. 비교 당시 상품·견적·재고의 참조 판과 평가를 고정하고, 현재 참조 변경은 과거 비교를 덮어쓰지 않고 별도로 표시한다. 소싱 검토 기록은 캠페인 삭제에도 보존한다.

전역 실행 중단 중에도 견적·비교안 작성은 허용한다. 응답의 `mayOrder:false`와 화면 안내로 실제 발주 권한과 구분하며 최저가 후보를 자동 채택하지 않는다. 다SKU 번들, 공급자 실조회, 실제 주문·계약·입고, 판매속도 기반 재발주 시점과 현금 한도 연결은 후속이다.
