# 성장2 실제 현금 원장 (G2-32)

상태: 구현·로컬 검증 대상. 게시·운영 계좌 대사는 별도다.

## 계산 계약

순현금 = 기간의 실제 정산 입금 + 기타 실제 입금 − 실제 지급이다. 광고 전 공헌이익, 예상 원가, 재고 평가액, 예산 예약, 미지급 협업 비용을 현금 지급으로 간주하지 않는다.

- 정산 `received.amount`는 이미 수령한 실제 금액이다. `feeAmount`는 정산 정보이며 다시 차감하지 않는다.
- 별도 수수료는 별도 은행 출금 거래와 증빙이 있는 경우에만 `fee_payment`로 기록한다. 정산 금액에 반영된 공제·환불을 별도 지급으로 다시 기록하지 않는다.
- KRW 정수 또는 금액 미확인(null)을 보존한다. 미확인을 0으로 바꾸지 않는다.
- UTC 날짜 범위이며 실제 시각은 UTC ISO로 기록한다. 미래 입출금과 미래 기간 완전성 확인은 거절한다.
- 은행 자동 연동·확인 기능이 아니다. 출처는 항상 `operator_attested`이며 인과 효과를 뜻하지 않는다.

## 같은 은행 거래의 식별

정산 `accountRef`/`receiptRef`와 현금 원장의 계정 참조/은행 거래 참조는 **같은 실제 계좌·거래에 대해 동일한 내부 식별자**를 사용한다. 정산 `settlementRef`는 묶음 참조이며 별개의 은행 거래를 뜻하지 않는다. 은행 계좌번호·개인 이름·연락처 대신 개인정보 없는 내부 참조를 사용한다.

같은 owner 전체에서 계정+은행 거래 참조 중복을 거절한다. cash를 먼저 저장하거나 settlement를 먼저 저장해도 중복은 차단된다. 기존 데이터에 중복이 발견되면 합계·기간 완전성 확인을 막는다. 별도 참조를 임의로 붙인 동일 실거래까지 자동 인식하지는 못하므로 운영자 증빙 대사가 필요하다.

현금 기록의 ID와 계정·은행 거래 참조·입출금 방향은 고정된다. 정정은 같은 기록의 새 판이고 무효는 기존 이력을 보존하며 합계에서 제외한다. 무효 처리해도 거래 식별자는 재사용할 수 없고 같은 기록을 정정해 복원한다.

## 기간 완전성 확인

입출금이 없다는 것과 모두 확인해 0원인 것은 다르다. 관리자·소유자가 해당 기간의 모든 입금·매입·광고·환불·별도 수수료를 증빙과 대조한 뒤 명시적으로 완전성을 확인해야 순현금이 계산된다.

확인은 해당 캠페인·기간 ID, 캠페인 판, 현재 cash와 settlement 전체 내용의 digest에 고정된다. 신규 거래, 정정, 무효, 정산 변경, 캠페인 변경이 생기면 기존 확인은 자동 stale이 된다. 금액 미확인이나 중복이 있으면 확인을 저장할 수 없다. UUID 재시도와 expectedVersion CAS로 중복 저장·구판 덮어쓰기를 막는다.

## 화면·API·보존

캠페인 → 성장·판매 → 마케팅 후 손익·현금에서 실제 입출금 기록, 정정·무효 및 이력, 기간 완전성 확인을 제공한다. 요약 순현금은 미확인 조건에서 null로 유지한다.

`GET/POST /api/growth/cash`는 관리자 이상, owner scope, mutation origin 검사, 공유 owner lock을 사용한다. POST는 `save_cash`, `void_cash`, `attest_period`를 받는다. 실제 은행 송금·환불·수수료 지급을 실행하지 않는다.

현재/이력/UUID 요청과 기간 확인 현재/이력/UUID 요청을 여섯 record kind로 보존한다. 현금 현재·이력이 있으면 캠페인 삭제를 막고 보관을 안내한다. owner 전체 현금·정산 조회 5,000건, 캠페인 현금 500건·이력 5,000건 한도 초과는 부분 합계를 정상 금액으로 표시하지 않고 거절한다.

## 검증 구분

`tests/growth-cash-route.test.mjs`는 실제 메모리 SQLite로 권한, CSRF, UUID, CAS, batch rollback, 중복 방향, 미확인, 수수료 중복 차감 방지, 변경 후 확인 무효화, 삭제 보호와 overflow를 검증한다. 인증은 모의이며 외부 은행 호출은 없다.

`e2e/growth-profit.spec.ts`는 로컬 D1·Chromium에서 기록→기간 확인→정정→무효 이력을 확인한다. 운영 은행 대사 완료나 실제 계좌 연결을 증명하지 않는다.
