# 성장2 비용 제어와 운영 연결 후속 계획

승인 범위: 대표의 “나머지도마저개발하라”, main `56760cd` 기준. 앞선 잔여 보고의 Q 원화 비용 제어와 판매처 설치·실연결에 필요한 코드를 구현한다.

1. 전용 평가 gateway: 고정 모델·단일 공급자 호출, 정확한 요청 견적, 영속 SQLite 사전 의도와 영수증 조회. 도구·후속 요청·자동 재시도·폴백 없음. 원화 계약과 USD 환산 장부를 구분한다.
2. Q 비용 원장: 가격 계약/서명 검사, 정확한 동결 pair 견적, UTC 월 원자 예약, 제출 전 영속 의도, 응답 불명 GET-only 복구, 최종 영수증 정산. 취소·삭제·월 경계로 미확인 비용을 해제하지 않는다.
3. 성장 후보 연결: 프롬프트와 운영 규칙의 정확한 pair만 준비·시작·회수. 등록·활성화 권한은 그대로이며 다른 모델/실행 경로를 운영 효과와 동일시하지 않는다.
4. 판매처 설치: 기존 ASGI 어댑터 조합, 정적 루트에 가려지지 않는 wrapper, 명시적 보조 테이블 migration, 읽기 readiness와 설치 검사. 실제 목적별 동의·수신자·실험 문맥의 연결 누락을 점검한다.

수용 조건: 다른 소유자/본문/가격판/모델 거부, 동시 예산 초과 차단, 가격 만료, 과금 POST 유실·재시작 후 중복0, 최종 영수증 중복·상충 처리, 취소 후 비용 보존, 기존 앱/lifespan 보존, DB 미준비 차단, 명시하지 않은 운영 테이블 변경0, 비밀값 비노출.

검증: 변경별 RED→GREEN, 합성 SQLite/HTTP/ASGI 통합, 기존 Q/Growth 회귀, 코드·보안 독립 검토, 전체 타입·테스트·빌드·lint 기준선, 핵심 브라우저, GitHub CI, 기존 Sites 게시 및 공개 tree 대조. 실제 공급자 유료 호출·운영 DB·고객 발송은 별도이며 mock 통과로 주장하지 않는다.

## 사용 흐름과 운영 경계

성장·판매 → 최적화 후보 샌드박스에서 소유자가 평가 전용 공급자와 검증 키를 연결하고 UTC 월 원화 한도를 승인한다. 기존 동결 후보에서 출력 상한을 지정해 무료 견적을 준비한 뒤, 표시된 최대 원화 비용으로 평가 시작을 승인한다. 준비 ID에 실행이 한 번만 연결되며 응답 유실 뒤 같은 승인 복구는 새 실행을 만들지 않는다. 준비 이후 프롬프트·규칙·케이스가 달라지면 새 예약을 거부한다. 이미 생성한 실행의 조회 복구는 캠페인 보관·전역 중단 이후에도 가능하다.

기존 Q 워커가 전용 경로를 처리하고 기존 채점기가 출력의 진단 결과를 기록한다. 별도 모델/실행 경로를 운영 Hermes와 동일하다고 증명하지 않았으므로 기존 프롬프트 활성화·승격 게이트는 통과하지 않는다. 오프라인 진단을 판매 개선 근거로 바꾸지 않는다.

견적은 짧은 유효기간을 가진다. 케이스가 많아 미전송 견적이 만료되면 미전송 예약만 해제하고 실행을 중단한다. 이미 전송한 요청이 unknown이면 서명된 확정 영수증까지 기존 월 예약을 보존한다. 요청 본문을 바꾼 자동 재견적이나 유료 POST 재시도는 없다. 취소와 원문 삭제도 미확정 비용을 지우지 않는다.

실제 고정 원화 공급자 계약이 없다면 유료 실행은 여전히 blocked다. [전용 평가 서비스 설치](EVAL-GATEWAY.ko.md), [MAPDAL 설치 절차](MAPDAL-INSTALL.ko.md)를 따른다. 현재 저장소에는 실제 원화 계약·발송 공급자 자격증명·법무 승인 고지문이 없다. 이 항목을 합성 테스트 데이터로 대체하지 않는다.
