# 성장2 일반 판매 실행 준비·결과 확인

원안 G2-28/12a/17a의 수동 운영 경로다. 준비된 판매 미션에 소유자가 서명한 위임과 공유 재고를 연결하고, 예산·재고·실행 준비 기록을 함께 저장한다. 실제 판매면 게시·광고비 집행·고객 발송은 수행하지 않는다.

## 구현 계약

- `POST /api/growth/execution`의 `prepare_execution`은 캠페인·미션·위임·재고의 현재 판과 상품·오퍼·근거 준비도를 확인한다. 예약 수량은 **등록된 SKU 재고 단위(개/팩)**이며 오퍼의 판매 세트 수가 아니다.
- 기존 `growth_commitment`와 `growth_stock_event`를 재사용한다. 같은 계정의 다른 캠페인 예약도 예산 한도에 포함된다. 준비 기록과 두 예약은 하나의 DB batch로 저장하며 어느 검사나 쓰기라도 실패하면 부분 예약을 남기지 않는다.
- 미션별 준비 기록은 하나다. 동일 요청 재전송은 같은 결과를 반환하며, 내용을 바꾼 재전송이나 기존 재고 예약과의 충돌은 대사를 요구한다. 같은 내용의 기존 예산 예약은 검증 후 연결할 수 있다.
- 복구 담당 역할·재확인 기한·개인정보 없는 근거를 기록한다. 서버가 미션·위임·재고의 스냅샷을 만든다. 클라이언트가 보낸 금액이나 승인 스냅샷을 신뢰하지 않는다.
- `record_execution_receipt`는 운영자 확인으로 `unknown`, `observed`, `failed`를 추가 전용으로 기록한다. 결과 불명은 다시 확인할 수 있지만 확정된 결과는 임의로 덮어쓰지 않는다. 접수·관측은 고객 결제나 인과 효과 증명이 아니다.
- 결과 기록만으로 예산·재고를 해제하지 않는다. 결과 불명 상태의 중복 준비·자동 재전송과 기존 미션 상태 변경을 통한 예약 해제 우회를 막는다. 주문이 들어오면 기존 품목 연결이 예약 재고를 주문 할당으로 옮긴다.
- 조회·결과 대사는 위임 철회나 캠페인 보관 뒤에도 유지한다. 신규 준비는 막는다. 관리자 이상만 변경할 수 있고 owner lock·CSRF·캠페인 격리·버전 충돌 검사를 적용한다.
- `growth_action_intent`, `growth_action_receipt`는 대사 이력으로 보존한다. 연결된 캠페인을 삭제해 예약 한도와 실행 근거를 초기화할 수 없다.

## 남은 범위

실제 채널별 공급자 접수·재조회 adapter, 전역 중단과 실행 직전 재검증, 실제 비용 대사·예산 해제, 공급자별 안전 취소는 후속이다. 이번 준비·운영자 확인은 자동 실행 권한이나 외부 검증 완료가 아니다. G2-12a/28 전체 완료로 표시하지 않는다.

다음 본선은 소비자 동의·철회와 재구매 적격성(G2-14), 사업목표·30일 리뷰(G2-32), 실제 주문·비용 및 실행 adapter의 연결이다. 실데이터·외부 권한을 요구하는 수용조건은 별도로 추적한다.

## 검증

이번 변경의 검증 명령·수치·real/mocked 구분은 PR 및 `STATUS.md`에 기록한다. 외부 fetch가 발생하면 실패하는 API 검사와 실제 로컬 브라우저/D1 검사를 사용한다. 개발 검사는 실계정 집행·실판매 성과를 대체하지 않는다.
