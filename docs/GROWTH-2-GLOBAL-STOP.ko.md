# 성장2 작업공간 전역 중단

성장2 원안의 신규 게시·지출·학습 승격 중단 경계를 owner 작업공간 전체에 적용한다. 특정 캠페인만 중단하는 설정이 아니다. 다른 owner의 작업공간에는 영향을 주지 않는다.

## 상태와 권한

관리자와 소유자가 신규 실행 접수를 중단할 수 있고 재개는 소유자만 할 수 있다. 사유·서버 시각·담당 계정·판을 저장하고 추가 전용 이력을 남긴다. POST는 CSRF 검사, owner 잠금, 현재 판 비교, UUID 멱등 재시도를 적용한다. 상태와 이력을 원자적으로 저장한다. 상태가 없으면 기존 동작을 유지하며, 저장된 상태가 손상됐거나 읽기 실패하면 신규 실행은 차단한다.

`growth_stop`의 id는 `global`, `growth_stop_history`의 id는 요청 UUID이며 parent는 빈 문자열이다. 캠페인 삭제와 무관하게 owner 범위에서 보존한다. `/api/growth/stop`에서 조회하고 `stop`/`resume` 요청을 기록한다. 최근 이력100건과 더 있는지 여부를 표시하며 과거 이력을 삭제하지 않는다.

## 차단과 유지

| 중단 시 차단 | 중단 시 유지 |
|---|---|
| 일반 예산·재고 신규 예약, 실행 준비 | 기존 비용 대사, 확인된 무집행 취소, 주문 이행·수집 |
| Buffer 게시 승인·예약·전송 직전 접수 | 기존 게시 상태 조회와 불확실 결과 확인 |
| Meta 예산 예약·실행 승인·ACTIVE 전환 | PAUSED 전환, 광고비 대사·정산·감시 |
| 학습 채택·활성화·연장, Meta 규칙 승인 | 관측 결과·초안·회고 저장, 규칙 중지·폐기 |
| 프롬프트 활성화·지정 적용·승격·고정 해제 | 등록·경보 확인·rollback |

점포 회고의 자동 학습 적용은 보류 사유를 반환하며 회고 자체는 저장한다. 미리보기도 같은 조건을 표시한다. Q 소유 프롬프트 엔진은 바꾸지 않고 기존 owner 잠금 안의 API 진입점에서 검사한다.

## 외부 실행의 한계

중단 토글은 이미 접수된 외부 작업의 취소 완료를 뜻하지 않는다. Buffer는 전송 직전에 다시 검사하고, 전송이 시작된 요청은 응답 또는 불확실 결과를 보존한다. Meta도 활성화 단계마다 상태를 확인하되 외부 상태 확인 전 `unknown`/`maySpend`를 임의로 해제하지 않는다. 예산·재고 예약은 중단만으로 풀리지 않는다.

중단 중에도 기존 예약의 취소 가능 여부와 비용을 대사해야 한다. 재개는 새 요청을 허용할 뿐 외부 작업을 자동 재전송·재활성화하거나 학습을 자동 승격하지 않는다. 이번 개발 검증에서 실제 광고 집행·고객 전송은 수행하지 않는다.
