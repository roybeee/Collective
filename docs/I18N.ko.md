# 다국어(i18n) 1단계 — ko/en/ja

GLOBAL-PLAN G6 1단계 기록이다. 한국어가 원본이자 기본값이고, 영어·일본어는 화면을 보는 사람이 고를 때만 바뀐다.

## 구조

| 파일 | 역할 |
|---|---|
| `lib/i18n/ko.ts` | 한국어 원본 중 홈이 그리는 문구. 홈 첫 로딩에 그대로 실린다. |
| `lib/i18n/ko-lazy.ts`, `lib/i18n/lazy.ts` | 열 때 내려받는 화면(명령 팔레트·확인 대화상자 본문·행 안 동작·설정·언어 선택)의 한국어 원본. 그 화면 파일이 `import '@/lib/i18n/lazy'`로 등록하므로 그 화면 청크에 실린다. 두 파일의 키를 합친 것이 `MessageKey`다. |
| `lib/i18n/ko-<구역>.ts`, `lib/i18n/lazy-<구역>.ts` | 3단계에서 `ko-lazy.ts`를 화면 구역으로 나눴다: `campaign`(캠페인 상세 틀·브리프·회의·이력·성과·작업물 대화상자·계획 카드·타임라인·진행 단계·사용량), `exec`(제작·발행·채널 미리보기·묶음 게시), `settings`(설정 채널 카드·카카오), `trust`(규정 점검·수정 제안·근거·인용·AI 출처·소재 점수·수정 사유·담당 이름), `cards`(공유 링크·플레이스 초안·광고 제안·브랜드 사실). 화면 파일은 쓰는 구역의 `import '@/lib/i18n/lazy-<구역>'`를 직접 둔다. `ko-lazy.ts`는 공통 구역(확인 대화상자 본문·행 안 동작·명령 팔레트·설정 틀·언어 선택·상태 배지)만 남았다. |
| `lib/i18n/ko-agenda.ts` | 서버가 만든 안건 제목·설명(`titleKey`·`detailKey`)의 한국어 원본. 화면에 등록하지 않는다(한국어 화면은 서버 문장 그대로). |
| `lib/i18n/en.ts`, `lib/i18n/ja.ts` | (구역 파일 `en-<구역>.ts`·`ja-<구역>.ts`를 묶는다. 키가 `ko-<구역>.ts`와 같아야 한다) 영어·일본어 사전. `Record<MessageKey,string>`이라 키가 빠지면 타입 검사가 실패한다. 그 언어를 고를 때만 동적 import로 내려받는다. |
| `lib/i18n.ts` | `t(key, vars?)`, `setLocale`, `currentLocale`, `missingKeys()`, `LOCALE_BOOT_SCRIPT`, 지금 언어로 형식을 맞추는 `localMoney`·`localCompact`·`localDay`. React를 쓰지 않아 서버·테스트 런타임에서도 읽힌다. |
| `lib/i18n-react.ts` | `useT()`·`useLocale()`. `useSyncExternalStore`로 언어가 바뀌면 다시 그린다(`lib/ui/theme.ts`와 같은 방식). |
| `components/app/locale-toggle.tsx` | 한국어·English·日本語 선택(라디오 묶음). 묶음 이름은 지금 언어로 읽힌다. |
| `lib/format.ts` | `money(v, empty, locale)`·`compact(v, locale)`·`dayLabel(v, locale)`. 언어 인자를 주지 않으면 한국어이며 기존 결과와 바이트가 같다. |
| `lib/brief-language.ts` | 산출물 출력 언어(`outputLanguage`) 판정과 지시문 한 줄. |

- 선택은 localStorage `locale`에 남는다. `app/layout.tsx`의 부트 스크립트가 첫 그림 전에 `html[lang]`을 맞추고, 첫 구독 때 사전을 받아 문구를 바꾼다(새로고침이 필요 없다).
- 사전을 받은 뒤에 언어를 바꾸므로 반쯤 번역된 화면이 보이지 않는다. 받지 못하면 한국어에 머물고 선택 아래에 안내가 뜬다.
- 없는 키·빠진 번역은 한국어로 보이고 `missingKeys()`에 `'en:nav.overview'` 형식으로 남는다. 로그는 남기지 않는다.
- 문구의 `{name}`은 `t(key,{name})`로 채운다. 복수형 규칙은 두지 않는다. 숫자는 `'{n}건'`처럼 단위와 함께 쓴다.
- 언어 선택은 머리 띠에 두지 않는다(홈 첫 로딩 예산 `tests/ux-budget.json` `homeJsGzKB`). 계정 메뉴의 팀 계정 관리(`app/account-panel.tsx`)와 설정 > 팀·권한(계정 메뉴가 없는 헤더 인증에서도 열린다)에 있다.

## 산출물 출력 언어

- 캠페인 브리프에 선택 항목 `outputLanguage: 'ko'|'en'|'ja'`가 있다. 기본은 한국어이며 한국어는 키를 저장하지 않는다(이전 캠페인과 바이트 동일). `validateCampaign`이 그 밖 값을 400으로 거절하고, `'ko'`를 보내면 저장된 언어를 지운다.
- 영어·일본어일 때만 역할(`lib/role-instruction.ts`)·회의(`lib/meeting-input.ts`)·브리프(`lib/brief-input.ts`) 지시문 끝에 `outputLanguageLine()` 한 줄이 붙는다. 한국어 지시문은 바뀌지 않으므로 프롬프트 기준선 픽스처를 다시 찍지 않는다.
- 화면 언어와 산출물 언어는 따로다. 브리프 화면의 선택 칸은 1단계에 없다(`POST /api/action` `save_campaign`의 `data.outputLanguage`로만 지정한다).

## 키 추가 방법

1. 홈 첫 화면이 그리는 문구는 `lib/i18n/ko.ts`, 열 때 내려받는 화면의 문구는 `lib/i18n/ko-lazy.ts`에 `'영역.이름':'한국어 문구'`를 더한다. 영역 접두어는 화면 단위로 쓴다(`nav.`·`agenda.`·`confirm.` 등). 홈 부품이 `ko-lazy.ts` 키를 쓰면 키 이름이 보이므로 `tests/i18n-coverage.test.mjs`가 막는다.
2. 같은 키를 `lib/i18n/en.ts`·`lib/i18n/ja.ts`에 더한다(타입 검사와 `tests/i18n-coverage.test.mjs`가 빠진 키·남는 키·자리표시 차이·남은 한글을 잡는다).
3. 부품에서는 `const t=useT()`로 받아 `t('영역.이름',{값})`을 쓴다. 부품 밖 함수(오류·확인 문장)는 `import {t} from '@/lib/i18n'`. `ko-lazy.ts` 키를 쓰는 파일은 `import '@/lib/i18n/lazy';`를 둔다.
4. 금액·큰 수·요일 날짜는 `localMoney`·`localCompact`·`localDay`를 쓴다.

## 2단계 화면 추가 방법

1. 화면 파일의 문구를 위 방법으로 키로 옮긴다. 한국어 화면의 글자는 그대로 둔다(기존 E2E는 한국어 이름으로 요소를 찾는다).
2. `tests/i18n-coverage.test.mjs`의 목록에 파일을 더한다. `strict`는 JSX 밖 문자열까지 0, `jsxOnly`는 JSX 안만 본다. `app/workspace.tsx`는 `workspaceRegions`에 영역(태그·className)을 더한다.
3. 영어·일본어 사전은 홈 첫 로딩에 실리지 않지만 `ko.ts`는 실린다. 1단계 뒤 홈 첫 로딩은 168KB(예산 170KB)라 여유가 작다. 홈 밖 화면 문구는 `ko-lazy.ts`(또는 화면별 새 구역 파일과 등록 모듈)에 둔다(`tests/ux-budget.json` `homeJsGzKB`).
4. 새 화면이 정적 문구 원본 검사(다른 테스트의 `includes('…')`)에 걸리면 사전 값과 `t('키')` 사용을 함께 확인하도록 고친다.
