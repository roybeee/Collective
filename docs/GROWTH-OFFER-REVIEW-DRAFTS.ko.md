# 관측 근거 기반 오퍼 검토 초안

일일 검토는 최신 canonical 실험 결과와 `current`·`observed` 반응 근거를 읽어 별도 검토 초안을 만든다. 운영자가 적은 성과 메모, 게시 성공만 있는 기록, 지난 분석과 불일치하는 주문·환불은 새 초안의 근거가 되지 않는다. 반응 기록은 인과 효과나 판매 개선을 증명하지 않는다.

초안은 캠페인 판, 정확한 오퍼 판과 전체 digest, 원천 종류·ID·최신 분석 참조·digest를 동결한다. 조회할 때 현재 원문과 원천을 다시 검증하여 `current`, `stale`, `unavailable`로 표시한다. 이전 초안을 조용히 덮어쓰지 않는다. 제안은 검토 항목을 안내하는 고정 문구이며 AI 평가·새 가격·새 판매 문구가 아니다. 오퍼·가격 승인·상품·외부 판매처를 수정하지 않고, 적용 권한도 부여하지 않는다. 실제 변경은 기존 오퍼 승인 화면에서 별도로 처리한다.

한 번에 원천 20개를 회수하고 커서로 같은 날 이어 처리한다. 잘못된 원천은 오류 수에 기록하며 다른 원천을 계속 처리한다. 캠페인별 초안 1,000개에서는 기존 기록을 삭제하지 않고 `intakeHeld`를 표시한다. 조회는 최신 50개와 이전 기록 존재 여부를 표시한다. 이전 전체 기록용 페이지 UI는 제공하지 않는다.

원장 종류는 `growth_offer_review_draft`(불변 초안), `growth_offer_review_cursor`(재개 위치)이다. 캠페인 삭제 시 함께 삭제 가능하며 원천 실험·실행 감사 기록의 보존 정책은 바꾸지 않는다. 권한은 관리자/소유자, owner 범위 잠금 및 캠페인 현재판을 검사한다. 반복 실행은 같은 근거·오퍼 digest의 같은 ID로 중복 생성을 막는다. 글로벌 중단 시 새 초안을 만들지 않는다.

외부 호출과 모델 비용은 0원이다. 실제 SQLite 회귀는 canonical 주문 반응·환불·최신 분석 교체·동일판 원문 변조·수동 메모 배제·중복·권한·현재판·중단·수용 한도·원천 오류 격리를 검증한다.
