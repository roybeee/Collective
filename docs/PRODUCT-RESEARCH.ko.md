# 상품 리서치·MD 에이전트 운영 문서 (P4·P5 서버)

결론: 상품 리서치는 공식 API와 운영자·계약 데이터 가져오기로 시장 지표를 모으고(수집), 결정형 점수표로 평가하고(재계산), 근거를 인용한 선정 메모를 만든 뒤(결정형 또는 AI 팀 상품 MD), 대표·관리자가 승인한 상품만 성장2 캠페인의 시장 근거로 넘긴다. 발주·결제·가격 승인·공급자 연락은 하지 않는다(`mayOrder:false`).

- 계획: [PRODUCT-RESEARCH-PLAN.ko.md](PRODUCT-RESEARCH-PLAN.ko.md). 이 문서는 구현된 서버의 운영 기준이다.
- 코드: `lib/product-research/server*.ts`, `lib/product-research/md-prompt.ts`, `app/api/product-research/route.ts`, 워커 큐 `lib/research-worker.ts`(`product_research`).
- 검사: `tests/product-research-server.test.mjs` (mocked: 메모리 SQLite, 공급자·HERMES fetch 스텁, 실제 네트워크 0).

## 1. 스위치

| 스위치 | 기본 | 켜면 |
|---|---|---|
| `product_research` | 꺼짐 | 화면 결과·모든 쓰기(조사 방향·출처 연결·가져오기·재계산·메모·결정·넘기기·백테스트). 꺼져 있으면 쓰기는 409, GET은 같은 모양으로 `enabled:false`와 빈 목록(조사 방향·출처 연결 상태는 보임) |
| `product_research_collect` | 꺼짐 | 워커 tick의 `product_research` 큐와 소유자 즉시 수집(`collect_now`). 두 스위치가 모두 켜진 소유자에게만 워커가 큐를 돌린다 |

## 2. 저장하는 것 (`records`, 모두 소유자 범위·캠페인과 무관)

| kind | 내용 | 한도·수명 |
|---|---|---|
| `pr_credential` | 출처 자격증명. `secret`만 봉인 문자열(`lib/credential-crypto-server.ts`, 키 회전·전체 재암호화 대상), 화면에는 연결 여부·끝 4자리 계정·갱신 시각만 | 출처 묶음 5개 |
| `pr_snapshot` | 원본 스냅샷(불변): 출처·요청 범위·수집 시각·본문 해시·크기·상태·한계·관측값. 외부 원문 없음. 검색광고 응답은 힌트와 검색수 상위 100개 키워드만 남긴다 | 2만 개. 넘으면 400일 지난 것 중 현재 점수표·메모·결정이 가리키지 않는 것부터 지우고, 그래도 모자라면 409 |
| `pr_keyword_group` | 같은 수요 키워드 묶음 | 재계산마다 교체 |
| `pr_product` | 정규화 상품(목록 묶음·분류·현재 점수표 포인터·사람 브랜드 적합성) | 2,000개. 사람이 확인한 묶음(`match.confirmedBy`)은 재계산이 바꾸지 않는다 |
| `pr_score` | 점수표 판(불변). 입력 해시가 같으면 새 판을 만들지 않는다 | 5만 판. 넘으면 현재 포인터·결정이 가리키지 않는 오래된 판부터 |
| `pr_brief` | 선정 메모(인용 검사 통과분만) | 2,000개 |
| `pr_decision` | 승인·보류·제외와 사유, 넘긴 캠페인·신호 | 5,000개 |
| `pr_backtest` | 백테스트 결과(이력이 짧으면 null과 사유) | 200개 |
| `pr_quota` | 출처·날짜별 쓴 단위 | 60일 |
| `pr_collect_state` | 오늘 계획·진행 위치·출처별 마지막 오류·추적 영상(최대 200) | 1개 |
| `pr_settings` | 조사 방향(기본: 상온 식품 6개, 상온, 가격 상한 없음) | 1개 |
| `pr_request` | 쓰기 요청 멱등 근거(요청 지문, 결과 id). 자격증명 입력은 지문에도 넣지 않는다 | 2만 개, 90일 지난 것부터 정리 |

## 3. 외부 호스트·쿼터·근거

| 출처 | 호스트 | 하루 상한(이 앱) | 공급자 쿼터 | 근거 |
|---|---|---|---|---|
| 네이버 검색광고 키워드 도구 | `api.searchad.naver.com` | 키워드 40개(호출당 5개, 8회) | 미공개(429를 쿼터 오류로 받음) | 공식 API, 광고주 키 서명 |
| 네이버 데이터랩 검색어 트렌드 | `openapi.naver.com` | 묶음 40개(호출당 5개, 8회), 최근 104주 주간 | 1,000회 | 개발자센터 공식 API |
| 네이버 쇼핑 검색 | `openapi.naver.com` | 키워드 20개 | 25,000회 | 개발자센터 공식 검색 API |
| YouTube Data API v3 | `www.googleapis.com` | 발견 3회(`search.list` 100단위씩) + 추적 영상 200개(`videos.list` 50개씩) | 10,000단위(태평양 날짜) | 공식 API |
| 쿠팡 파트너스 | `api-gateway.coupang.com` | 식품(1012) 베스트 1회 | 승인 조건에 따름 | 공식 Open API(HMAC) |
| 운영자·계약 가져오기 | 없음(파일) | 2MB·2,000행/파일 | — | 쿠팡·무신사·올리브영 랭킹은 자동 수집 금지(robots·403), 계약 데이터는 계약 전 내보내기 파일만 |

- 호출 전에 쿼터 원장에 단위를 원자적으로 예약한다. 한도를 넘게 되면 호출하지 않고 그 출처를 오늘 건너뛴다(쿼터 초과 0). 입력 오류처럼 호출 전에 막힌 경우만 되돌린다.
- 출처 연결(`connect_source`)은 저장 전에 가장 싼 실제 호출 1번으로 키를 확인한다: 검색광고 힌트 1개, 데이터랩 7일 1묶음, YouTube 공개 영상 1개 `videos.list`, 쿠팡 검색 1개. 결과는 저장하지 않고 쿼터만 센다. 계약 데이터는 고정 호스트가 없어 형식만 확인한다.
- 법적 근거·약관 확인은 대표 결정 D5(법무 검토) 대상이다. 이 문서는 법률 판단이 아니다.

## 4. 흐름

1. **수집**: 한국 날짜로 하루 1번 계획을 세우고 워커 tick마다 12단계씩 이어 간다. 소유자는 `collect_now`로 바로 30단계까지 실행할 수 있다. 한 출처의 실패(인증·쿼터·네트워크)는 그 출처만 멈추고 다른 출처는 계속한다. 계획을 다 돌면 재계산한다.
2. **재계산**(`recompute`, 외부 호출 없음): 최근 120일 스냅샷(최대 3,000개) → 시계열 → 키워드 묶음(최대 500개) → 상품 매칭(자동 목록 최대 400개, 0.95 이상만 자동 병합) → 점수표 w1. 영상 조회수는 키워드로 발견한 영상들의 증가분을 더한 합성 누적 시계열로 넣는다(점마다 `videos.list` 스냅샷을 가리킴, 메모 주장에는 쓰지 않음). 수익성은 소싱 견적 연결이 생기기 전까지 미확인이다.
3. **선정 메모**(`generate_brief`): `template`은 결정형. `model`은 HERMES 연결이 있어야 하고(없으면 409), 관측표만 보내고 출력의 모든 숫자를 관측표와 대조한다. 하나라도 어긋나면 저장하지 않고 409와 근거 없는 목록을 돌려준다. 같은 요청 번호로 다시 보내도 모델을 다시 부르지 않는다. 약 20초 안에 끝나지 않으면 `pending:true`를 돌려주고, 같은 요청 번호로 다시 보내면 이어서 확인한다. 프롬프트는 `lib/product-research/md-prompt.ts`(레인 Q가 레지스트리에 옮길 예정).
4. **결정**(`decide`): 현재 점수표 판에만, 한 문장 이상 사유와 함께. 선정 금지(`blocked`) 점수표는 승인할 수 없다(409).
5. **넘기기**(`handoff`): 승인한 최신 결정만, 같은 소유자의 보관 전 캠페인·캠페인 판 일치·전역 중단 꺼짐일 때. 캠페인에 시장 신호 1개(`sourceType:'market'`, 제목 `상품 리서치: <상품>`, 요약은 인용 관측 문장만, 관측 시각 = 인용 스냅샷 중 최신 수집 시각, 유효기한 +30일)와 성장 이력을 한 batch로 쓰고, 신호에 `productResearch{decisionId,scoreCardId,productId,snapshotIds}` 계보를 남긴다. 출처 주소는 상품 목록의 공개 https 주소(쿼리 없는 것), 없으면 요청의 `sourceUrl`이 필요하다(409로 안내). 넘긴 신호는 성장 화면에서 고칠 수 없다.
6. **백테스트**(`run_backtest`): 화면은 정답 기준을 퍼센트로 보내고 서버가 비율로 바꾼다. 기준 시점 이전 4주 + 관측 기간보다 이력이 짧으면 숫자 없이 사유를 남긴다.

## 5. 실패 모드

| 상황 | 결과 |
|---|---|
| 스위치 꺼짐 | 쓰기 409, GET은 설명 상태 |
| 같은 요청 번호에 다른 내용 | 409 |
| 다른 작업 저장 중(소유자 잠금) | 409 |
| 가져오기 파일 오류 | 400 `{error, issues:[{row,field?,message}]}`, 저장 0 |
| 키 확인 호출 거절 | 400(인증)·409(쿼터)·502(네트워크), 저장 0 |
| 저장된 키를 풀 수 없음 | 409, 다시 등록 안내 |
| 출처 쿼터 소진 | 그 출처 오늘 건너뜀, `collect.lastErrors`에 표시 |
| 스냅샷 한도·정리 불가 | 409 |
| 모델 메모 인용 실패·형식 오류 | 409 `{error, unsupported}`, 저장 0 |
| 전역 중단 중 넘기기 | 409 (수집·채점·메모는 계속) |

## 6. 하지 않는 것

- 자동 발주·결제·오퍼·카탈로그 가격·공급자 연락·광고비 집행.
- robots.txt·약관이 막은 사이트의 자동 수집, 레지스트리 밖 호스트 호출, 리디렉트 따라가기.
- 외부 응답 원문 저장, 리뷰 작성자 등 개인정보 저장(개수만).
- 인용 검사를 통과하지 못한 모델 메모 저장, 모델이 점수를 바꾸는 것.
