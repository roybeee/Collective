# M6 보고에서 다음 실험으로

성과 대조에서 기록한 보고를 선택해 보류·중단·재실험·계속 관찰이라는 사람의 판단을 남긴다. 재실험은 같은 캠페인의 현재 소재를 선택하고 가설·바꿀 한 가지·대조안·실험안·지표·최소 표본·종료 기준을 채운 준비 초안이다. 구매 지표가 없는 기존 바이럴 실험에 이를 억지로 넣지 않는다.

- `meta_ads_learning_decision`은 보고 ID/판/digest, 캠페인 판, 판정 근거와 선택한 소재 ID/판/파일 hash를 보존한다. 같은 요청은 멱등이며 다른 내용은 새 판정 이력이다.
- 저장 전에 같은 기간의 주문·성과를 다시 대조한다. 환불·추가 주문·성과 개정 뒤에는 새 보고를 기록해야 한다. 조회에서는 이전 판단을 삭제하지 않고 낡은 근거를 표시한다. 소재 버전·파일·사실의 유효성 변경도 표시한다.
- 워크스페이스 소유자·관리자만 판단을 기록한다. 불변 사전등록은 소유자만 가능하다. CSRF·캠페인 범위·owner 잠금·판 비교를 적용한다. 직원은 읽기만 가능하다.
- `evidenceStatus`는 자료 부족 또는 관찰 자료일 뿐이다. 계속 관찰이 지출 권한을 부여하거나 재실험 후보가 완료 실험·승자·증분 근거로 승격되지는 않는다. 규칙 자동 활성화와 외부 호출은 없다.
- 보고와 판단 이력은 최근 20개를 읽으며, 이력에 참조된 이전 보고도 대조한다. 캠페인 삭제 정책은 보고와 함께 삭제다.

검증은 `tests/meta-learning.test.mjs`와 `e2e/meta-learning.spec.ts`. 로컬 SQLite/브라우저 및 모의 인증을 사용하며 실제 광고 효과 검증이 아니다. 외부 전송·유료 모델 실행 0.

## 불변 사전등록

같은 learning API의 `action=preregister`로 기존 draft 후보를 사전등록한다. `meta_ads_learning_decision` 원장에 새 판을 추가하며 원래 draft는 수정하지 않는다. 신규 kind나 외부 쓰기는 없다.

- 원후보 ID·version·candidateDigest와 보고 ID·판·digest, 캠페인 판, 소재 판·PNG hash를 확인한다. 현재 보고나 소재가 달라졌으면 거부한다.
- 가설·한 변수·control/treatment·primaryMetric·최소 표본·중단 기준은 원후보에서 복사하며 클라이언트 값으로 덮지 않는다. 미래 시작/종료(최대 31일), 종료 후 성숙 대기(24~720시간), 고정 조건·배정 및 측정 계획, 한 변수 확인을 함께 고정한다. 시각은 한국시간 입력을 UTC ISO로 저장한다.
- 동일 후보의 정확히 같은 사전등록 요청만 멱등이다. 기간이나 조건을 바꾼 재등록은 409로 거부한다. 최근 20건 바깥의 기존 등록도 DB에서 찾아 중복 등록을 막는다. 다른 요청은 최신 원장 version CAS와 워크스페이스 잠금을 사용한다.
- 사전등록은 배정·집행 시작이 아니다. `observationSource=not_connected`이며 실험 결과는 `insufficient`, 근거 변경 시 `invalid`다. 기존 보고의 `observation_only`는 관찰 근거 표시이며 실험 성공이나 인과 검증으로 승격하지 않는다. 시간이 지나거나 총 주문이 늘어도 승자·규칙·광고를 자동 활성화하지 않는다.

기존 D 원장(`lib/learning.ts`의 `ViralExperiment`)은 share/completion/click rate 지표와 분자/분모를 요구한다. 구매 주문 수·기여이익 후보를 이 타입으로 강제 변환하면 다른 지표를 통계 검증한 것처럼 보이므로 재사용하지 않는다. `lib/viral-stats.ts`도 같은 이유로 호출하지 않는다. 점포 실험은 날짜·측정 원장은 있으나 이 사전등록의 소재/보고 lineage와 불변 기간·성숙 계약을 갖지 않아 현재 M6 원장을 확장했다.

남은 개발: 실험군 배정과 관측 수집, 군별 최소 표본/성숙 검증, 원가·세금 기준을 포함한 결과 정합성, 해당 지표에 맞는 통계 계약, 검증된 결과의 규칙 후보 연결. 사전등록 화면은 이 한계를 명시한다.

단위 검증은 실제 메모리 SQLite·모의 인증으로 수행한다. E2E는 합성 브랜드 사실→실제 브라우저 Canvas PNG→로컬 R2 소재→후보→사전등록→새로고침 보존 경로를 검증하며 외부 광고를 호출하지 않는다.
