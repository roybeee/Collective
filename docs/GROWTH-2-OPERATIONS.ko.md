# 성장2 주문·재고·정산 운영

원안 G2-02/03/30/32의 후속 증분이다. 첫 공통 기반 #266 위에 `codex/growth2-fulfillment`로 개발한다. 원안 전체와 외부 판매·배송·은행 연동 완료를 뜻하지 않는다.

## 사용 흐름

캠페인 → 성장·판매 → 주문·재고·이행 운영. 지점이 연결된 캠페인에서 같은 브랜드·지점·SKU의 공유 재고를 등록한다. 상품 초안의 재고 숫자를 실물 재고로 자동 복사하지 않는다. 개/팩 단위는 고정하며 품목 실제 수량을 입력한다.

기존 지점 주문을 선택하고 판매 미션·오퍼·SKU를 품목에 연결한다. 기존 주문의 결제/환불액이 금액 정본이다. 품목 연결은 새 매출을 만들거나 인과 귀속을 증명하지 않는다. 품목 배분 합계는 같은 지점의 모든 캠페인 연결을 합쳐 원 주문 금액 이내로 검사한다. 금액 미확인은 null이다.

출고·환불 수량·실물 반품·미출고 예약 해제를 서로 다른 사건으로 기록한다. 환불 수량 입력만으로 재고를 되돌리지 않는다. 실제 반품 수령, 검수 수락, 재판매 가능, 재입고 확인이 모두 있어야 실물 재고에 더한다. 출고한 수량을 예약 해제로 되돌릴 수 없다.

지급예정과 실입금 증빙을 별도로 등록한다. 분할 입금은 개별 입금 참조를 달리하고 정정은 같은 사건의 다음 판이다. 예정 수수료와 입금 증빙 수수료도 별도 합산하며 기존 주문 비용에 다시 더하지 않는다. 실입금 합계는 수령 현금이며 순현금흐름이나 이익이 아니다. 운영자 증빙은 은행 대사 완료로 표시하지 않는다.

## 저장·충돌 계약

`GET/POST /api/growth/operations`는 소유자·브랜드·지점 범위, 관리자 쓰기, CSRF, 소유자 잠금, 캠페인 판을 검사한다.

| 작업 | 검사와 결과 |
|---|---|
| create_inventory | 브랜드·지점·SKU 결정 키, 중복 재고 생성 거부, 모르는 수량은 null |
| stock_adjust | 실사 총량 또는 입고 증가량, inventoryVersion CAS, 관측/기록 순서 검사 |
| reserve_stock | 준비된 미션의 오퍼/SKU 판 확인, 공유 가용량 내 예약, 기존 미배정 예약 중복 거부 |
| release_stock | 취소/실패 확인 미션의 미배정 수량만 명시 해제, unknown 자동 해제 금지 |
| link_order | 기존 주문·판매 시점 미션/오퍼/상품 스냅샷, 실제 주문 초과분은 부족 상태로 보존, 금액 정정은 재할당하지 않음 |
| record_operation | 사건 ID·내용 digest 멱등, inventoryVersion CAS. 새 출고는 최신 주문 판·취소·전액환불 확인. 정상 0원 주문은 이행 가능 |
| save_settlement | 같은 사건 다음 revision, 같은 개별 입금 참조 중복 거부, 최신 주문 판 확인, 정정 이력 보존 |

응답 유실 후 동일 사건 ID와 내용으로 재전송하면 수량/금액을 다시 더하지 않는다. 같은 ID의 다른 내용은 거부한다. 실사 시각보다 오래된 이동을 뒤늦게 적용하지 않는다. 과거 사건 복구는 현재 자동 지원 범위 밖이며 새 실사·원장 대사가 필요하다.

주문 변경은 품목 금액 배분과 정산 연결을 재대사 필요로 바꾼다. 판매 후 미션·오퍼·상품이 개정돼도 기존 판매 시점 스냅샷을 보존하고 주문 금액만 재대사한다. 출고 전 주문이 다른 지점으로 바뀌면 차단한다.

신규 kinds: growth_inventory_item(store), growth_stock_event(inventory_item), growth_order_line(store), growth_order_line_history(campaign), growth_settlement(store), growth_settlement_history(campaign). 이벤트/정정 이력은 INSERT 추가 전용이고 현재 투영과 같은 batch에 저장한다. 운영 기록이 연결된 캠페인은 삭제를 막고 보관하도록 안내한다. 공유 재고는 캠페인 삭제 범위 밖이다.

한도는 지점 재고500, 품목연결1000, 정산사건1000, 상품별 재고사건5000이다. 초과 시 부분 합계를 전체로 보여주지 않고 대사를 요구한다. 고객 이름·연락처·배송주소·계좌번호·택배 추적번호는 이 원장에 입력하지 않는다. 기존 시스템의 64자리 주문 해시는 orderId 참조에만 허용하고 저장 시 소유자/지점 주문 존재를 검증한다.

## 아직 남은 원안 범위

- 예산+재고의 단일 외부 실행 예약, 실제 판매/게시 adapter 연결, 외부 영수증 자동 조회·복구.
- 공식 재고/택배/반품/정산 수집, CS 원인·정산 지연 관리, 공급계획/재발주점/현금 소요안.
- 브랜드 전체 목표·일일 결정, 구매 병목, 수요 시퀀스, 동의 기반 재구매, 운영 교훈과 학습 적용.
- 일반 판매의 실험/검증 확대와 조건부 후속 카드. [전체 33개 카드](GROWTH-2-PLAN.ko.md)를 계속 기준으로 사용한다.

외부 전송·입금·실판매 효과 검증은 not_run이다. 검사 실행 결과와 PR/게시 상태는 [STATUS](STATUS.md)에 기록한다.
