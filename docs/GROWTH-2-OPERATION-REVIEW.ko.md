# 주문·품목 운영 확인 목록

원안 G2-30/32의 부분 구현. 기존 운영 조회에서 현재 캠페인 주문·연결 품목·참조 공유 재고를 읽어 확인할 일을 모은다. 새 저장 종류·API·외부 실행은 없다.

- 주문 변경 후 재대사, 배분 근거 미확인, 품목 미연결, 정확한 재고 할당 미확인, 미출고 할당, 취소/환불 후 남은 할당, 공유 원장 미확인/부족을 구분한다.
- 재고 할당은 주문 ID가 아니라 품목 ID·미션 계보·수량으로 대조한다. 예약 없는 직접 할당의 빈 미션/예약 ID 쌍도 기존 원장 계약에 따라 인정한다. 확인 불가 수량은 null, 정상 0은 0으로 유지한다.
- 배송 약속일이 없어 배송 지연으로 단정하지 않는다. 환불액에서 반품 수량을 추정하지 않는다. 공유 재고 부족은 원장 전체 값이며 현재 캠페인 부족으로 귀속하지 않는다.
- 정확한 품목 재대사·이행 기록·주문 연결·재고 폼으로 이동한다. 이행 종류·수량·증빙·안전 확인은 자동으로 채우지 않는다. 미저장 입력이 있으면 이동을 막고 명시적 취소로만 입력을 버린다. 성공한 저장은 해당 폼 dirty만 해제한다.
- 조회 오류·갱신 중·읽기 권한에서는 목록 실행 버튼을 막는다. 목록 자체는 mayExecute=false이며 출고/환불/발주를 실행하지 않는다.

검증: 도메인32, 기존 운영 API49 passed(real pure/memory SQL, 인증 mocked); 타입·빌드 passed. 신규2+기존 운영2 E2E4 passed(real local D1/API/Chromium, 마지막 GET503만 mocked). 미연결 UI RED 실패 뒤 GREEN을 확인했다. 독립 리뷰 HIGH/MED0. 전체 회귀·CI·게시 상태는 STATUS에 기록한다. 실제 택배·은행·고객 연락은 not_run.

잔여: 실제 배송 약속/택배 상태·고객 문의 사건·처리 담당/기한과 정산 예외의 독립 증거 연결. 이 목록은 해당 기능 전체 완료가 아니다.
