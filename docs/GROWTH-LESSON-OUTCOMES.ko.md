# 교훈 적용의 자동 근거 회수 (G2-13/31)

일일 루프는 교훈 적용 기록을 20개씩 순환하며 현재 근거를 별도 회수합니다. 한 캠페인의 회수가 남으면 같은 날짜의 다음 실행에서 이어갑니다. 전역 중단 중에도 이 읽기·근거 보관 작업은 가능하며, 게시·지출·고객 발송·프롬프트 승격은 실행하지 않습니다.

수동 `outcome`, 적용 버전, 교훈 재사용 성공/실패 집계와 실패 방법 초안은 바꾸지 않습니다. 자동 기록은 `growth_lesson_outcome`, 변경 이력은 `growth_lesson_outcome_history`, 순환 위치는 `growth_lesson_outcome_cursor`에 캠페인 범위로 보관합니다. 동일 근거는 중복 기록하지 않으며 현재 기록과 변경 이력·순환 위치를 원자적으로 저장합니다.

교훈의 정확한 판·저장 digest·만료·재사용 가능 여부·상위 근거와 대상의 정확한 판을 검사합니다. 대상이 상태 전환으로 개정되어도 새 판을 자동 승계하지 않습니다. 해당 판에 다시 적용한 기록이 필요합니다. 조회할 때도 현재 근거와 대조하므로 다음 일일 실행을 기다리지 않고 원본 변경을 표시합니다.

판매 실험은 같은 owner/브랜드/캠페인/지점, 등록 설계 digest·개입 참조, 미션·오퍼·상품 판과 확정 사실·상품 유효기간, 최신 분석과 현재 canonical 주문·환불·원가·관측·주문 매핑을 확인합니다. 입력이 바뀌면 과거 분석을 현재 결과로 쓰지 않습니다. 결과는 판매 실험의 관측 결과이며 **교훈의 인과 효과는 측정하지 않음**으로 표시합니다. 실제 수익 증가를 교훈의 효과로 변환하지 않습니다.

미션 상태, 상세 적용 상태, 수요 단계 관측 여부는 운영 관측만 표시합니다. 원문의 메모·연락처·주문 내용은 자동 결과에 복사하지 않습니다. 수동 판단과 자동 관측은 화면에서도 분리합니다.

현재 기록은 최대 1,000개이며 이력 10,000개 이후 신규 자동 기록은 보류합니다. 기존 기록의 변경·무효화·복구는 이 한도 이후에도 가능하고 이력을 덮어쓰지 않습니다. 화면은 최신 이력 200개와 이전 이력 존재 여부를 제공합니다. 자동 관측은 운영자의 결과 확인 안건을 완료 처리하지 않습니다.

검증: `tests/growth-lesson-outcomes.test.mjs`는 실제 임시 SQLite에서 외부 호출을 금지하고 수동 결과 보존, 정확한 판·만료, canonical 환불 변경, 최신 분석 교체, 원자 저장 실패·재시도, 한도 이후 복구, 같은 날짜의 분할 회수를 검사합니다. 실제 제공자나 운영 데이터 변경은 포함하지 않습니다.
