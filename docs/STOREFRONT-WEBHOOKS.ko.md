# 자사몰 서명 주문 수신

자사몰 서버가 COLLECTIVE 형식으로 변환한 주문·누적 환불을 기존 `store_order` 장부에 자동 반영한다. 카페24/Shopify 네이티브 웹훅 어댑터는 아니며 해당 서버의 변환/서명 설정은 별도다. 고객 이름·주소·연락처를 받지 않고 Meta 전환 이벤트도 보내지 않는다.

## 설정

주문 대조 → 주문 자동 수신 연결(서버 개발자용)에서 소유자가 몰 식별자를 지정해 연결을 만든다. 기존 CSV와 같은 몰이면 같은 식별자를 사용한다. 지점당 최대10개, 같은 몰 식별자 중복 생성은 거부한다.

- 기본 수신 꺼짐. 32바이트 난수의 64자리 hex 서명 키는 생성/교체 응답에서 한 번만 보여 준다. 서버 비밀 설정에 저장하며 브라우저 코드/URL에는 넣지 않는다.
- 암호화 자격증명 저장과 기존 키 회전 경로를 재사용한다. 조회 응답에 원문/암호문을 포함하지 않는다. 관리자·직원은 조회만 가능하고 설정은 소유자·CSRF·판 CAS·mutation lock으로 보호한다.
- 소유자가 자동 장부 반영 확인 후 수신을 켠다. 키 교체는 즉시 기존 키를 무효화하고 수신을 끈다. 새 키를 몰 서버에 설정한 뒤 다시 켠다. 수신 중단은 기존 장부를 삭제하지 않는다.

## 요청 계약

`POST /api/storefront-webhooks/<connection-id>`, UTF-8 JSON, 최대64,000바이트/100주문. 연결이 지정한 소유자·브랜드·지점·몰을 사용하며 본문에서 범위를 지정하지 않는다. 수신 API는 로그인 쿠키 대신 HMAC을 검증한다.

- `X-Collective-Timestamp`: 현재 Unix 초 10자리 문자열, 수신 시각 기준 과거/미래 300초 안.
- `X-Collective-Signature`: `sha256=` + HMAC-SHA256(서명 키의 UTF-8 문자열, `timestamp + '.' + rawBody`)의 소문자 hex. 키를 hex decode하지 않는다. JSON 직렬화 후 그 **동일한 바이트**를 서명/전송한다.
- 본문 최상위는 `orders`만 허용하며 각 행은 아래 7개 필드만 허용한다. 임의 필드/개인정보 필드는 거부한다.

```json
{"orders":[{"order_id":"ORDER-EXAMPLE","revision":1,"order_date":"2026-09-01","status":"paid","paid_amount":10000,"refund_amount":0,"mode":"delivery"}]}
```

문자열은 order_id/order_date/status/mode, 나머지는 JSON 정수다. [CSV 계약](STOREFRONT-ORDERS-M2.ko.md)의 상태/누적 환불/최초 주문일 규칙을 그대로 사용한다. 주문 ID는 고객 정보가 아닌 몰의 불투명 주문 번호여야 한다.

## 처리와 복구

- 서명·시간을 확인한 후 연결 상태를 잠금 안에서 다시 읽는다. 회전/중단/보관/브랜드 불일치이면 반영하지 않는다.
- 기존 CSV 처리에서 주문 준비 함수를 공통 모듈로 추출했다. 낮은 revision은 건너뛰고 같은 revision/내용은 중복, 같은 revision/다른 내용은409. 더 높은 revision은 기존 주문의 환불/상태를 갱신한다. 수동 장부 수정 충돌을 덮어쓰지 않는다.
- 주문·몰 연결·개정 기록·마지막 정상 수신 집계를 같은 DB batch로 저장한다. 일부 주문 충돌 시 전체 요청 미반영. 감사 행위자는 `webhook:<id>`이며 새 전환/구매 이벤트를 만드는 것이 아니다.
- 응답은 created/updated/duplicates/older 집계와 externalTransmissions0만 제공한다. 수신 화면은 마지막 **정상 수신**만 표시하며 모든 실패 시도 대장/서버 재시도 큐를 제공하지 않는다.
- 401: 서명/시각/수신 상태 확인, 400/413: 형식/크기 수정, 409: 설정 또는 장부 충돌 확인. 네트워크 응답 유실/일시 실패는 최신 시각으로 **같은 주문 ID·revision·내용**을 다시 서명할 수 있다. 무작정 revision을 올리지 않는다. 성공 응답 유실 후 재전송도 중복 처리된다. 전송 서버의 재시도 정책/한도/실패 알림은 해당 어댑터 책임이다.
- 미지 연결/서명 실패는 인증 오류로만 반환한다. 서명 키/원문 요청/고객 필드는 로그에 기록하지 않는다. 지점 보관 후에도 수신을 끌 수 있다. 자격증명은 캠페인과 독립하며 암호화된 비활성 연결과 장부를 유지한다.
