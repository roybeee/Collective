# 성장2 재발주 수량·시점·구매비 검토

G2-30의 단일 SKU 재발주 검토 부분 구현이다. 현재 상품과 공급 견적, 공유 재고를 수요 가정에 연결한다. 실제 발주·공급 계약·입고·지급·예산 예약을 수행하지 않으며 `mayOrder:false`를 유지한다.

## 수요와 재고의 범위

수요는 운영자가 입력한 기간·수량·근거의 가정이다. 기존 주문 건수를 SKU 수량이나 전체 판매속도로 간주하지 않는다. 기준기간 양끝을 포함한 달력 일수로 일평균을 계산하고 미확인과 확인된0을 구분한다. 미래의 기준기간과 유효하지 않은 날짜는 거부한다.

재고는 지점·SKU의 기존 사건 원장으로 계산한다. 다른 캠페인의 예약도 포함한 `onHand − reserved`를 그대로 사용하여 음수 부족분을 보존한다. 개/팩이 다르거나 재고가 미확인이면 구매수량을 확정하지 않는다. 미입고 발주 원장은 없으므로 발주 없음의 당일 확인·근거가 없으면 중복 발주 위험을 보류한다. 확인시각은 미래일 수 없고 한국시간 당일만 유효하다.

## 수량·시점·금액

- 재발주 기준: `ceil(기간 수량 × 납기 / 기간 일수) + 안전재고`.
- 목표량: `ceil(기간 수량 × (납기 + 추가 확보기간) / 기간 일수) + 안전재고`.
- 필요량: `max(0, 목표량 − (보유 − 예약))`.
- 구매 검토량: 필요량0이면0, 양수이면 필요량과 MOQ 중 큰 값. MOQ는 포장 배수가 아니다.

현재 기준 도달 여부와 가정 속도에 따른 검토 시점은 예측 참고이며 확정 납품일이나 자동 발주 일정이 아니다. 중간 곱·합도 안전한 정수 범위를 확인하고 넘으면 계산을 보류한다. 수요0에서 나눗셈으로 무한대 시점을 만들지 않는다.

금액은 기존 소싱 견적의 단가×검토량과 고정 배송비·부대비를 사용한다. 구매 불필요0이면 고정 배송비를 더하지 않는다. 만료·단위·세금·근거·비용 미확인은 보류한다. 세금 별도 견적은 소계만 제시하며 최종 필요현금·한도 충족을 확정하지 않는다. 사용자가 입력한 구매비 한도는 이 검토의 제한이며 은행 잔고·위임 예산이나 지출 권한이 아니다.

## 보존과 운영 경계

관리자 이상이 캠페인 판과 상품·후보 판을 확인하여 저장한다. 입력·상품·견적·재고·계산 시각·평가를 서버 불변 스냅샷과 digest로 보존한다. 현재 조건이나 시간이 바뀌면 변경 표시만 추가하고 과거 평가를 덮어쓰지 않는다. UUID 재시도·owner 잠금·원자 저장·용량 한도를 적용한다.

전역 중단 중에도 검토안 작성은 가능하며 기존 주문·재고·오퍼·예산·정산 기록은 변경하지 않는다. 검토는 캠페인 삭제 후에도 보존한다. 실제 판매속도 자동수집, 미입고 발주·현금 원장, 실제 사입과 공급자 검증은 후속 범위다.
