# 상품 리서치 보존 처리와 실제 검증 자료

2026-10-05, 기준 main `6f6401a3`, 사용자 “나머지도 개발진행해서 마무리하라”의 후속 구현.

## 보존 처리

출처 화면과 상품 리서치 OFF 화면에서 소유자가 보존 계획을 확인한다. 신규 `/api/product-research/retention`은 수집 스위치와 자격증명 없이 작동한다. 계획은 10분 동안 유효하며 원문 대신 종류별 영향 건수·해시·보류 사유를 반환한다. 적용 시 소유자 및 상품 리서치 잠금, 전체 조회 범위의 바이트·판·새 행 여부를 다시 확인한다. 확인과 삭제·영수증 저장은 한 D1 batch이며 실패하면 모두 롤백한다. 같은 계획 재실행은 추가 삭제하지 않는다.

자동 처리는 기본 OFF다. 소유자가 화면에서 영향을 확인하고 켜면 기존 작업자 순환에서 UTC 하루 한 번 확인한다. 수집 OFF와 별개로 동작하며 작업자가 연결돼 있어야 실행된다. 이번 배포는 운영 설정을 켜거나 실제 자료를 삭제하지 않는다.

안전하게 자동 처리하는 범위는 만료된 YouTube 원본과 계보가 확인된 로컬 스냅샷·격리·점수·메모·키워드·백테스트다. 사업/승인/멱등 요청/혼합 자료의 참조가 있으면 전체 계획을 보류한다. 사업 원장이나 승인 감사를 통째로 삭제하지 않는다. 모호한 구조·누락 참조·시각 오류·진행 중 요청·조회 상한(소유자 범위 2,000행/700KB)도 보류한다. 이 기능은 모든 형태의 과거 복사본을 자동 파기하는 기능이 아니다.

외부 복사본 증빙은 담당자의 참조와 설명을 기록하며 `operator_attested`다. 증빙을 올려도 공급자 삭제 자동 확인으로 승격하거나 보류된 내부 삭제를 우회하지 않는다. 외부 시스템의 실제 삭제 요청은 별도 수행한다.

보존 기준은 [YouTube 개발자 정책](https://developers.google.com/youtube/terms/developer-policies)을 참고한 내부 구현이며 정식 법률 의견이나 공급자 승인을 대신하지 않는다. 기존 출처 사용 차단은 그대로 적용한다.

## 실제 검증 자료

`/api/product-research/validation`은 소유자가 법무 검토·정답 상품·평가 원본을 등록하는 경로다. 단건 폼 또는 빈 CSV 양식을 제공한다. 입력은 시간 순서·중복·증빙 주소·해시를 검사하며 자료가 바뀌면 409를 반환하고 화면 입력을 유지한다. UUID 재시도는 중복 저장하지 않고 감사 기록과 현재 판을 원자적으로 저장한다.

- 법무: 출처·검토자·기간·증빙·허용 범위·결론. 현재 법무 등록 기준은 DataLab 두 출처다. 다른 출처 전체의 법무 완료를 뜻하지 않는다. 등록만으로 수집이나 AI 사용 정책을 해제하지 않는다.
- 정답: 정확 SKU, 의사결정과 관측 기간, 결과를 보기 전에 확정한 판정 기준, 증빙 파일 해시와 사람 검수 시각. 서로 다른 SKU 50개와 hit/control 양쪽이 필요하며 후보·AI 제안은 집계하지 않는다. 중복 SKU나 상충 자료는 완료 판정을 보류한다.
- 블라인드: 실제 평가자 이름, 배부 자료·제출 파일 해시, 동결·제출 시각과 원본 증빙을 등록한다. 소유자 대리 등록이므로 계정 인증과 독립성은 미확인이다. 3명 자료를 등록해도 독립 맹검 완료로 표시하지 않는다. 평가자별 독립 로그인·직접 제출은 이 경로에 포함하지 않는다.
- 출시 결과: 기존 결정→카탈로그 SKU→주문 원장의 4/8/12주 관측을 읽는다. 신규 장부를 만들거나 과거 다른 상품 매출을 실적으로 넣지 않는다. 매출 관측은 비용·마진·인과 효과 검증과 다르다.

등록 증빙은 불변 누적이며 같은 번호의 내용 교체는 거부한다. 신규 번호로 추가한 자료도 상충하면 검증 완료로 세지 않는다. 입력 내용이 실제 법무 의견이나 인간 판정이라는 사실을 소프트웨어가 자동 입증하지 않는다.

## 운영 인수 조건

자동 수집과 자동 보존 처리를 배포 때문에 켜지 않는다. 쿠팡 최종 승인, 권한 있는 법무 검토, 정답 검수자·실제 평가자, 신규 출시 관측은 실제 자료가 들어와야 진행된다. 현재 운영 자료를 시험 입력으로 대체하지 않는다.
