이 문서는 **「Collective 성장계획2 — 실행·개발계획 완성본 v2.0」(2026-09-27)**의 전체 범위를 개발 저장소에 복원한 실행 기준이다. 원문은 `Collective_성장계획2_개발플랜_완성본.html`, 원 대화는 [성장트랙 개발플랜 수립](https://chatgpt.com/c/6ab8f75f-8960-83ee-a173-ab4347e7d954)이다. v0.1 또는 Meta 광고 구현만으로 원래 범위를 대체하지 않는다.

착수 기준은 `origin/main`의 `8cc294297fb196e73c8fdc865768619c78e85293`, 개발 브랜치는 `codex/growth2-full`이다. 아래 카드 표는 원문 범위·의존성과 완료 조건을 보존한다. **모든 카드의 전체 수용조건 검증은 미완료**이며, 기존 기능 또는 새 기초 코드의 존재를 카드 전체 완료로 세지 않는다. 배포·실계정·사업 성과 상태도 별도로 검증한다.

## 1. 목적과 본선 범위

대표의 일일 지시 없이 시장과 소비자를 이해하고, 팔릴 상품과 구매 이유를 만들고, 실제로 판매하며, 결과에서 배워 다음 행동을 바꾸는 자사 이커머스 운영 시스템을 만든다. 대표는 사업 방향·사용할 자원·총예산·손실 한도·금지사항·고위험 예외를 정한다. Collective는 기회부터 상품·오퍼·판매면·유입·구매·이행·재구매·확대까지 연결한다.

본선의 여덟 능력은 다음과 같다.

1. 시장·경쟁·검색·리뷰·자사 구매·시즌 일정에서 판매 기회를 포착한다.
2. 고객 상황·현재 대안·불편·구매 장벽에서 새로운 구매 이유와 수요를 만든다.
3. 권리·재고·가격·원가·배송·반품을 갖춘 상품·번들·오퍼를 설계한다.
4. 광고·오가닉·협업·동의된 CRM 등 허용 접점을 실행하고 실제 영수증을 회수한다.
5. 상세페이지·결제·배송비·신뢰·옵션·문의의 구매 방해 요인을 수정한다.
6. 성숙한 주문·환불·비용을 바탕으로 반복 구매와 수익성 있는 확대를 수행한다.
7. 시장 지식·소비자 행동·실행 실패·판매 결과·대표 시각에서 규칙을 갱신한다.
8. 실현 순매출·공헌이익·현금·귀속·검증 증분을 구분해 사업 결과를 설명한다.

Meta는 유입·집행 경로 중 하나다. 외부 고객 대상 에이전시/도구 상품화 J는 선택 후속이며, 자사 반복 판매보다 우선하지 않는다. GEO/UCP·해외·MMM·추가 채널은 각각 데이터·권한·사업성이 준비될 때 수행한다.

## 2. 두 운영 루프와 증거 등급

```text
시장/고객 신호 → 고객 문제/기회 → 상품/오퍼 → 판매 미션 → 실행/주문/이행
                                  ↑                          ↓
                                  └──── 교훈/다음 행동 ────────┘

유망 개입 동결 → 사전등록/배정 → 성숙 주문·분모 → 독립 분석 → 검증된 확대
```

판매·학습 루프는 적은 데이터에서도 허용된 작은 탐색과 구매 오류 수정을 진행한다. 관측 사실·잠정 가설·시험 운영 규칙·운영 오류 교훈을 즉시 남길 수 있다. 확증 표본 부족은 이 루프 전체를 막지 않는다.

증명·확대 루프는 고정된 개입, 유효한 비교, 충분한 분모, 성숙 주문과 비용, 독립 검증을 요구한다. 전후 매출 상승·귀속 매출·기존 incrementality-lite를 인과 기여로 바꾸어 부르지 않는다. 성공 캠페인의 전체 카피를 자동 정답 라벨로 만들지 않는다.

탐색 예산과 검증된 확대 예산은 별도 원장으로 관리한다. 탐색 손실 한도를 반복 재설정해 총지출을 우회하지 않는다. 근거 없는 전환율을 채워 정밀한 예상 매출처럼 표시하지 않는다.

G0-B는 첫 고객 주문이 이미 발생했다는 조건이 아니다. 주문이 들어오면 결제·기록·환불·대사를 확인할 수 있어야 한다. 테스트 주문은 실제 고객 매출에서 분리한다. G0-B 전에 최소 예산 가드는 필요하지만 증분분석 전체 완성은 필요하지 않다.

기존 기준은 폐기 대신 적용 범위를 좁힌다. 3주 연속 주30주문은 데이터 유입 건강도 참고, 귀속25%는 측정 개선 목표, 대표 라벨100건은 판단 모사/선호 보정 성숙도다. HERMES 봉인 회귀0은 자동 프롬프트 승격에 적용하고, 토큰 폐기20% 초과는 해당 루프를 줄인다. 이 항목으로 모든 개발·주문 대사·제한판매를 일괄 차단하지 않는다.

| 등급 | 행동과 경계 |
|---|---|
| T0 | 읽기·집계·조사·점수화. 허용 출처·권한·비용 안에서 자율, 미확인 표시 |

| T3 | 캠페인 지출/예산 이동. 탐색/확대 구분, 1회20%·일/주/계정 총캡·잔액/비용예약, 큰 확대는 효과/수익 근거 |
| T4 | 새 가격정책·신규 계정/계약·대량 발송/사입·위기·법률/의료·이상치. 사람의 예외 결정 |

위임에는 브랜드/상품군·채널/계정·행동·가격/할인 선택지·총예산·최대 탐색손실·수량/재고·시간·금지사항·정책버전·승인자·회수 방법이 필요하다. 미설정은 무제한이 아니다. 새로운 외부 연락·협업·발송은 해당 행동 권한이 필요하다. 자동 승급은 충분한 실제 검수 표본·최근4주 승인율90% 이상·위반0·관련 평가 비회귀를 별도 검증한다. 2주 반려3건 또는 규제 위반1건이면 역할×채널을 낮춘다.

실행 전 가격·재고·권한·정책·손실·기간·중복/충돌을 검증하고 intent와 비용/재고 예약을 기록한다. 공급자 접수·실제 노출·방문·주문을 구분한다. 결과 불명 쓰기를 자동 재시도하지 않고 재조회·복구 담당과 기한을 둔다. 수동 게시/CSV는 유효한 제한판매 경로지만 자율 실적으로 세지 않는다.

전역 중단은 신규 게시·지출·학습 승격을 막되 주문 수집·비용 대사·감사·복구 조회를 유지한다. 접수된 예약의 취소 가능 여부와 실제 결과를 확인한다. 우선순위는 결제/주문/이행 오류→진행 판매→전환 개선→새 탐색→후보 최적화다.

상품 MD/소싱은 목표 원가·MOQ·납기·공급 후보·현금/재고 영향을 갖춘 발주안을 만든다. 크리에이터/제휴는 청중 적합 근거·브리프·권리·조건·수수료·추적 링크·일정을 관리한다. 구매 후에는 출고/지연·문의·취소/반품/환불과 반복 원인을 처리하고, 재발주점은 판매속도·납기·가용재고·현금 범위로 제시한다. 발주·새 계약은 위임 범위 밖 예외다.

24주 계획은 W1–4 첫 판매/장애 제거, W5–8 반복 오퍼/전환/증분, W9–16 위임된 자율 운영/재구매/독립 자기개선, W17–24 검증 방식의 예산·물량·채널 확대다. 코드 구현은 앞당길 수 있지만 환불·재구매·인과 관측 기간을 압축해 완료로 간주하지 않는다.

## 8. 측정·학습·완료 정의

실현 순매출은 완료 주문·취소/환불·세금/통화를 일관되게 처리하며 결제액·출고·정산 수령액과 분리한다. 공헌이익은 순매출에서 원가·변동 배송/결제/채널비·광고 등 해당 비용을 차감하되 할인/환불을 이중 차감하지 않는다. 현금은 실수령·집행/사입·정산 지연·재고를 별도로 본다. 미확인 비용을 0으로 채우지 않는다.

귀속 매출은 경로 관측이다. 검증 증분은 유효한 사전 설계의 추정치·구간·대상/기간·증거 등급이다. 상태는 `not_measured / collecting / insufficient / positive / negative / no_material_effect / invalid`를 구분한다. 주간 보고마다 유의성을 새로 요구하지 않고 양성만 합산하거나 같은 효과를 중복 가산하지 않는다.

TargetContract는 D1–2 잠정 목표를 기록하고 첫2주 속도·첫4주 매출/비용 기준선으로 D30까지 다음 기간 목표를 확정한다. 변경 이유와 버전을 보존하며 과거 실패를 지우지 않는다. 기준선0은 성장률 대신 순매출·공헌이익·유료 주문 절대값을 쓴다. 목표 미정은 사유와 확정일을 남기고 허용 판매/학습은 계속한다.

자율40→70→85%, 대표 예외 주5건, 폐기토큰10%는 단계별 후보 목표다. 가설10·실험5·규칙3 같은 산출량 할당을 강제하지 않는다. 학습은 실제 실행 변경·재발 감소·재사용 성과·검증 상태로 평가한다. 독립 봉인·후보 동결·조회/재시도 제한·rollback을 유지하되 일상 운영 교훈마다 봉인 실평가를 요구하지 않는다.

| 완료 종류 | 필요한 증거 | 대체할 수 없는 상태 |
|---|---|---|
| 기술 완료 | 주문·환불·권한·복구 경로의 실제 검증 | 판매 성공·매출 개선 |
| 집행 완료 | 실제 판매면·게시/광고·유입 경로·결과 확인 | 실제 고객 구매 |
| 첫 판매 성공 | 실제 유료 고객 결제와 주문 이행 | 반복 수익·AI 인과 기여 |
| 반복 판매 성공 | 성숙 환불/비용 반영 후 같은 조건의 지속 판매·수익 | 타채널/타국가 일반화 |
| 기여 검증 | 유효 비교로 추가 매출과 적용범위 설명 | 범위 밖 성과 보장 |
| 성장2 본선 완료 | 대표 일일 지시 없이 판매→학습→수정 반복, 사전 사업목표 달성·매출/이익·재구매/속도 개선·유효 기여 근거 | 시장 최강자 선언·외부 고객 계약 |

목표 미정 또는 관측기간 미충족이면 사업 성공은 미완료다. 8주 성과 관측의 반복성 취지를 유지하되 매주 새 유의성 검정을 요구하지 않는다. `merged`, `published`, `runtime-verified`, `registry-active`와 사업 성과는 독립 상태다.

## 9. 현재 구현과 다음 검증 경계

기존 [Meta 구현](GROWTH-2-META-ADS.ko.md)과 [Meta 종료 판정](GROWTH-2-CLOSEOUT.ko.md)은 재사용 기반이다. 성장2 전체 종료 증거로 확장하지 않는다. 코드 기준 기존 [온라인 주문 원장](../lib/storefront-orders.ts), [주문 서버](../lib/storefront-orders-server.ts), [상품 사실](../lib/brand-facts.ts), [kind 레지스트리](../lib/record-kinds.ts)를 연결한다.

첫 구현은 [판매 워크스페이스 증분](GROWTH-2-WORKSPACE.ko.md)의 시장 근거/니즈·카탈로그/오퍼·판매 미션·소유자 위임/계획 예약·캠페인 장부 집계다. 초안 준비도·버전 참조·로컬 예약을 외부 집행이나 실매출 검증으로 간주하지 않는다. 시장 자동수집, 실제 노출/주문 연결, 번들/소싱, DemandSequence, JourneyBlocker, 재고/이행·비용 정산·현금, SkillLesson, 사업목표/일일 결정은 카드별 잔여 범위로 추적한다.

변경 소유권은 [LANES](LANES.ko.md), 현황은 [STATUS](STATUS.md), 인계는 [HANDOFF](HANDOFF.ko.md)를 따른다. A는 제품·learning, Q는 eval·prompt-registry·독립 검증, R은 franchise를 소유한다. 소비자 매출과 가맹 리드/계약수를 합치지 않는다. 기술 게이트 결과와 실계정 증거를 PR별로 기록한다.

필수 검증은 주문 중복/역순/부분환불, 타브랜드 접근, 동시 예산예약/재고, 공급자 unknown, 만료/철회, 실험 설계변조/분모, 봉인누출/rollback, 기능 꺼짐 회귀다. 프로젝트 게이트는 `node scripts/test.mjs`, `node node_modules/typescript/bin/tsc --noEmit`, `node scripts/lint-gate.mjs`, `node scripts/check-prompts.mjs`, `node scripts/run-framework.mjs build`이며 변경 브라우저/worker 계약의 실검증은 별도다. 각 결과는 `passed / failed / blocked / not_run` 및 `real / mocked`를 명시한다.

이 문서는 전체 범위와 완료 기준의 복원이다. 위 검사를 실행했다거나 전체 카드가 배포되었다는 보고는 아니다.
