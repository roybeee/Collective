# Meta 읽기 수집 상태와 복구

M1 첫 증분은 실패 응답을 화면에만 표시하고, 같은 값 재수집 시 최초 수집 시각을 그대로 두었다. 실패를 새로고침 뒤에도 확인할 수 있도록 마지막 시도를 캠페인 범위에 저장한다.

- 외부 호출 직전 running, 성공 시 성과 스냅샷과 succeeded 상태를 같은 DB batch에 기록한다. 종료 전에 프로세스가 끊기면 running은 완료 미확인으로 표시한다.
- 권한 만료/부족·호출 제한·연결 실패·형식 오류는 안전한 코드만 저장한다. 공급자 원문 오류·토큰은 상태/응답에 넣지 않는다. 실패는 이전 정상 성과를 변경하지 않는다.
- 마지막 성공 시각은 같은 광고 계정·외부 캠페인·기간·전환 기준의 시도에만 이어받는다. 범위를 바꾸면 이전 성공을 새 범위의 성공으로 표시하지 않는다.
- 같은 수치를 다시 API 수집해도 새 수집 시각과 성과 판을 기록한다. 변화가 없다는 이유로 지연 전환 확인 시점을 영구히 과거에 고정하지 않는다. 수동 CSV의 동일 입력 중복 방지는 유지한다.
- 화면은 최근 수집 범위/성공·실패/다음 확인을 표시한다. 실패 직후 상태를 다시 조회하되 작성한 조회 입력은 보존한다. 자동 재시도·스케줄러 없음.
- 연결 해제는 토큰을 삭제하고 상태와 정상 성과는 남긴다. 캠페인 삭제 시 상태도 삭제한다. 실제 계정 연결/운영 실패 복구는 토큰·승인 계정 미제공으로 blocked다.

검사: 기존 Meta 모의 회귀 82 assertions, 오류별 지속 상태·정상 성과 보존·복구·같은 값 새 수집 판·비밀값 미포함. 타입/lint/빌드 및 전체 CI를 검증한다. 실제 외부 호출·광고 쓰기·고객 전송 0.
