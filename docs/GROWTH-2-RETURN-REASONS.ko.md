# 반품·환불 사건의 원인 근거

원안 G2-30/29/31의 부분 구현 계약. 현재 캠페인의 기존 반품(return)·금전 환불(refund) 사건에 운영자가 확인한 원인과 내부 증빙 참조를 연결한다. 고객 상담 원문·연락처·메시지를 수집하지 않는다.

## 연결과 저장

- 사건의 orderId는 실물 주문 품목 ID다. 소유자·캠페인·브랜드·지점·품목·재고·사건 종류를 서버에서 확인한다. 화면에서 받은 수량이나 원인을 기존 원장에 쓰지 않는다.
- 사건 한 개당 현재 원인 기록 한 개와 추가 전용 개정 이력을 갖는다. unknown은 정상적인 미확인 값이다. 나머지 원인도 운영자 확인 기록이며 자동 인과 판정이 아니다.
- 원본 사건 스냅샷·digest와 품목 판을 고정한다. 원본이나 계보 변경은 보류로 표시한다. 원인 코드와 제한된 내부 증빙 ID만 저장하며 고객 원문을 증빙으로 복사하지 않는다.
- 관리자 권한·CSRF·소유자 잠금·CAS·UUID 멱등·원자 현재/이력/요청 저장을 적용한다. 캠페인에 귀속하고 원장 근거와 함께 보존한다. 원인 추가만으로 캠페인 삭제를 새로 차단하지 않는다.
- 전역 실행 중단 및 캠페인 보관 상태에서도 이미 발생한 사건의 근거 보완은 관측 기록으로 취급한다. 신규 발행·환불·출고·재고 변경 권한을 부여하지 않는다.

## 화면과 의미

사건과 현재 원인을 선택하고 저장·재조회한다. 판 충돌 시 미저장 입력을 보존하고 최신 기준을 명시적으로 선택한다. 저장 응답을 받은 뒤 목록 조회에 실패한 경우 저장 실패로 재분류하지 않는다. 실제 원장 사건만 선택할 수 있다.

반품 수량과 환불 수량의 원장 의미를 구분한다. 환불 금액에서 물리적 반품 수량·원인을 추정하지 않는다. 원인별 비율·고객 문의 티켓·자동 개선 미션·실제 고객 응대·환불 실행은 이번 범위에 없다.

## 검증 상태

도메인12/API33·종류 보존 정책54 passed. real pure/memory SQL, 인증/runtime mocked, 외부0. 원본 실제 필드 digest·재고 단위 변경 보류, 정확 POST가 조회 한도에 막히지 않는 경로를 포함한다. 타입 passed, 독립 code/security 리뷰 HIGH/MED0. UI·빌드·전체 회귀·CI·게시 결과는 STATUS에 별도로 기록한다. 원안 전체 완료는 아니다.
