# 점포 브라우저 실행

공개 API로 확인되지 않은 네이버 스마트플레이스 관리 작업을 로그인된 로컬 장치에서 수행한다. 조사 워커와 인증·권한을 공유하지 않는다. 영업시간 조회·변경, 요일별 변경안, 권리를 확인한 사진 업로드, 공개 화면 대조, 장치 상태와 상주 워커를 제공한다. 실행 가능한 화면 구성과 실제 네이버 검증 범위는 아래처럼 구분한다.

## 운영 흐름

1. 소유자가 `store_browser_execution` 스위치를 켠다(기본 꺼짐).
2. 점포 마케팅 → 채널 점검에서 로컬 장치와 브라우저 프로필을 등록한다. 장치 토큰은 최초 한 번만 보여준다. 로그인 쿠키·비밀번호·인증 코드는 로컬 브라우저에만 둔다.
3. 해당 점포의 공개 플레이스 ID, 관리자 업체 ID, 실제 관리 화면 주소와 지정 장치를 연결한다. 두 ID는 별개 값이다.
4. 먼저 조회 작업으로 계정·대상·시간 표시를 확인한다. 변경은 현재값과 변경값을 작성하고 관리자가 그 전후값을 승인한다.
5. 장치가 작업을 claim하고 실제 페이지의 대상과 현재값을 확인한다. 서버가 제출 시작을 영속 기록한 뒤 저장 버튼을 한 번만 누른다.
6. 저장 후 관리 화면을 재로딩해 다시 읽은 값이 승인값과 같아야 관리 화면 확인 완료가 된다. 실환경과 모의 결과는 별도로 표시한다. 등록한 공개 주소를 별도로 읽어 반영 일치·차이·확인 불가를 기록한다. 관리 화면 확인과 공개 반영 확인은 서로 다른 결과다.

요일별 시간은 7일의 영업·휴무·미확인 상태와 여러 시간 구간을 저장한다. 자정 넘김을 명시하고 겹침을 거부한다. 미확인을 휴무로 바꾸지 않으며 등록하지 않은 위젯·시간 구간 변경은 사람에게 인계한다.

사진은 해당 브랜드·점포의 확인된 아카이브 원본만 사용한다. 원본 판, 권리 판, 사용 허락 근거·기한, 실제 이미지 MIME·크기·SHA256을 승인에 고정한다. 장치 다운로드와 저장 시작 때 다시 확인한다. 파일은 임대에 묶인 별도 인증 경로로 내려받으며 브라우저에 필요한 바이트만 짧게 제공한다. 권리는 기능 OFF·점포 보관·원본 삭제 상태에서도 관리자가 회수할 수 있다. 회수 후 재등록해도 기존 승인은 사용할 수 없다. 이미 외부에 게시된 사진의 삭제는 별도 작업이다.

## 중단과 복구

- 로그인 만료, CAPTCHA, 추가 인증, 명시적 보안 차단은 사람에게 인계한다.
- 점포 불일치·현재값 변경·연결 판 변경은 제출을 차단한다.
- 저장 직후 시간 초과·연결 단절은 결과 미확인이다. 다시 저장하지 않고 조회만 하며 대사한다.
- 스위치를 꺼도 기존 결과 조회·장치 회수·미확인 대사는 유지한다.
- 장치 토큰은 해당 소유자 범위에만 접근한다. 작업 보고에는 대상 ID·주소·필요한 시간값만 보내며 페이지 원문 전체를 보내지 않는다.

## 검증의 한계

로컬 fixture 테스트는 실제 네이버 성공 증거가 아니다. 네이버 관리자 화면의 요소와 계정 권한을 실관찰로 설정한 후 실제 조회, 승인한 변경, 재조회까지 별도로 검증해야 운영 가능으로 판정한다. 승인 화면이나 작업 큐만으로 외부 작업 완료를 주장하지 않는다.

`registered_dom` 어댑터는 현장에서 관찰해 등록한 단일 입력칸 또는 요일별 고정 위젯과 사진 파일 입력을 지원한다. 네이버의 실제 화면 구조를 임의로 같은 구조라고 가정하지 않는다.

`naver_smartplace` 어댑터는 실제 관찰한 네이버 관리 주소와 캘린더를 읽는 **조회 전용** 연결이다. 변경 요청은 저장 허가를 받기 전에 인계한다. 네이버의 요일별 편집·법정공휴일·임시휴무·사진 등록 위젯에 대한 실제 쓰기는 아직 지원하지 않는다. 상주 워커 템플릿이 있다는 사실만으로 운영 장치가 설치됐다고 판단하지 않는다.

2026-10-13 ASIDE 로컬 `u0`에서 사용자 로그인 뒤 맵달SEOUL 성수의 실제 조회를 검증했다. 관리 사업장 `11695831`과 공개 플레이스 `2071910776`은 서로 다른 ID이며 두 화면 모두 확인했다. 관리 캘린더의 표시된 7일은 11:00–20:50이다. 이 표시는 법정공휴일·임시 설정까지 일반 주간 일정과 같다는 증거가 아니다. 실제 저장·사진 업로드는 실행하지 않았다.

공개 네이버 조회 어댑터도 실측했다. 등록한 지도 주소에서 같은 플레이스 ID의 지도 리디렉션과 실제 iframe 주소를 검증한 뒤, 실제 점포 이름과 펼친 시간표의 전체 DOM을 읽는다. 접근성 이름이 5일에서 잘리는 화면에서도 7일을 확보하며, 불완전한 시각·추가 휴게 구간을 버리고 일치로 판단하지 않는다. 요청한 공개 주소와 실제 이동 주소의 읽기 범위를 함께 남긴다. 공개 반영 확인은 심사 승인이나 사진 업로드 성공과 같은 뜻이 아니다.

## 로컬 워커 실행

ASIDE CLI가 설치되고 네이버 관리자 계정에 로그인된 업무용 컴퓨터에서 실행한다. 아래 환경변수는 해당 장치의 비공개 설정에서 공급한다. 토큰을 명령 문자열·공유 문서에 직접 넣지 않는다.

```sh
node scripts/store-browser-worker.mjs --config /private/path/store-browser.json --once
```

- `STORE_BROWSER_API_ORIGIN`: COLLECTIVE HTTPS 출처(경로 없음).
- `STORE_BROWSER_WORKER_TOKEN`: UI에서 처음 발급한 해당 장치 토큰.
- 설정 파일: `host:'local'`이면 `account`를 지정하고, 원격 host면 `profile`을 지정한다. 서버에 등록한 `profileId`와 정확히 같아야 한다.
- `hoursReadMode`: `input` 또는 `text`. 변경은 `input`만 지원한다.
- `locators`: `managerBusinessId`, `naverPlaceId`, `storeName`, `hours`, `save` 각각 `{role,name}` 또는 `{css}`. 실제 화면 snapshot에서 관찰한 요소만 로컬 설정에 등록한다. 서버 작업에서 코드·selector를 받지 않는다.
- claim 임대는 5분이다. 장시간 중단·결과 미확인은 임대 종료 뒤 읽기 대사로만 다시 접수한다. 승인 유효기간은 24시간이다.
- 로그인/차단 인계는 자동 재개되지 않는다. 원인을 해결하고 현재값을 조회한 후 새 변경안·승인을 만든다.

요일별·사진 연결은 `version:2`를 사용한다. `weekly`는 각 요일의 상태 선택 요소·명시적 상태값·시작/종료/자정 넘김 요소를 등록한다. `photo`는 실제 파일 입력·제출·업로드 결과 ID/해시 요소를 등록한다. 저장된 사진의 ID/해시 근거가 없으면 업로드 완료로 표시하지 않는다. `public`은 등록한 공개 주소의 읽기 요소를 지정한다.

실제 네이버 조회 전용 설정은 `adapter:'naver_smartplace'`, `host:'local'`, `account:'u0'`, `native:{dashboardUrl,hoursUrl}`이다. 주소는 실제 화면에서 관찰한 같은 관리 사업장이어야 한다. 점포 연결의 `managerUrl`은 관찰한 영업시간 화면 주소와 정확히 같아야 한다. 설정 파일·토큰·로그인 상태를 저장소에 넣지 않는다.

상주 실행은 `--watch --env-file /private/path/browser-env.json`을 쓴다. 환경 파일은 소유자 전용 0600 JSON이며 API 출처와 장치 토큰만 둔다. singleton 잠금은 같은 설정의 이중 실행을 막는다. `NO_JOB`만 정상 대기로 처리하고 인증 실패·다른 API 오류는 구분해 중단 또는 제한적으로 재시도한다. 종료 신호를 받으면 새 제출을 중단한다. `scripts/store-browser-worker.launchd.plist`는 절대 경로를 치환하는 미설치 예제다. 운영 UI 장치 발급과 실제 연결이 확인되기 전 설치하지 않는다.

운영 워커는 `--allow-local-fixture`를 사용하지 않는다. 다음 명령은 로컬 합성 점포와 실제 ASIDE 브라우저만 사용하며 네이버나 운영 API를 변경하지 않는다.

```sh
node tests/fixtures/store-browser-aside-smoke.mjs
node tests/fixtures/store-browser-aside-next-smoke.mjs
```

## 검증 기록

- 신규 서버·API·복구·실행 회귀는 별도 테스트 파일에 둔다. 실 SQL/HTTP 경계와 모의 인증·외부 공급자를 구분해 보고한다.
- ASIDE 시험 페이지의 저장 1회 및 새 페이지 재조회는 실제 로컬 브라우저 실행으로 검증한다. 서버 phase와 점포 데이터는 fixture다.
- 코드·보안 독립 검토의 발견 사항(기능 OFF 회수/취소, 큐 정체, 저장 후 재로딩, 모의 결과 표시)을 수정했다.
- 기존 의존성 감사는 workspace 설정 때문에 표준 명령이 blocked이며 별도 공식 bulk 검사에서 기존 advisory가 보고됐다. 이번 변경에는 의존성 추가·업데이트가 없고 기존 advisory 해소를 주장하지 않는다.
- V8 실행 range 측정은 서버 82.3%, 실행기 61.8%, 어댑터 64.7%(초기 전용 검사)이며 라인·분기 커버리지 80% 달성으로 표현하지 않는다.
- 2026-10-13 최종 후속 전체 회귀 378/378 suites·19,886 assertions passed(외부 mocked). UI E2E8 passed(real local Chromium/D1/R2, auth fixture), 사진 권리13·인계/보관 취소5·native23 passed(mocked). 실제 native 관리/공개 조회는 각각 source real이며 저장·업로드0회다. 코드·보안 최종 독립 검토 신규 CRITICAL/HIGH/MEDIUM 잔여0이다.
