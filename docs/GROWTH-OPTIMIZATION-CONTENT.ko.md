# 성장2 상세 문구·오퍼 원문 코드 검사

`landing_copy`와 `offer_message`는 대상 ID가 가리키는 현재 원장 전체와 근거를 동결해 무료 결정론적 검사를 실행합니다. AI 생성 품질 점수, 새로운 AI 심사 게이트, 매출 개선 판정이 아닙니다. Q 케이스나 프롬프트 pair로 다른 내용을 평가한 결과를 대신 가져오지 않습니다. 외부 모델·판매처 호출 및 사용료는 0입니다.

## 동결과 재검사

- 원문 전체, 대상 판, 캠페인 범위, 연결 오퍼·상품·수요·시장 신호·사실 원장·병목의 내용과 판을 SHA-256으로 고정합니다. 실제 후보 제안은 대상 원장에 저장되어 있어야 합니다. 제안 요약을 실제 변경 내용으로 오인하지 않습니다.
- 기존 상품/오퍼 준비도, 승인 가격, 현재 공유 재고, 배송·반품·신뢰의 사실 참조, 구매 병목 판, 기존 표현 검사기의 block만 그대로 적용합니다. warn/info를 새 차단 조건으로 올리지 않습니다.
- 회수할 때 동결 저장값 자체와 현재 원문·근거를 다시 비교합니다. 같은 판 번호에서 내용만 달라져도 거부합니다. 새 근거를 몰래 끼워 기존 결과를 유지하지 않습니다.
- 동결 당시 재고 관측과 digest는 감사 근거로 별도 보존합니다. 정상 입출고로 수량·재고 사건 판이 바뀌는 것은 문구 수정이 아니므로 원문을 자동 무효화하지 않습니다. 지점/SKU/재고 장부 식별/단위는 고정하고, 현재 가용 수량에 기존 준비도 검사를 다시 적용합니다.
- 검사 결과는 `kind=deterministic_content`, 0 tokens, 서버 verdict와 이유로 기록합니다. 요청의 임의 verdict는 사용하지 않습니다.

## 판매 연결의 조건

확증 실험의 등록 digest와 정확한 intervention refs가 일치해야 하며, 실험에서 실제 실행하는 offer ID/판도 평가한 대상의 offer와 같아야 합니다. 참조 목록에 무관한 평가 대상만 덧붙이는 것은 거부합니다.

상세 문구는 추가로 provider_verified 적용 기록, apply 영수증, 실제 readback 검증 상태, 현재 승인 digest, before/after 설명 digest와 상품 판을 검사합니다. 수동 적용 확인만으로 실제 판매처 내용 일치를 주장하지 않습니다. 현재 판매처 어댑터가 지원하는 단일 전체 설명 변경만 연결할 수 있습니다.

원장 판은 엄격하게 비교합니다. 승인·적용 등 단계 이동으로 대상 판이 올라갔어도 동결한 예전 판을 새 판으로 자동 바꾸지 않습니다. 최종 적용된 정확한 판으로 새 후보를 동결·검사한 뒤, 그 이후에 등록하는 제한 판매 실험에 연결합니다. 실제 적용 전후의 판을 하나의 불변 content revision으로 묶는 추가 프로토콜은 현재 지원하지 않습니다.

오퍼는 현재 원문·정확 offer ref와 등록 실험의 실행 offer 일치를 증명합니다. 특정 광고/게시 문안이 이 오퍼 메시지를 실제로 노출했다는 일반 증명은 아닙니다. 별도 메시지 게시를 평가하려면 해당 정확 게시 산출물/공급자 영수증 연결이 추가로 필요합니다.

## 검증

`node --experimental-vm-modules tests/growth-optimization-content.test.mjs`는 실제 임시 SQLite와 기존 준비도·표현 검사 함수를 사용합니다. 원문/근거 변조, 타 소유자, 다른 실행 오퍼, 등록 digest 위조, 정상 재고 변경, provider 영수증 불일치와 근거 만료를 검사하며 네트워크 호출은 금지합니다.
