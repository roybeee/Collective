# 성장2 판매 워크스페이스 — 공통 기반 첫 증분

원안 [전체 33개 개발 카드](GROWTH-2-PLAN.ko.md)를 기준으로 Meta 밖의 판매 흐름을 시작한다. 캠페인의 **성장·판매** 탭에 시장 근거 → 고객·기회 → 상품 → 판매 오퍼 → 판매 미션을 연결한다.

## 구현과 원안 매핑

| 원안 | 이번 구현 | 남은 전체 수용조건 |
|---|---|---|
| G2-01 | 소유자/브랜드/캠페인 격리, 판 충돌, 기록 이력, 삭제 정책 | 기존 origin 전체 매핑·추가 공통 객체 |
| G2-03·26 | 가격·원가·변동비·재고·판매 권리·배송·반품·확정 사실, 오퍼 가격/수량/구매 이유 | 실제 상품 동기화, 번들·MOQ·소싱·결제 경로 검증 |
| G2-06·07·25 | 출처/관측 시각/유효기한, 고객 상황·대안·장벽·반례·담당/기한/행동 | 자동 수집·중복 신호 묶음·기회 순위·시즌 캘린더 |
| G2-28 | 오퍼 버전에 연결한 미션, 준비 요청/취소/결과불명/실패/관측 기록 | 실제 실행 어댑터·재조회 작업자·외부 증빙 대사 |
| G2-05·17a | 소유자 위임, 계정/기간/행동/등급, 총/일/주/손실 캡, 관리자 미션 예산 예약 | 외부 실행 전 가드 연결, 실제 비용 정산·안전한 해제·재고 예약 |
| G2-02·32 | 기존 지점 주문 장부의 캠페인별 순매출·확인된 원가 공헌이익 읽기 | 상품주문/정산/현금·광고비 배분·목표 계약·일일 결정·30일 리뷰 |

이 표는 카드 전체 완료 판정이 아니다. 첫 제한판매 G2-12a와 반복 자율 G0-C는 아직 이 화면에서 수행하지 않는다. 기존 Meta 작업은 별도 연결 버튼으로 이동하며 기존 승인을 우회하지 않는다.

## 데이터·준비 상태

- `GET/POST /api/growth`: signal, need, catalog, offer, mission. 관리자 쓰기·CSRF·소유자 잠금, `campaignVersion`과 `expectedVersion` 검사. 같은 요청 재전송은 기존 기록을 반환한다.
- 상품의 확정 사실 버전, 니즈의 시장 근거 버전, 오퍼의 니즈/상품 버전, 미션의 오퍼 버전을 연결한다. 출처 만료·사실/상품/기회 변경은 하위 미션의 준비 상태에 전파된다.
- 입력 금액의 빈칸은 `null`이다. 통화 KRW, 원 단위 정수이며 세금 포함/제외 기준 미확인을 이익 계산에 숨기지 않는다. 입력 단위 공헌이익은 실제 실현 이익이 아니다.
- 시장 근거와 고객 니즈는 관측·가설이다. 고객 표본 미확인 또는 20개 미만은 준비를 보류하며, 표본 20개 이상도 실제 수요나 인과 효과를 입증하지 않는다.
- 원시 고객 식별정보를 수집하지 않는다. 상품/오퍼/근거/미션 자유 입력은 개인정보 검사를 통과해야 하며 출처·구매 URL은 쿼리/해시 없는 공개 HTTPS 경로로 제한한다.
- 미션의 운영자 관측 기록은 외부 공급자 영수증 검증이나 실제 매출 증명이 아니다. `unknown` 미션은 다시 준비 요청하지 않는다.
- 로컬 계획/미션/버전 이력은 캠페인과 함께 삭제한다. 외부 실행 기록은 기존 전용 대장에 별도로 남는다.

## 위임·예약

- `GET/POST /api/growth/authority`: `save_authority`, `revoke_authority`, `reserve_mission`.
- 승인·철회는 소유자만 가능하다. 활성 위임은 UI의 명시적 범위 확인을 요구하며 서명 참조·시각·브랜드/캠페인은 서버가 결정한다. 일반 관리자는 승인된 범위에서 준비된 미션의 예산만 예약한다.
- 예약의 계정은 저장된 위임, 채널/금액/손실은 저장된 미션에서 가져온다. 클라이언트가 보낸 금액·증분 근거·등급으로 바꾸지 않는다. 예약 키는 미션 ID와 판으로 결정한다.
- 소유자의 전체 예약 원장을 읽고 같은 계정의 비용을 합산한다. 위임을 새로 만들거나 기간이 지나도 미대사 예약이 사라지지 않는다. 검증·합산·삽입은 하나의 소유자 잠금 안에서 처리한다.
- 계획 예약은 실제 결제나 외부 실행 권한이 아니다. 이 증분에는 외부 실행 호출·정산/해제 API가 없다. 철회는 새 예약을 막고 기존 원장은 유지한다.
- 예약이 존재하는 캠페인은 삭제 대신 보관한다. 예약 원장을 지워 누적 한도를 초기화하지 못한다. 위임의 계정/채널 변경도 예약 이후에는 허용하지 않는다.
- 순수 정책 코어는 검증 근거 없는 확대와 1회 20% 초과 확대를 거부한다. 이 값은 실제 확대 기능 완료를 뜻하지 않으며 API는 탐색 예약만 만든다.

## 사업 지표

캠페인과 동일한 소유자·브랜드·지점의 연결 주문만 읽는다. 지점 미연결은 `not_measured`, 잘못된 범위/기간/원장은 `unavailable`, 읽은 장부는 `ledger_only`다. 최대 10,000건을 넘으면 부분 합계를 전체처럼 표시하지 않는다.

순매출은 결제액에서 누적 환불을 뺀다. 원가가 한 항목이라도 미확인이면 공헌이익도 미확인이다. 광고·제작비 배분, 실수령 현금, 장부 대사, 증분 효과는 연결 전까지 미확인이다. 주문 기록 0건과 실제 판매 0건을 구분한다.

## 검증과 후속

전용 단위/API 검사와 모바일·데스크톱 브라우저 검사를 둔다. 로컬 SQLite/D1 저장·조회·권한·충돌·삭제 경계는 실제 실행하며 외부 계정/매출은 호출하지 않는다. 최종 명령별 결과는 [상태](STATUS.md)에 기록한다.

다음 본선 작업은 상품 재고 예약·이행/비용 대사(G2-30), 수요 시퀀스와 실제 실행 연결(G2-27/28/12a), 일일 결정·운영 교훈(G2-11/31/32)이다. 소비자 동의/후속 구매와 범용 실험·검증 확대도 원안에서 제거하지 않는다. 선택 채널·해외·MMM·외부 상품화는 원안의 조건을 유지한다.
